# 商办租赁平台 MVP 全量验收测试用例

> 文档类型：系统验收测试（SAT）+ 用户验收测试（UAT）
> 覆盖范围：前台网站、Payload 后台、公开 API、领域服务与跨模块数据链路
> 假设状态：前后台功能已全部开发完成，并已完成部署、迁移和测试数据初始化
> 版本：V1.0
> 日期：2026-07-26

## 1. 验收目标

本测试集用于判断商办租赁平台 MVP 是否达到可上线标准，重点验证：

1. 前台用户能够搜索、比较、查看当前有效房源并成功提交咨询。
2. 后台五类角色只能访问和操作获授权的数据、菜单、动作与字段。
3. 楼盘、房源、审核、举报、商户、经纪人、线索和跟进状态机符合 PRD。
4. 前台、后台聚合、咨询候选和看板复用同一有效供给口径。
5. 幂等、并发、审计、隐私、缓存、SEO、性能和可访问性达到上线门槛。

## 3. 验收结论规则

### 3.1 优先级

| 优先级 | 定义 | 验收要求 |
|---|---|---|
| P0 | 核心闭环、权限、安全、数据一致性或不可逆数据风险 | 必须 100% 通过 |
| P1 | 主要页面、异常恢复、SEO、可访问性和重要运营能力 | 通过率必须 ≥ 98%，且无阻断缺陷 |
| P2 | 次要体验、兼容性和低频边界 | 通过率必须 ≥ 95%，遗留项须有负责人和期限 |

### 3.2 缺陷等级

| 等级 | 示例 | 上线规则 |
|---|---|---|
| S0 阻断 | 无法登录、前台不可访问、数据损坏、迁移失败 | 不得上线 |
| S1 严重 | 越权、敏感数据泄露、无效房源曝光、重复 Lead、状态机绕过 | 不得上线 |
| S2 一般 | 主要流程局部错误、错误提示不正确、SEO 关键字段缺失 | 修复或获得正式风险接受 |
| S3 轻微 | 非关键视觉偏差、低频文案或兼容问题 | 可带计划上线 |

### 3.3 最终签署条件

- P0 全部通过，S0/S1 为 0。
- P1 通过率 ≥ 98%，未关闭 S2 有书面风险接受。
- 前台六页、后台二十二页均至少完成正常、权限、异常三类验证。
- 统一有效供给差异数为 0。
- 类型检查、测试、生产构建、迁移校验和浏览器 E2E 全部有证据。
- 产品、研发、测试、运营和安全/数据责任人完成签署。

## 4. 测试环境

### 4.1 环境要求

- 使用生产等价 PostgreSQL，不以 SQLite 结果代替数据库约束验收。
- 应用以生产构建模式运行，环境变量、域名、时区和缓存策略与生产一致。
- 数据库时区存储为 UTC，产品展示时区为 `Asia/Shanghai`。
- 邮件/站内通知可使用测试通道，但必须保留真实事件和幂等行为。
- 对象存储或本地媒体服务具备成功、404、不可读三种测试能力。
- 分析、日志、错误监控和审计查询入口可供验收人员查看。

- 相同手机号：格式分别为 `13800000000`、`138 0000 0000`、`+86 13800000000`。
- Lead 覆盖新建、待分配、跟进中、有效商机、带看、谈判、已转化、已流失。
- 归属覆盖未分配、已分配、公海，另准备已合并来源 Lead。
- 在 `Asia/Shanghai` 的 00:00、23:59、月末、SLA 到期前 1 秒、到期时、到期后 1 秒准备固定时钟数据。

## 13. 推荐自动化分层

| 层级 | 自动化范围 | 建议触发 |

| 单元 | 状态机、权限纯函数、价格、时间、筛选、mapper、幂等键 | 每次提交 |

| API 集成 | 权限、查询范围、审核/发布、询盘、限流、审计 | PR |

| 灾备演练 | 备份恢复、迁移回滚、Outbox 重投 | 上线前 + 定期 |

不得用单元测试替代浏览器验收，也不得用浏览器 UI 隐藏验证替代直接 API 权限测试。

6. 修复后重跑失败用例及其相邻回归集。
7. 生成最终覆盖率、缺陷、风险和签署报告。
