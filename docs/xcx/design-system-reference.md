# 设计系统 · 中性极简（对齐 Apple）

> 改任何 C 端视觉（颜色、字体、间距、圆角、阴影、动效、图片）前必读。
> 与 `.agent/frontend.md` 的关系：frontend.md 管数据流、状态、SEO、可访问性；本文件管视觉。
> **本文件是视觉的唯一事实源，`(frontend)/styles.css` 的 token 必须与此一致。**

## 0. 状态与来源

- **决策日期**：2026-08-17。**取代** 2026-08-03 定下的「奶油 + 铜 + 宋体不可偏离」硬约束。旧品牌（`#fcfbf8` / `#a46f3f` / 宋体标题）**已作废**，不再是保护对象。
- **数值来源**：`gstack browse` 实测 `apple.com.cn` 首页与 `/macbook-air/`，视口 1440×900，2026-08-17。
- **交叉校验**：与一份 2025-04 反推自 apple.com 英文站的规范逐条对过。色值、字号阶、行高、pill 半径、零边框卡片、玻璃导航六项完全吻合；四项该文档已过时（见 §12）。**冲突一律以本文件的实测值为准。**
- **北极星**：「这家的数据是真的、干净的」。每一条规则都服务于这句话。这不是装饰性说明——遇到取舍时用它裁决。

## 1. 视觉主题

排版与留白干全部的活，零装饰。房源图来自商户上传、质量不可控，所以**不赌图片，赌排版秩序**。

- 底色只有两级，分区靠色块而非分隔线。
- 全站只有一个彩色（蓝），且只出现在可交互元素上。
- 数字是视觉主角：等宽字形、成列对齐，让「账是清的」可以被眼睛直接验证。
- 大留白。section 之间的空白不是没内容，是节奏。

## 2. 色彩

### Token

```css
--bg:          #ffffff;   /* 主底色 */
--bg-subtle:   #f5f5f7;   /* 次底色，唯一的分区手段 */
--ink:         #1d1d1f;   /* 主文字 */
--ink-2:       #6e6e73;   /* 次文字 */
--ink-3:       #86868b;   /* 三级文字、占位符、禁用态 */
--accent:      #0071e3;   /* 填充 CTA 底色、focus ring */
--accent-hov:  #0077ed;
--accent-link: #0066cc;   /* 正文内链接（比 accent 深，保证小字号可读） */
--line:        rgba(0,0,0,.08);
--line-2:      rgba(0,0,0,.16);
--error:       #bf4800;   /* 仅真实错误 */
--warning:     #b25000;   /* 仅真实警告 */
--on-accent:   #ffffff;
--header-bg:   rgba(255,255,255,.8);
```

### 规则

- **没有第三种底色。** 需要再分一层时用间距或 `--line`，不要发明新灰。
- **蓝色只给可交互元素。** 不做标题色、不做图标装饰色、不做数据强调色。整个色彩预算就这一个彩色。
- **禁止装饰性语义色。** 早期的 `--color-forest` / `--color-warn` / `--color-danger` 及其 `-soft` 变体全部退场。`--error` / `--warning` 只在真实错误和真实警告出现，不做标签、不做徽章、不做状态点。
  - 房源状态（在租 / 已租 / 新上）用**底色深浅 + 字重**区分，不用色相。见 §5 标签。
- **暗色模式暂不上线**，但 token 结构已按可切换设计。启用时只重定义变量，不改组件。

暗色变量（预留，未启用）：

```css
--bg:#000000; --bg-subtle:#1d1d1f; --ink:#f5f5f7; --ink-2:#a1a1a6; --ink-3:#86868b;
--accent:#0a84ff; --accent-hov:#409cff; --accent-link:#2997ff;
--line:rgba(255,255,255,.12); --line-2:rgba(255,255,255,.22);
--error:#ff6b3d; --warning:#ff9f0a; --header-bg:rgba(0,0,0,.8);
```

## 3. 字体

### 字体栈

```css
--font-cn:  "PingFang SC", "Source Han Sans SC", "Noto Sans CJK SC",
            "Microsoft YaHei", -apple-system, sans-serif;
--font-num: "Geist", "SF Pro Text", -apple-system, "Helvetica Neue", sans-serif;
--font:     var(--font-num), var(--font-cn);
```

- **必须自托管，走 `next/font/local`。** `fonts.googleapis.com` 在中国大陆不可达，禁止用 Google Fonts CDN 加载 Geist。思源黑体 SC 同理，需要子集化后自托管。
- **不要用 Inter。** 它是 AI 设计的收敛陷阱。Geist 的 `tabular-nums` 更成熟，且这是数据优先系统的核心诉求。
- **`SF Pro SC` / `SF Pro Display` / `SF Pro Text` 的 Web 授权仅限 Apple 自有站点，不得引用。** apple.com.cn 首选 SF Pro SC，我们只能从 PingFang SC 起步。
- 历史遗留：`--font-display` / `--font-sans` / `--font-numeric` 曾引用三个从未被 `next/font` 注入的幽灵变量（`--font-source-han-serif` 等），靠同族兜底掩盖。改造时**接上 `next/font/local` 并删掉幽灵变量**，不要保留半接线状态。

### 字号阶（实测 apple.com.cn 完整梯级）

```
12 · 14 · 17 · 19 · 21 · 24 · 28 · 32 · 40 · 48 · 56 · 80
```

正文基准是 **17px，不是 16px**。

| 角色 | 字号 | 字重 | 行高 | 字距 |
|---|---|---|---|---|
| Hero 标题 | 56px | 600 | 1.07 (60px) | `normal` |
| 章节标题 | 40px | 600 | 1.10 (44px) | `normal` |
| 卡片/区块标题 | 24–28px | 600 | 1.2 | `normal` |
| 引导副标 | 21px | 400 | 1.38 (29px) | **`+0.011em`** |
| 正文 | 17px | 400 | 1.47 (25px) | `normal` |
| 卡片标题 | 19px | 600 | 1.3 | `normal` |
| 辅助/说明 | 14px | 400 | 1.43 | `normal` |
| 微型/法务 | 12px | 400 | 1.33 | `normal` |
| 大数字 | 48px | 600 | 1.08 (52px) | `normal` |

### CJK 铁律

1. **中文一律 `letter-spacing: normal`。** 实测 apple.com.cn 的 56px 中文大标题和 17px 正文字距都是 `normal`。
2. **不要套西文的负字距。** 网上流传的「Apple 全字号负字距」（`-0.374px @ 17px`、`-0.28px @ 56px`）是 **SF Pro Text 的西文 tracking 表**，套到汉字上会明显发挤。
3. **唯一的正字距例外是 21px 引导副标：`+0.231px`（≈ +0.011em）。** 这是实测值，也与外部规范的 21px 行吻合。
4. 若某处混排大量西文/型号，可对该元素单独 `:lang(en)` 收紧，但**不要设在全局或中文容器上**。

## 4. 数据与数字（北极星的落点）

- **所有数字使用等宽字形**：`font-variant-numeric: tabular-nums; font-feature-settings: "tnum" 1;`
  - 适用：租金、面积、楼层、层高、得房率、车位配比、统计数、日期。
- **规格表右列右对齐**，让小数点成列。位数不同（`1,860` 与 `474,300`）不得错行。
- **正文栏宽上限 702px**（`--measure`）。长段落不得铺满 1024px 容器。
- 价格必须携带币种、租售类型、周期和单位（此条与 `.agent/frontend.md` 一致，不得跨单位聚合或排序）。
- 数值缺失显示 `—`，**不显示 0**，也不隐藏整行。失败不得伪装成 0 数据。

## 5. 组件

### 按钮

| 类型 | 底 | 字 | 圆角 | 内边距 | 字号 |
|---|---|---|---|---|---|
| 主 CTA | `--accent` | `--on-accent` | `--r-pill` | `11px 21px` | 17px |
| 主 CTA（小） | `--accent` | `--on-accent` | `--r-pill` | `8px 15px` | 14px |
| 次级 | 透明 | `--accent-link` | `--r-pill` | 同上 | 同上 |
| 次级边框 | — | — | — | `1px solid --line-2` | — |

- **填充 CTA 也用 pill**（`980px`）。外部规范说填充按钮 8px、pill 只给文字链——那是 2025 年的旧状态，实测已统一为 pill。
- focus：`outline: 2px solid var(--accent)`，不得移除。
- 触控目标 ≥ 44×44px。

### 输入

底 `--bg`，边框 `1px solid --line-2`，圆角 `--r-input` (8px)，内边距 `11px 14px`，字号 17px。
focus：边框转 `--accent` + `box-shadow: 0 0 0 4px rgba(0,113,227,.18)`。

### 标签 / 徽章（零彩色）

底 `--bg-subtle`，字 `--ink-2`，圆角 `--r-pill`，`4px 10px`，12px/500。
需要强调时用反色：底 `--ink`、字 `--bg`。**不引入任何色相**。

### 卡片

- 底 `--bg-subtle`，**零边框**，圆角 **18px**（`--r-card`）。
- 默认无阴影。分层靠底色差异，不靠阴影。
- 卡片本身不做 hover 态，交互交给卡内链接。

> 圆角说明：实测 apple.com.cn 主导圆角是 **28px（68 处）**。本项目按 2026-08-17 决议收到 **18px**——仍远大于国内同行的 4–8px，但避免商办产品发"软"。**不要照抄外部规范"矩形不得超过 12px"那条，它已过时。**

### 导航

- 高 **44px**，`sticky`，底 `--header-bg`，`backdrop-filter: saturate(1.8) blur(20px)`。
- **只写标准属性 `backdrop-filter`，绝不手写 `-webkit-backdrop-filter` 双行。** LightningCSS 会把两行去重到只剩前缀行，Chromium 不支持该前缀 → 效果静默失效。（真实教训，`site-header` 曾有同样隐患。）
- **浅色玻璃，不是深色。** 外部规范说 `rgba(0,0,0,.8)` 深玻璃且标注 "non-negotiable"——那是旧版本，实测已换成浅色。

## 6. 布局与间距

### 间距 token

```
--sp-1:4   --sp-2:8   --sp-3:12  --sp-4:16  --sp-5:24
--sp-6:32  --sp-7:48  --sp-8:72  --sp-9:96

--section-pad-y: 72px    /* section 上下 padding，相邻两段之间实得 144px */
```

**section 节奏改用 padding 模型，不用 margin。** 原实现是 `margin-top: 48px` +
`padding: 0`，导致加了底色的 section 文字贴边（底色交替做不了），且相邻 margin 会合并。

**72px 是定案值（2026-08-17），不要照搬 Apple 的实测值。**
apple.com.cn 实测是 section 内 110–120px、section 之间 234–236px，180px 也上机试过，
**都偏空旷**。原因是 Apple 那是「一屏一个产品」的营销长页，每段内部有满屏大图撑着；
本站首页是内容型，「按类型浏览」只有一行瓷砖、「资讯」只有三条标题，
段内内容量撑不起那么大的段间距，观感是断裂而不是节奏。

这是本设计系统里**实测值不适用**的一处，改动前先看这条。

**`--sp-10` / `--sp-11` 是本次改造最关键的新增。** 实测 Apple 的 section 内 padding 是 110–120px、section 之间是 234–236px；本项目改造前的上限只有 96px。这不是微调，是量级差异——留白观感几乎全部来自这里。外部规范只有 2–24px 的微观刻度，完全没有宏观节奏，**不要以它为准**。

### 容器

```
--container: 1024px   /* 内容容器（实测主导值） */
--measure:   702px    /* 正文栏宽上限 */
```

桌面重点验证 375 / 768 / 1024 / 1440 / 1920。

### 圆角

```
--r-card:  18px   /* 卡片、图片容器 */
--r-ctrl:  12px   /* 次级容器、色板块 */
--r-input:  8px   /* 输入框 */
--r-pill: 980px   /* 按钮、标签 */
```

## 7. 深度

阴影极少用。默认 0 阴影，分层靠底色。

| 层级 | 处理 |
|---|---|
| 平面 | 无阴影，纯底色 —— 绝大多数元素 |
| 玻璃导航 | `backdrop-filter: saturate(1.8) blur(20px)` |
| 浮层（Modal / Drawer / Toast） | `0 4px 16px rgba(0,0,0,.12)` |
| focus | `2px solid var(--accent)` |

禁止多层阴影、禁止大面积阴影。

## 7b. 首屏 Hero：保留背景媒体（2026-08-17 定案）

**Hero 保留视频 / 大图背景。** Apple 的产品页正是这么做的，天际线与 CBD 能建立
高端感，这是纯白首屏给不了的。此前「改成纯白 + 大字 + 数据带」的提案作废。

但成立有前提——**素材必须是单一主体**：

- ✅ 天际线、CBD 全景、单栋写字楼外立面、幕墙细部
- ❌ 室内办公场景（玻璃反光 + 人物 + 家具 + 远景天际线，四层信息打架，
  标题只能靠重遮罩硬压，结果是图被闷死、字还是不跳）

**遮罩只压文字带，不整片压暗。** 顶部近乎不压以保住天空与楼体高光，
暗度集中在垂直居中的文字带，底部回收。用纯黑，不要带暖调的 ink 色
（压在冷色天际线上会脏）。

**Hero 标题字重 600，不用 700/800。** 实测 apple.com.cn 全站最重就是 600；
800 在汉字上笔画会糊成一团。行高 1.07，字距 normal。

**视频技术约束**（`HomeHeroMedia.tsx` 已实现，勿退化）：
poster 先 eager 加载；视频走 `requestIdleCallback` 懒加载；
`prefers-reduced-motion` / 移动端 / `saveData` 一律跳过视频只留 poster；
`autoPlay muted loop playsInline preload="none"`。

## 8. 图片治理（不做这条，token 改得再准也白改）

房源图来自商户上传，尺寸/色温/水印全不统一。这是 Apple 式设计在本项目**最大的失败风险**。

- **固定裁切比例**：房源卡 4:3，详情主图 16:10。声明尺寸，禁止 CLS。
- **统一后处理**：轻微降饱和向中性靠拢，避免色温打架。
- **底部渐变压暗**：图上有文字时必须加 `linear-gradient(to top, rgba(0,0,0,.42), transparent)` 覆盖底部约 45%，保证白字对比度 ≥ 4.5:1。
- **模糊占位**：用已装的 `@oversightstudio/blur-data-urls` 生成 blurDataURL。
- **必须有 alt 与失败占位**，失败态不得留空洞。
- **图片弱的位置改用排版型区块**（大字 + 数据）替代大图，不要硬撑满屏图。

## 9. 动效

- 时长 160–240ms（`--dur: 200ms`），缓动 `cubic-bezier(0.4, 0, 0.2, 1)`。
- 滚动进场用原生 `animation-timeline: view()`。**不引入 GSAP / Framer Motion**。
- 必须尊重 `prefers-reduced-motion: reduce`，该分支下 `transition` 与 `animation` 全部关闭。
- 禁止自动轮播、禁止阻挡搜索的视频。

## 10. 响应式

| 断点 | 变化 |
|---|---|
| < 640px | 单列；Hero 56 → 40px；section padding 降至 `--sp-8` |
| 640–1024px | 2 列网格 |
| ≥ 1024px | 3 列网格，容器满 1024px |
| ≥ 1440px | 居中留白 |

section 的底色块在所有断点保持满宽，节奏不断。

## 11. Do / Don't

### Do

- 正文 17px / 1.47，栏宽上限 702px
- 中文字距一律 `normal`
- 所有数字用 `tabular-nums`，规格表右列右对齐
- 分区靠 `--bg-subtle` 色块，不靠分隔线
- 蓝色只给可交互元素
- section 内 120px、section 间 236px 的宏观节奏
- 卡片零边框、18px 圆角、无阴影
- `backdrop-filter` 只写标准属性

### Don't

- 不给中文加负字距
- 不引入第三种底色，不引入第二个彩色
- 不用语义色做标签 / 徽章 / 状态点装饰
- 不用 Google Fonts CDN 加载字体（大陆不可达）
- 不用 Inter
- 不用多层阴影、大面积阴影
- 不给卡片加边框
- 不把正文居中（只有 Hero 标题居中）
- 不引入第二套 UI 库（后台的 Arco 不外溢到 C 端）
- 不在 `styles.css` 里散落颜色 / 字号 / 间距字面量，一律走 token

## 12. 与外部 Apple 规范的差异（遇到冲突以本文件为准）

若参考 2025 年前后反推自 apple.com 英文站的规范，以下四条**它已过时**：

| 项 | 外部规范 | 实测 2026-08 |
|---|---|---|
| 导航玻璃 | `rgba(0,0,0,.8)` 深色，48px | `rgba(255,255,255,.8)` 浅色，44px |
| 圆角上限 | "矩形不得超过 12px" | 28px 主导（本项目取 18px） |
| 填充按钮 | radius 8px | 980px pill |
| 底色节奏 | 黑 / `#f5f5f7` 二元交替 | 只有 `#ffffff` + `#f5f5f7`，零黑底 |

另有三处它**完全没有**，而本项目全需要：宏观间距（§6）、CJK 排版（§3）、数据密集界面（§4）。

以及一条它自相矛盾：正文写"negative tracking at all sizes"，但自己的字号表里 21px 那两行是 `+0.231px`（正的）。以实测为准——中文 `normal`，21px 副标 `+0.011em`。
