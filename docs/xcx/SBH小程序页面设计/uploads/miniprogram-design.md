# 小程序设计方案 · 商办租赁

> 载体：微信小程序。视觉规范继承 `.agent/design-system.md`（Apple 中性极简）。
> 本文件只写**小程序特有的适配与决策**，不重复 web 端已有的 token 定义。
> 改小程序视觉前，两份都要读。

## 0. 三条定盘决策（2026-08-20）

| # | 决策 | 理由 |
|---|---|---|
| D1 | ~~延续 Apple 中性极简，只做移动适配~~ **已于 2026-08-20 推翻** | 见 §1b |
| D1' | **布局与规范照移动端惯例重做，色彩仍走本项目中性色板** | 用户看过 v1 预览后判定 web 设计系统不适合移动端 |
| D2 | **范围 = 找房主链路 + 楼盘体系** | 楼盘字典是相对竞品的差异化资产，移动端也要站住；用户常见路径是「先相中楼再看房源」 |
| D3 | **纯 C 端**，供给侧全部留在后台 | 用户明确选择 |

### 已知取舍（D3 的代价，非疏漏）

经纪人在外场无法改房源状态。带看途中房源被租掉，前台会继续挂着，
直到有人回到后台处理。这**直接顶着北极星**（「数据是真的」），
且随供给量增长而放大。若日后前台失效供给投诉变多，优先回看这条。

## 1. 参考对象与不可照搬之处

参考素材：唯果租房小程序（`docs/xcx/`，15 张截图）。

**它是 C2C 住宅租房，我们是 B2B 商办租赁。** 这不是行业差异，是产品物理规律的差异：

| | 唯果 | 本项目 |
|---|---|---|
| 决策人 | 个人租客，冲动成分高 | 企业多人决策，周期数周至数月 |
| 决策依据 | 看图、看位置、看价格 | **算账**：单价×面积、物业费、免租期、押付、得房率 |
| 供给方 | 个人房东（UGC） | 商户与经纪机构 |
| 联系方式 | 电话/消息**直连房东** | 留资 → 顾问跟进 |

**可以借鉴的**：整体框架节奏、列表卡的左图右文形态、筛选行的位置、
详情页的规格网格、底部固定操作栏、半屏弹层。

**必须拒绝的**：
- 彩色标签体系（带独卫红、宠物友好橙）——撞 R3「标签零色相」
- 橙红价格——撞「蓝色只给可交互元素，数字用主文字色」
- 收藏我 / 看过我 / 个人主页 / VIP 会员 / 邀请有奖——C2C 社交机制，B2B 不成立
- 底部中央凸起的「发布」按钮——我们不做供给侧（D3）

## 1b. D1 反转：为什么 web 设计系统搬不进小程序（2026-08-20）

v1 按「延续 Apple 中性极简、只做移动适配」出了四屏预览，上机后被判定不合适。
复盘下来错的不是色彩，是**地基**：

| | v1（照搬 web） | v2（移动优先） |
|---|---|---|
| 页面底色 | 白底 | **灰底 `#f2f2f4`** |
| 分组方式 | 细分隔线 + 标题层级 | **白色圆角卡块**，块本身就是分组容器 |
| 卡块间距 | section padding 48px | **10px** |
| 字号阶 | 17 / 14 / 12 | **15 / 13 / 11** |
| 卡片圆角 | 18px | **12px** |
| 一屏可见房源卡 | 1.5 张 | **3 张** |

关键在第二行。桌面端靠留白和标题层级交代「这是一组」，移动端靠**白块的边界**
直接交代——白块本身就是容器，不需要额外的分隔线或标题去说明范围。
把桌面的分组手法搬到 375 屏，结果是留白吃掉屏幕、层级还是不清楚。

**色彩不在反转范围内。** 中性色板、标签零色相、价格用主文字色（靠字号与字重出挑，
不靠色相）全部保留。唯果的绿主色、橙红价格、彩色标签一概不引入。

## 2. 载体硬约束（决定了哪些 web 做法搬不过来）

**① 加载不了中文自定义字体。**
`wx.loadFontFace` 存在，但 CJK 字体动辄数 MB，实际不可用。
→ 中文走系统字体（iOS 即 PingFang SC，Android 落系统黑体），与设计系统首选一致，无损失。
→ **数字单独处理**：加载 Geist 的拉丁+数字子集（约 30–60KB），只挂在 `.num` 类上。
   这是为了保住 `tabular-nums`——北极星「账是清的」在移动端唯一的落点。
   子集加载失败时回退系统字体并保留 `font-variant-numeric`，不阻塞渲染。

**② `animation-timeline: view()` 不可用。**
设计系统的滚动进场全押在这个原生特性上，小程序 webview 不支持。
→ 改用 `wx.createIntersectionObserver`，进入视口时加 class 触发 CSS transition。
→ 位移量与时长沿用（14px / 500ms / `cubic-bezier(.4,0,.2,1)`），观感对齐 web。

**③ 没有 hover，只有按压。**
→ 用小程序的 `hover-class` + `hover-stay-time="70"`。
→ web 端那套 hover 反馈（卡片底色提亮、箭头右移）全部改为按压态：
   `scale(0.98)` + 底色下沉一档，松手复原。

**④ `backdrop-filter` 支持不稳。**
→ 导航栏放弃毛玻璃，改用不透明 `#ffffff` + 底部 1px `--line`。
   滚动到顶时透明压在 hero 上这条**取消**，小程序自定义导航成本高、机型差异大。

**⑤ 底部 tab 最多 5 个，且样式受限。**
→ 用 4 个，见 §3。

**⑥ 安全区。**
→ 底部固定操作栏必须 `padding-bottom: env(safe-area-inset-bottom)`。

## 3. 信息架构

```
tabBar（4 项，无中央凸起按钮）
├── 首页      平台叙事 + 搜索入口 + 精选
├── 找房      房源列表（筛选主战场）
├── 楼盘      楼盘列表 + 楼盘详情
└── 我的      收藏 + 我的留资 + 城市切换 + 设置
```

**为什么不放「地图找房」进 tab**：唯果把地图做成了独立入口，因为住宅租客关心
通勤距离，地图是第一诉求。商办选址同样看位置，但企业更先看的是**面积段和预算**，
地图是筛选后的验证工具而非入口。→ 地图作为「找房」页的**视图切换**（列表 ⇄ 地图），
不占 tab 位。

页面清单（D2 范围）：

| 页面 | 说明 |
|---|---|
| 首页 | hero 叙事 + 搜索 + 数据带 + 按类型 + 热门商圈 + 精选房源 |
| 找房 · 列表 | 筛选行 + 结果卡 + 分页/触底加载 |
| 找房 · 筛选面板 | 半屏弹层，承载八个维度 |
| 找房 · 地图 | 视图切换，价格气泡 pin |
| 房源详情 | 画廊 + 规格 + 概况 + 配套 + 描述 + 所在楼盘 + 相关推荐 + 底部操作栏 |
| 楼盘列表 | 区域/等级筛选 + 楼盘卡 |
| 楼盘详情 | 核心信息 + 在租房源分组 + 参数 + 位置 + 猜你喜欢 |
| 留资弹层 | 半屏，需求摘要预填，**只问手机号与期望入驻** |
| 我的 | 收藏 / 浏览过 / 我的留资 / 对比 / 城市 / 设置。无 UGC、无会员 |

### 三个屏的设计要点（已出稿）

**筛选面板** —— 租金单位放在**最前**，用分段控件，并显式告知
「切换会改变结果集」+「另有 N 套按其他单位报价」。
这是商办的结构性难题（三种报价单位无法互相换算），
放在底部或折叠里等于把问题藏起来。底栏按钮写实时结果数「查看 168 套」。

**留资弹层** —— 需求摘要由上下文预填（房源名、面积、单价、月租估算），
用户只需选期望入驻 + 填手机号。**问得越少，转化越高**；
其余信息顾问电话里问，不在小程序里做长表单。

**筛选无结果** —— 不只说「没有符合条件的房源」。列出**具体的放宽建议
并带上各自的结果数**（面积放宽到 1,200㎡ 以上 → 找到 7 套），
让用户一步就能走出死胡同。兜底 CTA 是「说需求，让顾问帮你找」。

**楼盘列表** —— 「暂无在租」的楼盘**下沉为独立分组**（标题：暂无在租 · 可留资等通知），
文字与封面统一降饱和降对比。不隐藏——楼盘字典本身有查询价值；
也不混排——否则用户以为平台没货。

## 4. 视觉适配

### 色彩
沿用 `.agent/design-system.md` §2，但页面底色改为 **`#f2f2f4`**（比 web 的
`#f5f5f7` 略深一档），白卡才立得出来。其余一个值不改。

### 卡块系统（v2 的核心）
```
页面底色  #f2f2f4
白卡      #ffffff · radius 8px · 左右 margin 12px · 块间 10px · 内 padding 14px
图片      radius 6px      标签 radius 3px      按钮/输入 radius 6px
```

**圆角比 web 小两档**（web 卡片 18px）。375 屏上卡块本身就窄，12px 已经偏圆，
8px 更接近「贴合内容的容器」而不是「一颗药丸」。
块内再分组用 1px `--line` 横线，不再嵌套白卡。

### 字号
移动端重新定阶，**不沿用 web 的 17px 正文**。

| 角色 | 小程序 | web |
|---|---|---|
| Hero 标题 | 23 | 56 |
| 卡块标题 | 17 | 28 |
| 列表卡标题 | 15 | 19 |
| 正文 / 元信息 | 13 | 17 |
| 辅助 / 发布人 | 11–12 | 14 |
| 标签 | 10 | 12 |
| 价格 | 19 | 24 |
| 详情大价格 | 26 | 48 |

### 间距
左右 12px，卡块间 10px，卡内 14px。**web 的 `--section-pad-y` 概念不适用**——
小程序没有「section」，只有卡块。

## 5. 关键组件

### 房源卡：左图右文（**与 web 不同，见 §7 RISK**）

```
┌────────┬────────────────────────────────┐
│ 图     │ 标题 15/600 · 两行截断          │
│ 112×84 │ 1,860 ㎡ | 28 层 | 得房率 72%   ← 12/--ink-2 数字等宽
│ r6     │ ◎ 静安区 · 距南京西路站 320 米  ← 12/--ink-3
│ 角标   │ 价格 19/600 tabular + 单位 12   │
│ 新上   │ 标签 ×4  10/r3                  │
└────────┴────────────────────────────────┘
```

**不放商户名与「今天更新」**（2026-08-20 决定）。理由：
- 商办用户不按经纪机构选房源，商户名在卡上是噪声；
- 「今天更新」在每张卡上重复出现就失去了信号价值。
  时效信息移到**详情页**，在那里它才真正服务「数据是新的」。

去掉这一行后 375 屏上一屏可见 **4 张**完整房源卡。

### 筛选行（吸顶）
`位置 ▾   价格 ▾   面积 ▾   筛选 ⚙︎(3)`
高 44pt，吸顶在导航下。生效条件数以角标显示。点任一项唤起半屏面板。

### 规格网格（详情页，北极星落点）
4 列等分，每格「标签 12/--ink-3」上、「数值 17/600 tabular-nums」下。
数值缺失显示 `—`，不显示 0，不隐藏整格（保持网格对齐）。

### 底部操作栏（详情页）
`收藏  分享  │  预约看房（主 CTA，pill，accent 底）`
高 56pt + 安全区。滚动时常驻。

## 6. 动效

| 场景 | 做法 |
|---|---|
| 进场 | IntersectionObserver 触发，fade + 上浮 14px，500ms |
| 按压 | `hover-class`，`scale(0.98)` + 底色下沉一档，70ms 延迟触发 |
| 页面切换 | 用小程序原生转场，不自定义 |
| 骨架屏 | 列表与详情首屏用骨架，不用 loading 转圈 |

禁止：视差、数字滚动计数、自动轮播、弹跳缓动。

## 7. SAFE / RISK

### SAFE（类目基线，用户预期如此）
1. 底部 tabBar + 吸顶筛选行 + 触底加载——所有找房类小程序都这样
2. 详情页底部固定 CTA 栏
3. 半屏弹层承载筛选与留资

### RISK（刻意偏离）

**R1 · 列表卡用左图右文，与 web 的上图下文不一致**
*得到*：375 宽一屏能看 3–4 张卡（上图下文只能看 1.5 张）；图小了商户上传图的质量缺陷不明显。
*代价*：跨端形态不一致。可接受——载体不同，密度诉求不同。

**R2 · 不做地图 tab，地图降级为视图切换**
*得到*：tab 位留给楼盘体系，符合「先相中楼再看房源」的真实路径。
*代价*：与同类小程序惯例不符，重位置的用户要多点一次。

**R3 · 全站零彩色标签，价格用黑色**
*得到*：与 web 完全一致，且数字成为视觉主角。
*代价*：**这是三条里最难坚持的**。小程序生态里所有竞品都用彩色，
第一眼会显得"素"。后续迭代中最容易被以「转化率」为由破坏。
