# FP-01 首页 PRD

> 路由：`/`  
> 优先级：P0  
> 状态：待确认

## 1. 页面目标

首页应让首次访问者在 10 秒内理解平台提供企业办公选址服务，并能立即搜索房源、浏览精选供给或发起咨询。

## 2. 用户故事

- 作为正在选址的企业用户，我希望直接按区域、关键词和办公类型开始找房。
- 作为尚未形成明确条件的用户，我希望看到热门区域、精选房源和服务流程。
- 作为重视服务质量的决策者，我希望快速判断平台是否专业可信。

## 3. 页面结构

### 3.1 全局导航

- 品牌标识。
- 当前城市入口；MVP 单城市时可展示但不制造不可用切换。
- 找办公室、楼盘库、办公解决方案、关于我们。
- “获取选址方案”主操作。
- 移动端折叠菜单必须支持键盘和焦点管理。

### 3.2 首屏 Hero

- 一句明确品牌主张和一句辅助说明。
- 搜索框包含关键词/楼盘、区域和办公类型。
- 主按钮“查找办公室”。
- 提交后进入 `/listings`，全部条件写入 URL。
- 首屏使用一张高质量办公空间图片或克制的编辑型版式，不使用自动轮播。

### 3.3 精选房源

- 默认展示 6 套，桌面 3 列、平板 2 列、移动端 1 列。
- 仅显示后台推荐且当前有效的房源。
- 推荐不足时用其他当前有效供给按既定稳定排序补齐，但不显示虚假“精选”标签。
- 卡片至少包含封面、标题、楼盘、区域、面积、类型、标准化价格和最多三个亮点。

### 3.4 热门区域

- 展示行政区或商圈名称、当前有效房源数量和代表图片。
- 数量与点击后列表结果使用同一查询时点和口径。
- 数量为 0 的区域默认不进入热门区域。

### 3.5 服务能力

- 用选址需求、方案匹配、实地带看、商务谈判、入驻支持表达服务流程。
- 不宣称后台没有数据或运营无法保证的服务时效。
- 提供“提交需求”入口。

### 3.6 内容与收束咨询

- 展示最多 3 篇已发布的办公指南或品牌内容。
- 页尾咨询区说明提交后会发生什么，并明确隐私提示。

## 4. 数据规则

- 精选卡片、区域数量和楼盘入口必须来自统一有效供给查询。
- 首页查询使用同一 `asOf`，禁止每个模块分别形成不一致数量。
- 媒体不可用时展示固定比例品牌占位，不改变布局。
- CMS 内容只读取已发布版本。

## 5. 页面状态

| 状态 | 表现 |
|---|---|
| 正常 | 完整展示可用模块 |
| 无精选 | 隐藏精选模块或展示普通有效房源，不显示空骨架 |
| 无内容文章 | 隐藏内容模块，不影响找房主路径 |
| 房源服务失败 | 显示可重试错误区，不展示缓存外的旧房源 |
| 图片失败 | 使用固定比例占位和可读替代文本 |

## 6. SEO 与埋点

- title、description、canonical、OG 图片完整。
- 首页只存在一个 H1。
- 事件：`home_search_submit`、精选曝光/点击、区域点击、咨询打开。
- 搜索关键词不得作为个人信息进入分析事件。

## 7. 验收标准

- 当用户提交首屏搜索时，系统应跳转至可复现相同条件的房源列表 URL。
- 当精选房源任一有效供给条件失效时，系统应在失效窗口内从首页撤销该房源。
- 当用户点击热门区域时，列表结果数应与首页相同查询口径一致。
- 当视口为 375px 时，系统应保持搜索、导航和咨询入口完整可操作。
- 当图片或内容模块失败时，系统应保持核心搜索流程可用且不发生明显布局跳动。
- Lighthouse/等价实测中，首页应满足技术设计中的 Core Web Vitals 和可访问性目标。

## 8. 非目标

- 地图搜索。
- 自动轮播大屏。
- 登录后个性化推荐。
- 多城市自动定位。
