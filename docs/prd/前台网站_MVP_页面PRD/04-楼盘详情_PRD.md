# FP-04 楼盘详情 PRD

> 路由：`/buildings/[slug]`  
> 优先级：P0  
> 状态：待确认

## 1. 页面目标

楼盘详情以稳定的楼盘主数据承载位置、品质、配套和当前有效供给，使用户可以先判断楼盘，再比较其中具体房源。

## 2. 用户故事

- 作为关注特定商务区的用户，我希望了解楼盘位置、等级、交通和配套。
- 作为正在比较同一楼盘空间的用户，我希望看到当前真实可选房源及价格和面积范围。
- 作为尚未找到合适单元的用户，我希望提交针对该楼盘的需求。

## 3. 页面结构

### 3.1 楼盘主视觉

- 楼盘名称、等级、行政区/商圈和地址。
- 封面及楼盘画廊。
- 楼盘摘要和咨询入口。

### 3.2 核心信息

- 行政区、商圈、最近地铁。
- 楼宇等级和后台定义的公开配套。
- 详细介绍。
- 经纬度存在并允许公开时可展示地图；MVP 无地图时展示文字交通信息。

### 3.3 当前有效供给概览

- 当前有效房源数。
- 面积区间。
- 价格区间按租售类型、币种和单位分别展示。
- 聚合卡点击后定位到楼内房源列表并应用相应条件。

### 3.4 楼内房源

- 默认展示当前有效房源。
- 支持类型、面积、价格单位和排序等必要筛选。
- 默认最多首屏展示 12 套，其余分页或“查看更多”。
- 卡片使用与房源列表相同的数据契约和组件。

## 4. 数据规则

- Building 本身须存在、未逻辑删除、状态可公开，所属城市和区域启用。
- 楼内房源、数量和区间必须调用统一有效供给服务。
- 楼盘可公开但暂时无房源时，允许展示楼盘内容和通用咨询；不得显示“在租”措辞或伪造价格区间。
- 楼盘内不同价格单位不得合并计算最小/最大值。
- 后台工作版本和内部坐标精度不直接公开。

## 5. 页面状态

| 状态 | 表现 |
|---|---|
| 有有效房源 | 显示聚合和房源列表 |
| 无有效房源 | 展示楼盘内容、明确暂无可选空间和提交需求入口 |
| 楼盘不可公开 | 404 |
| 聚合失败 | 不显示错误区间，提供重试 |
| 媒体不足 | 使用品牌占位；若违反楼盘公开规则则不公开页面 |

## 6. SEO 与分析

- 优先使用 Building SEO title/description，缺失时安全生成。
- 结构化数据不声称楼盘内所有历史房源均可租。
- 事件：楼盘浏览、画廊、供给筛选、房源点击、咨询打开。

## 7. 验收标准

- 当楼盘存在有效房源时，系统应以同一查询时点展示房源数、区间和房源列表。
- 当最后一套房源失效时，系统应撤销聚合数值并进入“暂无可选空间”状态，但可按楼盘公开规则保留内容页。
- 当聚合包含多种价格单位时，系统应分别展示，不得生成误导性统一区间。
- 当用户点击楼内房源卡片时，系统应进入对应的有效房源详情。
- 当 Building、城市或区域停用时，系统应在失效窗口内停止公开楼盘及其房源入口。
- 当视口为 375px 时，楼盘信息、供给筛选和咨询入口均应无横向溢出。

## 8. 非目标

- 楼盘历史成交。
- 业主后台入口。
- 实时地图周边 POI 服务。
- 用户评论与评分。
