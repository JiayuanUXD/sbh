## 1. 页面定位

楼盘详情是面向企业选址人的“楼盘价值判断 + 楼内供给比较页”，用于回答：

1. 楼盘位于哪里，交通、品质和企业形象是否合适。
2. 楼盘有哪些建筑、物业、设备和配套条件。
3. 当前有多少出租、出售或联合办公空间。
4. 各类有效供给的面积与价格区间是什么。
5. 用户应继续查看哪套房源，或如何提交楼盘级需求。

楼盘主数据可以在暂无房源时继续公开，但供给数量、价格和面积聚合必须来自同一查询时点的当前有效房源。

## 2. 用户与核心任务

| 用户 | 核心任务 |
|---|---|
| 企业决策者 | 判断楼盘地段、等级、形象、物业和总体成本 |
| 行政/选址负责人 | 比较楼内不同面积、价格、装修和入驻时间的空间 |
| 创业团队负责人 | 查看联合办公、服务式办公和可注册能力 |
| 异地企业 | 通过地图、地铁、周边和楼盘参数理解本地环境 |
| 搜索引擎访客 | 从楼盘词进入后确认真实性，并继续查看当前房源 |

## 3. 页面信息架构

```text

├── 全局导航与搜索

├── 楼盘名称、标签、分享
├── 首屏价值区
│   ├── 楼盘分类媒体画廊
│   └── 价格/面积/房源数、地址、地铁、物业、开发商、CTA
├── 锚点导航
├── 当前有效供给
│   ├── 出租
│   ├── 出售
│   └── 联合办公
├── 楼盘参数
├── 设备与配套
├── 楼盘特色与介绍
```

## 4. 首屏价值区

### 4.1 面包屑、名称与标签

- 面包屑：首页 / 城市写字楼 / 行政区 / 商圈 / 楼盘。
- `H1` 使用楼盘公开名称。
- 标签优先展示物业类型、楼宇等级、已验证认证、近地铁等。
- “5A”“LEED”“可注册”等必须映射独立可验证字段或凭证。
- 提供分享入口；收藏为 P1。
- 分享只使用 canonical URL，不包含筛选和个人信息。

### 4.2 楼盘媒体画廊

- 分类：外立面、大堂、公共区、标准层、配套、楼层平面图、视频。
- 楼盘媒体与具体房源媒体分别维护，不得无来源混用。
- 首屏展示一张主图和 2–4 张缩略图；移动端横向滑动。
- 全屏模式支持分类、缩略图、键盘、触控、焦点锁定与归还。
- 视频默认静音、不自动播放并延迟加载。
- 楼层平面图标“示意图，以现场实际情况为准”。
- 媒体失败和缺失规则与房源详情一致。

### 4.3 当前供给概览

首屏展示：

| 字段 | 来源 | 展示规则 |
|---|---|---|
| 有效供给数 | 当前有效房源 `[计算]` | 出租、出售、联合办公分别计数 |
| 可选面积 | 当前有效房源 `[计算]` | 按供给分组展示最小–最大面积 |
| 价格 | 当前有效房源 `[计算]` | 按租售类型、币种、单位分别展示最低或区间 |
| 立即可入驻数 | 当前有效房源 `[计算]` | 仅统计满足日期口径的房源 |
| 地址 | Building | 行政区、商圈、详细地址 |
| 地铁 | Building/Location | 线路、站点、距离/步行参考 |
| 物业公司 | Building | 空值时隐藏 |
| 开发商 | 新增结构化字段 | 空值时隐藏，不从介绍文本解析 |
| 总建筑面积 | 新增结构化字段 | 与标准层面积分开 |
| 更新时间 | 聚合时点/核验时间 | 展示“供给截至 YYYY-MM-DD HH:mm” |

规则：

- 聚合使用同一 `asOf`，页面数量、区间和楼内列表必须一致。
- 跨租售类型、币种或计价单位不得合并。
- 楼盘无有效供给时隐藏价格和面积区间，不显示 0 元、历史最低价或“在租”。
- 聚合失败时不展示旧数字；正文继续可读，供给模块提供局部重试。

### 4.4 决策卡与 CTA

- 桌面端首屏右侧或媒体旁展示楼盘摘要与“询价 / 预约看房”。
- 移动端底部固定栏展示楼盘名/供给摘要和 CTA。
- 无有效供给时 CTA 改为“登记找房需求”。
- 公共电话和二维码遵循平台统一公开联系方式规则。

## 5. 楼内有效供给

### 5.1 分组

- 独立分组：出租、出售、联合办公。
- 仅当对应分组存在当前有效供给时显示。
- 不显示空 Tab；全部为空时进入“暂无可选空间”状态。
- 租售/联合办公的价格口径、筛选项和卡片文案分别适配。

### 5.2 筛选与排序

每组支持：

- 面积区间。
- 价格区间和计价单位。
- 装修状态。
- 可入驻时间。
- 默认推荐、面积升降、单价升降、总价升降。

规则：

- 用户选择价格排序前必须明确价格单位。
- 不同币种或单位不得共同排序。
- URL 只保存有复现价值的筛选，不保存展开状态、手机号或个人信息。
- 筛选后结果数、价格区间和列表使用同一查询上下文。

### 5.3 列表形态

- 桌面默认紧凑表格，可切换卡片；移动端固定卡片。
- 表格/卡片展示：标题、面积、工位、装修、楼层、单价、总价、特色、可入驻日期、更新时间。
- 首屏每组最多 6 条，支持“查看更多”；完整结果可在楼盘页分页或进入列表页并保留楼盘条件。
- 点击进入对应有效房源详情。
- 房源失效后同时从数量、区间和列表撤销。

### 5.4 无供给状态

- 显示“当前暂无公开可选空间”，不得暗示楼盘已永久满租。
- 提供楼盘级需求表单和附近相似楼盘。
- 不展示伪造的最低价、面积区间或历史房源。

## 6. 楼盘参数

### 6.1 字段清单

| 分组 | 字段 | 模型状态 |
|---|---|---|
| 身份 | 物业类型、楼宇等级、认证、注册能力 | 前三项部分已有；具体认证凭证需新增 |
| 建筑 | 竣工时间、总楼层、总建面、标准层面积、标准层高、净层高、得房率 | 竣工和总楼层已有；其余需新增 |
| 开发物业 | 开发商、物业公司、物业费 | 物业公司/费已有；开发商需新增 |
| 垂直交通 | 客梯数、货梯数、分区、等候说明 | 需新增 |
| 停车 | 总停车位、月租/临停费用、充电位 | 总数已有；费用和充电位需新增 |
| 空调 | 类型、开放时间、加时规则/费用 | 需新增 |
| 网络供电 | 运营商、网络能力、供电与备用电源 | 需新增 |
| 安防服务 | 门禁、监控、消防、前台、会议/商务服务 | 需新增或扩展配套字典 |

### 6.2 展示规则

- 按“建筑 / 物业与费用 / 电梯与停车 / 空调与网络 / 注册与认证”分组。
- 空字段隐藏；当整组信息不足时显示一次“信息待完善”，不逐行堆叠“暂无数据”。
- 楼盘参数不得从某套房源字段推断。
- 开放时间、费用和认证显示来源或更新时间。
- 认证到期、物业变化等事件应触发复核。

## 7. 设备、配套与楼盘内容

### 7.1 设备与配套

- 使用结构化分类：办公服务、空间设施、楼宇配套、交通生活。
- 展示电梯、停车、空调、网络、门禁、餐饮、商业、会议空间等。
- 收费或开放时间可变化的项目必须有更新时间。
- 不以图标或标签暗示后台没有的数据。

### 7.2 楼盘特色

- 最多展示 3–5 条经审核亮点。
- 亮点需对应可验证事实，如江景、近地铁、认证、商业综合体。
- 禁止“区域最优”“最低租金”“顶级物业”等无法证明的绝对化文案。

### 7.3 详细介绍

- 建议结构：项目概况 / 建筑与空间 / 物业服务 / 交通与商业 / 适合企业。
- 富文本使用白名单节点服务端渲染。
- 自由文本中的面积、楼层、物业和交通信息应与结构化字段一致。
- 冲突时阻止发布或进入内容复核。

## 8. 地图与周边信息（P1）

### 8.1 地图

- 使用楼盘经审核坐标。
- 地图进入视口后加载，不阻断首屏。
- 默认不请求用户位置；路线功能由用户主动触发。
- 无坐标或地图失败时展示静态位置卡和外部导航。

### 8.2 POI

- 分类：交通、餐饮、银行、酒店；交通分地铁和公交。
- 每类默认最近 5 条，展示名称、距离和方向。
- 点击 POI 在地图高亮。
- 数据来自单一地图服务并缓存，或来自楼盘人工精选 `nearbyPlaces`；同一环境不得同时维护两套冲突真源。
- 显示数据来源和更新时间；POI 不进入核心 JSON-LD。

## 9. 周边与相似楼盘

### 9.1 周边楼盘

- 以距离、同商圈和当前有效供给为主要条件。
- 卡片展示楼盘名、区域/商圈、最低有效价格分组、可选面积和有效房源数。
- 跨单位不生成单一最低价。
- 无有效价格时显示“价格面议”，不得使用历史价格。

### 9.2 相似楼盘

- 推荐维度：同商圈、同等级/类型、相近价格区间、相近面积供给。
- 标题使用“相似楼盘”，不声称个性化，除非已取得相应同意和数据基础。
- 推荐服务失败时隐藏模块，不阻断正文和咨询。

## 10. 咨询与预约看房

### 10.1 上下文

打开表单时自动携带：

`buildingSlug + activeSupplyGroup + currentFilters + pagePath + campaign + section`

从供给卡片打开时额外携带 `listingSlug`。

### 10.2 流程

1. 第一步：手机号、联系人称呼、公司/团队规模、隐私同意。
2. 第二步：意向日期、面积、预算、租售类型和备注。
3. 提交前服务端重新校验楼盘和目标房源。
4. 成功后展示需求摘要、联系预期和继续看房入口。
5. 预约状态为“待顾问确认”，不承诺时段已确认。

### 10.3 无房源与失效

- 楼盘无有效房源时创建楼盘级需求，不写错误房源关系。
- 某目标房源提交瞬间失效时，明确提示并降级为楼盘需求。
- 楼盘已停用或不可公开时拒绝创建该楼盘意向，并引导通用找房需求。

### 10.4 隐私与防刷

- 手机号、姓名、备注不得进入 URL、埋点、地图或前端日志。
- 使用 honeypot、IP/设备节流、重复提交去重、服务端枚举和长度校验。
- 平台只展示公共顾问身份和公共联系方式，不公开 `contactBroker` 私人手机号。

## 11. 页面状态

| 状态 | 页面表现 |
|---|---|
| 有有效房源 | 展示聚合、供给分组和房源列表 |
| 无有效房源 | 保留楼盘正文；隐藏价格/面积聚合和供给 Tab；展示登记需求 |
| 楼盘不存在/不可公开 | 品牌化 404 |
| 城市/区域停用 | 楼盘 404，关联房源入口同步撤销 |
| 聚合失败 | 不显示旧数字；供给区局部重试，正文继续可读 |
| 单一供给分组为空 | 不显示该 Tab |
| 媒体不足 | 使用品牌占位；低于公开门槛时不公开 |
| 地图/POI 失败 | 静态位置卡降级 |
| 推荐为空/失败 | 隐藏模块 |
| 咨询失败 | 保留非敏感输入，提示重试和公共联系方式 |

## 12. 响应式与可访问性

- `≥1200px`：12 栏首屏；楼内供给默认表格。
- `768–1199px`：单列首屏；供给仍可用紧凑表格或卡片。
- `<768px`：横滑媒体、供给卡片、底部固定 CTA。
- 320px 和 375px 无横向溢出；核心供给不依赖横向滚动表格。
- 粘性锚点：在租房源 / 在售房源 / 联合办公 / 楼盘参数 / 楼盘特色 / 周边 / 相似楼盘。
- 不存在的供给分组不进入锚点。
- Tab、筛选、排序、画廊、弹窗、折叠区均可键盘操作。
- 状态和错误使用文字/语义提示，不仅依赖颜色。
- 遵循 `prefers-reduced-motion` 和 WCAG 2.1 AA。

## 13. 数据与聚合规则

- Building 必须存在、未逻辑删除、已发布、运营启用，且所属城市/区域可公开。
- 数量、面积区间、价格区间、立即可入驻数和列表使用同一 `asOf` 与统一有效供给服务。
- 聚合按租售类型、币种、周期和单位分组。
- 楼盘可公开但无房源时允许保留内容页。
- 公开 DTO 不包含内部坐标精度、商户资质、审核原因、举报状态、内部电话或工作版本。
- 楼盘主数据更新、状态变化和关联房源变化必须精准失效缓存。
- 价格、认证、开放时间和 POI 等时效数据超过阈值后进入复核。

## 14. SEO 与分享

- canonical 为 `/buildings/[slug]`。
- 供给 Tab、筛选、排序、锚点和咨询状态不生成独立 canonical。
- metadata 优先后台 SEO；缺失时由楼盘名、行政区、商圈和物业类型生成。
- JSON-LD 使用 `Place`。
- 仅在存在有效供给时输出按租售类型、币种和单位分组的 `AggregateOffer`。
- 不声明历史房源、未经验证的评分、最低价或楼盘内全部空间均可租。
- 输出 `BreadcrumbList`。
- OG 图使用楼盘公开封面，不使用具体房源图或带私人联系方式水印的图片。
- 楼盘无房源但仍可公开时可保留索引；楼盘不可公开时 404 并从 sitemap 撤销。

## 15. 埋点与指标

### 15.1 漏斗

`building_view → supply_group_view → listing_click → inquiry_open → inquiry_submit → inquiry_success`

### 15.2 事件

| 事件 | 关键属性 |
|---|---|
| `building_view` | buildingId、有效供给数、价格单位组、asOf |
| `supply_group_view` | buildingId、租售分组、结果数 |
| `supply_filter/sort` | 分组、筛选项、排序项、结果数 |
| `building_listing_click` | buildingId、listingId、分组、位置、排名 |
| `gallery_open/media_view` | 媒体分类、序号 |
| `map_interaction/poi_click` | buildingId、POI 类别、距离区间 |
| `related_building_click` | 当前楼盘、目标楼盘、推荐类型、排名 |
| `inquiry_open/submit/success/fail` | buildingId、listingId（可选）、入口、campaign、失败码 |
| `stale_target_fallback` | 原房源、楼盘、发生阶段、降级结果 |

事件不得包含手机号、姓名、备注原文或精确用户位置。

## 16. 性能要求

- 移动端 75 分位：LCP ≤ 2.5 秒、CLS ≤ 0.1、INP ≤ 200 毫秒。
- 首屏只加载必要媒体；视频、地图、POI、后续供给和推荐延迟加载。
- 图片提供尺寸、响应式资源、压缩格式和占位。
- 聚合与楼内列表共享查询上下文，避免重复全量查询。
- 地图 SDK 不进入首屏关键链路。
- 第三方脚本失败不得影响楼盘正文、供给和咨询。

## 17. 建议数据模型扩展

### 17.1 Buildings

- `developerAndScale`：开发商、总建面、标准层面积、层高、得房率。
- `verticalTransport`：客梯、货梯、分区说明。
- `buildingServices`：空调、网络、供电、门禁、停车费用和服务时间。
- `certifications`：认证名称、编号/凭证、有效期、公开状态。
- `mediaItems`：资源、类型、分类、alt、日期、排序、平面示意标记。

### 17.2 POI

- 默认使用地图服务查询并缓存。
- 如需运营精选，新增楼盘级 `nearbyPlaces`，包含分类、名称、坐标、距离、来源和更新时间。
- 同一部署环境只启用一种 POI 真源。

### 17.3 公开 DTO

- 扩展 Building Detail DTO 和 Listing Card DTO，仅加入本页面需要的公开字段。
- 内部权限、经纪人联系方式、认证附件原件和高精度内部坐标不得进入 DTO。

## 18. 分期

| 阶段 | 范围 |
|---|---|
| P0 | 完整楼盘参数、供给分组/筛选/排序、聚合、咨询、有效性、响应式、SEO |
| P1 | 视频、平面图增强、地图与实时 POI、收藏/分享增强、信息纠错 |
| P2 | 路线规划、预约时段、顾问在线状态、个性化楼盘推荐 |

P1/P2 数据依赖可提前建模，但对应模块不得阻塞 P0。

## 19. 测试矩阵

1. 出租、出售、联合办公同时存在、单组存在、全部为空。
2. 三种租金单位、出售总价、工位价和价格面议。
3. 面积/价格/装修/入驻筛选和四类排序，验证跨单位不混排。
4. 建筑、物业、电梯、停车、空调、网络和认证字段有值/缺失。
5. 媒体分类、视频、平面图、单图失败和全部失败。
6. 地图正常、无坐标、SDK 失败、POI 超时和拒绝定位。
7. 房源、楼盘、城市、区域、商户状态变化后的聚合同步。
8. 咨询成功、目标房源失效降级、楼盘停用、限流和服务失败。
9. 320/375/768/1024/1440px、表格转卡片、键盘、读屏和减少动效。
10. canonical、OG、Place、AggregateOffer、BreadcrumbList、404 和 sitemap。
11. 手机号不进入 URL、埋点、日志、地图或分享。

## 20. EARS 验收标准

- 当楼盘存在有效供给时，系统应以同一查询时点展示分组数量、面积区间、价格区间和房源列表。
- 当楼盘包含多类供给时，系统应按租售类型、币种和单位独立聚合、筛选与排序。
- 当用户选择价格排序时，系统应先确定计价单位，不得跨单位比较。
- 当任一房源失效时，系统应在失效窗口内同时从数量、区间、列表、推荐和 sitemap 资格中撤销。
- 当最后一套房源失效时，系统应撤销价格与面积聚合并进入“暂无可选空间”，但可按楼盘公开规则保留正文。
- 当 Building、城市或区域停用时，系统应停止公开楼盘及关联房源入口。
- 当地图或 POI 服务不可用时，系统应展示地址、地铁和外部导航降级，且供给和咨询保持可用。
- 当楼盘参数缺失时，系统不得使用具体房源参数补齐楼盘字段。
- 当用户使用键盘或读屏浏览时，画廊、供给分组、筛选、排序和弹窗应可理解、可操作。
- 当视口为 375px 时，楼盘信息、供给卡片和咨询入口应无横向溢出且不被固定栏遮挡。
- 当页面生成 SEO 数据时，系统不得输出失效供给、跨单位最低价、未经验证的评分或内部信息。
- 当分析、地图或错误请求发出时，系统不得携带手机号、姓名或精确用户位置。

## 21. 非目标

- 楼盘历史成交、历史租金趋势和投资回报承诺。
- 在线签约、支付和产权交易。
- 公开业主、商户或经纪人的私人联系方式。
- 在 P0 阶段接入实时地图路线、预约日历或顾问在线状态。
- 用户评论、评分和未经审核的开放式内容。
- 将历史、下架或未审核房源用于补齐聚合值。
