# FP-03 房源详情 PRD

> 路由：`/listings/[slug]`  
> 优先级：P0  
> 状态：待确认

## 1. 页面目标

房源详情应让用户判断该具体空间是否值得咨询或实地查看，并在任何入口下保证所见房源当前真实有效。

## 2. 用户故事

- 作为企业选址人，我希望快速看到价格、面积、位置、类型和可入驻时间。
- 作为方案比较者，我希望查看真实图片、空间亮点、楼盘情况和同楼盘替代方案。
- 作为有兴趣的用户，我希望无需离开详情页即可询价或预约看房。

## 3. 页面结构

### 3.1 面包屑与画廊

- 首页 / 行政区或商圈 / 楼盘 / 房源。
- 主图与缩略图画廊；支持键盘、触控和全屏查看。
- 图片显示顺序由公开媒体顺序决定，封面不得重复。
- 图片计数、alt 和失败占位完整。

### 3.2 核心决策区

- 房源标题和办公类型。
- 标准化价格，明确币种和单位。
- 面积、工位数、可入驻时间。
- 楼盘名称、区域、地址。
- 最多三个重要亮点。
- 桌面为右侧粘性决策卡；移动端提供底部固定咨询栏。

### 3.3 详细内容

- 房源说明。
- 空间参数和配套。
- 所在楼盘摘要，提供楼盘详情链接。
- 位置与交通信息；MVP 可用静态位置说明，不强制地图。
- 同楼盘其他有效房源。
- 相似有效房源；必须说明推荐维度或保持中性标题。

## 4. 数据与失效规则

- 按 slug 查询后必须在响应时再次通过统一有效供给服务。
- 页面读取当前发布版本，不读取尚在审核的工作版本。
- 相关推荐再次应用完整有效供给谓词并排除当前房源。
- 价格、图片或楼盘关键数据缺失且触发媒体完整性规则时，该房源不得公开。
- 页面不得显示内部商户资质、审核原因、举报状态或未经授权的经纪人信息。

## 5. 咨询入口

- 主按钮文案为“询价 / 预约看房”。
- 打开咨询表单时自动带入 `listingSlug`、页面路径和活动参数。
- 表单关闭后焦点返回触发按钮。
- 提交成功后详情页保持原上下文并显示下一步说明。

## 6. 页面状态

| 状态 | 表现 |
|---|---|
| 正常 | 展示完整当前发布内容 |
| slug 不存在 | 返回品牌化 404 |
| 房源已失效 | 返回 404，不显示旧详情和咨询目标 |
| 相关推荐为空 | 隐藏对应模块 |
| 单张图片失败 | 展示占位，其他图片仍可浏览 |
| 数据服务失败 | 错误页和重试，不回退旧 `status=available` 查询 |

## 7. SEO、分享与分析

- 使用后台 SEO 字段；缺失时由房源标题、楼盘和区域生成。
- canonical 唯一，输出正确 OG 图片和基础结构化数据。
- 分享只使用公开 URL，不附带个人筛选信息。
- 事件：详情浏览、画廊打开、楼盘跳转、相关推荐点击、咨询打开。

## 8. 验收标准

- 当有效房源被访问时，系统应展示当前发布版本及统一格式的核心参数。
- 当房源不再满足任一有效供给条件时，系统应在失效窗口内停止渲染详情并从推荐和 sitemap 撤销。
- 当用户在移动端滚动页面时，咨询操作应持续可达且不得遮挡正文末尾。
- 当用户使用键盘浏览画廊时，系统应支持切换、关闭和焦点归还。
- 当相关推荐出现时，系统应排除当前房源且仅包含当前有效供给。
- 当价格单位为元/工位/月时，页面不得将其解释为元/㎡/天。

## 9. 非目标

- 公开完整业主或经纪人联系方式。
- 历史价格走势。
- 在线签约或支付。
- 3D/VR 看房。
