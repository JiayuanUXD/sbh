## 1. 页面定位

房源详情是面向企业选址人的“具体空间决策页”，用于回答：

1. 这套空间的价格和费用口径是什么。
2. 空间多大、能容纳多少人、位于什么楼层。
3. 装修、家具、注册、空调和租期等交付条件是否匹配。
4. 所在楼盘、交通和周边环境是否适合企业。
5. 是否值得立即咨询或预约实地看房。

页面必须以当前公开有效的具体房源为主体，不得用楼盘均值、历史房源或经纪人口头信息替代本房源数据。

## 2. 用户与核心任务

| 用户 | 核心任务 |
|---|---|
| 企业决策者 | 判断地段、形象、总成本和可入驻时间是否满足公司计划 |
| 行政/选址负责人 | 核对面积、工位、装修、楼层、租期、费用和交通 |
| 创业团队负责人 | 判断月度预算、家具、注册和拎包入驻条件 |
| 异地企业 | 通过楼盘、地铁、地图、周边和顾问服务理解现场情况 |
| 搜索引擎访客 | 快速确认搜索结果是否对应有效房源，并继续咨询或比较 |

## 4. 首屏决策区

### 4.1 面包屑、标题与标签

- 面包屑：首页 / 城市写字楼 / 行政区 / 商圈 / 楼盘 / 房源。
- `H1` 使用公开房源标题；不得堆叠同义关键词。
- 标签最多显示 3 个，优先级为：租售类型、办公类型、经验证的房源亮点。
- “业主直租”“认证房源”“可注册”等标签必须映射可验证字段，不得从描述文本推断。
- 提供分享入口；收藏为 P1，未登录时可使用本地收藏，跨设备同步不在 P1 范围。
- 分享只使用 canonical URL，不附带个人筛选、手机号或活动中的个人标识。

### 4.2 分类媒体画廊

- 桌面首屏展示一张主图和 2–4 张拼图缩略图；移动端展示横向滑动主图。
- 媒体分类：办公区、会议室、公共区、楼盘外立面、平面图、视频。
- 分类顺序由后台公开媒体顺序决定，封面不得重复。
- 展示媒体总数和当前序号；平面图、视频有独立入口。
- 全屏画廊支持分类筛选、缩略图、左右键、Esc、触控滑动、焦点锁定和关闭后焦点归还。
- 视频默认静音且不自动播放，用户操作后才加载播放器。
- 平面图固定展示“示意图，以现场实际情况为准”。
- 单图失败使用同尺寸占位，不影响其他媒体；某分类全部失败时隐藏该分类。
- 图片必须具备公开 alt、宽高和响应式资源；不得以文件名代替 alt。

### 4.3 价格与核心参数

首屏必须展示：

| 字段 | 来源 | 展示规则 |
|---|---|---|
| 主价格 | `Listings.price` | 使用原始币种、周期和单位；缺失时显示“价格面议”，不得显示 0 |
| 参考换算价 | 由结构化价格计算 | 月总价、元/㎡/天等换算值标“约”，并可查看口径 |
| 建筑面积 | `Listings.area` | 使用 `㎡`，保留必要小数 |
| 工位 | 后台区间或建议工位 | 优先显示区间；估算值标“参考” |
| 装修 | `decorationStatus` | 使用统一字典 |
| 楼层 | `floor` | 展示本房源楼层；总楼层来自楼盘并明确区分 |
| 可入驻 | `availableFrom` | 已到日期显示“可立即入驻”，未来日期显示具体日期 |
| 所在楼盘 | `building` | 可点击进入楼盘详情 |
| 地址/地铁 | Building/Location | 行政区、商圈、地址和最近地铁分层展示 |
| 信息更新时间 | 核验/价格更新时间 | 显示“信息更新于 YYYY-MM-DD” |

### 4.4 决策卡与行动入口

- 桌面端右侧决策卡在滚动至相关推荐前保持粘性。
- 决策卡包含主价格、面积、工位、装修/楼层、更新时间和“询价 / 预约看房”。
- 移动端使用底部固定栏，显示价格摘要和主 CTA。
- 固定栏不得遮挡正文、系统手势区、隐私提示或表单错误。
- 平台公共电话可点击拨打；二维码只编码平台公共落地页或热线，不编码个人手机号。

## 5. 房源概况

### 5.1 字段清单

| 分组 | 字段 | 模型状态 |
|---|---|---|
| 面积 | 建筑面积、得房率、套内参考面积 | 面积已有；得房率需新增；套内面积为计算值 |
| 工位 | 最少/建议/最多工位 | 建议工位已有；区间需新增 |
| 空间 | 楼层、朝向、净层高、是否可分割 | 楼层已有；其余需新增 |
| 交付 | 装修、家具状态、可入驻日期 | 装修和日期已有；家具需新增 |
| 注册 | 可注册/条件注册/不可注册/待确认 | 需新增房源级状态；不得仅继承楼盘能力 |
| 租期 | 最短租期、付款方式、押金 | 最短租期和付款条件已有；押金需结构化 |
| 费用 | 物业费是否包含、税费/发票、其他固定费用 | 需新增 |
| 设备 | 空调类型/开放时间/加时、电、水、网络、车位 | 房源级字段需新增；楼盘公共能力可继承并标注 |

### 5.2 计算规则

- 套内参考面积 = 建筑面积 × 得房率；仅当两项均可信时计算并标“约”。
- 工位区间优先后台录入；缺失时可按已批准的人均面积规则估算，并标“参考”。
- 月度参考租金只在币种、面积、周期和单位足以计算时生成。
- 换算不得跨币种，不得把元/工位/月解释为元/㎡/天。
- 物业费、税费和其他费用必须拆分为“租金内含 / 另计 / 待确认”。

### 5.3 缺失策略

- 价格、面积、所属楼盘、租售类型、有效期、公开联系方式链路属于发布门槛，缺失时不得公开。
- 注册、费用、租期等决策关键字段缺失时显示“咨询确认”。
- 普通补充字段缺失时隐藏该行，不用大量“暂无数据”占据页面。
- 任何估算值必须显示“约”或“参考”，并提供可理解的计算口径。

## 6. 配套设施与房源描述

### 6.1 配套设施

- 房源级设施：家具、独立会议室、茶水间、独立卫生间、网络、空调控制、门禁等。
- 楼盘级设施：电梯、停车、公共会议空间、餐饮、商业等。
- 房源级事实优先于楼盘级继承项。
- 继承项明确标注“楼盘配套”，不得将公共设施表达为房内独享。
- 配套按办公服务、空间设施、楼宇配套、交通生活分类。

### 6.2 房源描述

- 按“空间与格局 / 装修与交付 / 适用团队 / 看房说明”组织。
- 支持结构化亮点和经审核富文本。
- 禁止出现私人手机号、微信号、外部引流二维码、内部审核信息。
- 禁止“最低价”“100%真实”“保证注册”“绝对免佣”等无证据承诺。
- 内容中的面积、价格、交通距离必须与结构化字段一致；冲突时阻止发布或进入复核。

## 7. 所在楼盘摘要

- 展示楼盘名称、等级/类型、地址、最近地铁、总建面、总楼层、物业公司和当前有效房源数。
- 展示楼盘封面或一张公开图，不混入其他具体房源图片。
- 提供“查看楼盘详情”和“查看楼内其他房源”。
- 楼盘字段缺失时只展示已验证内容，不用当前房源参数补齐楼盘参数。
- 楼盘不可公开时，本房源也不可公开。

## 8. 地图与周边信息（P1）

### 8.1 地图

- 使用所属楼盘坐标定位，不使用商圈中心点代替。
- 地图模块进入视口后再加载 SDK，不进入首屏关键链路。
- 默认不请求用户定位；仅在用户主动点击“查看到这里的路线”时请求。
- 地图失败时回退静态位置卡：地址、最近地铁、复制地址、打开第三方地图。

### 8.2 POI

- 分类：交通、餐饮、银行、酒店；交通再分地铁和公交。
- 每类默认展示最近 5 条，包含名称、距离和方向。
- 点击列表项时在地图高亮；移动端先定位列表，再按需展开地图。
- 数据来源和缓存更新时间必须可追踪。
- POI 不进入核心 SEO 结构化数据。

## 9. 推荐与继续比较

### 9.1 同楼盘其他房源

- 优先展示同楼盘、同租售类型且当前有效的房源。
- 排除当前房源；最多首屏展示 6 条。
- 卡片展示价格、面积、装修、楼层、工位、入驻时间和更新时间。
- 无结果时隐藏模块，不用历史房源补齐。

### 9.2 附近相似房源

- 推荐维度依次为：同商圈、同价格单位、相近面积、相同办公类型、相近预算。
- 标题使用中性文案“附近相似房源”。
- 推荐服务不可用时隐藏模块，不阻断主页面。
- 推荐点击记录推荐类型、排名和来源位置。

## 10. 咨询与预约看房

### 10.1 上下文

打开表单时自动携带：

`listingSlug + buildingSlug + priceSnapshot + pagePath + campaign + section + recommendationContext`

手机号、姓名和精确位置不得进入 URL、埋点或前端错误日志。

### 10.2 表单流程

1. 第一步：手机号、联系人称呼、公司/团队规模、隐私同意。
2. 第二步：意向日期、需求面积、预算、租售类型和备注，均为可选增强项。
3. 提交成功后展示需求摘要、联系预期和“继续看相似房源”。
4. “预约看房”只创建待顾问确认的需求，不承诺时段已锁定。

### 10.3 提交时失效

- 服务端在提交前重新校验房源有效性。
- 若房源刚失效，明确提示用户，并将意向降级为楼盘级需求。
- 不得创建指向失效房源的 `interestedListing`。
- 降级后保留用户已填需求，并记录 `stale_target_fallback`。

### 10.4 防刷与错误

- 使用 honeypot、IP/设备节流、重复提交去重和服务端字段白名单。
- 字段错误就地提示，焦点移到首个错误。
- 服务失败时保留用户已填的非敏感内容，提供重试和平台公共电话。
- 关闭表单后焦点返回触发按钮。

## 11. 页面状态

| 状态 | 页面表现 |
|---|---|
| 正常 | 展示当前公开版本和完整决策信息 |
| slug 不存在 | 品牌化 404 |
| 房源已失效 | 404；从推荐、楼盘聚合和 sitemap 同步撤销 |
| 楼盘不可公开 | 房源 404 |
| 价格面议 | 展示“价格面议”，隐藏无法成立的换算值 |
| 单张媒体失败 | 单图占位，其他媒体继续可用 |
| 全部媒体失败 | 若低于公开完整性门槛则不公开；否则显示品牌占位 |
| 地图/POI 失败 | 静态位置卡降级，不阻断咨询 |
| 推荐为空/失败 | 隐藏模块 |
| 咨询服务失败 | 保留输入、提示重试和公共联系方式 |
| 浏览中房源失效 | 表单提交时降级为楼盘需求；刷新后 404 |

## 12. 响应式与可访问性

- `≥1200px`：12 栏布局，媒体 7 栏、决策区 5 栏。
- `768–1199px`：单列主内容，决策卡转普通区块，保留锚点导航。
- `<768px`：单列、横滑画廊、底部固定 CTA。
- 320px 和 375px 无横向溢出；正文为固定栏和系统安全区预留空间。
- 锚点滚动扣除固定页头高度；浏览器前进后退恢复锚点位置。
- Tab、画廊、弹窗、折叠区和 CTA 均可键盘操作。
- 焦点顺序与视觉顺序一致；交互后有明确状态反馈。
- 遵循 `prefers-reduced-motion`，核心内容满足 WCAG 2.1 AA。

## 13. 数据与公开规则

- 按 slug 查询后必须在响应时再次通过统一有效供给服务。
- 页面读取当前发布版本，不读取审核中的工作版本。
- 页面、推荐、咨询目标和 sitemap 使用同一有效供给谓词。
- 公开 DTO 不包含审核原因、举报状态、商户资质、内部电话、内部坐标精度或工作版本。
- 房源媒体与楼盘媒体分别维护，禁止无来源混用。
- 信息核验时间和价格更新时间超过运营阈值时进入复核或下架。
- 富文本、标题、alt 和 JSON-LD 必须安全处理，防止存储型 XSS。

## 14. SEO 与分享

- canonical 为 `/listings/[slug]`。
- 画廊分类、锚点、咨询状态和来源参数不生成独立 canonical。
- metadata 优先使用后台 SEO；缺失时由房源标题、楼盘、区域、面积和类型安全生成。
- JSON-LD 使用 `Product + Offer`；价格可信时才输出 Offer。
- 不声明无法保证的库存、评分、作者、经纪人或开售时间。
- 输出 `BreadcrumbList`。
- OG 图优先公开封面；平面图、视频截图和带个人联系方式水印的图片不得作为默认图。
- 失效房源返回 404，并在失效窗口内从 sitemap 撤销。

## 15. 埋点与指标

### 15.1 漏斗

`listing_view → gallery_or_detail_engage → inquiry_open → inquiry_submit → inquiry_success`

### 15.2 事件

| 事件 | 关键属性 |
|---|---|
| `listing_view` | listingId、buildingId、租售类型、价格单位、信息完整度、asOf |
| `gallery_open` / `media_view` | 媒体分类、序号、页面类型 |
| `listing_building_click` | listingId、buildingId、section |
| `map_interaction` / `poi_click` | buildingId、POI 类别、距离区间 |
| `recommendation_click` | 当前房源、目标房源、推荐类型、排名 |
| `inquiry_open/submit/success/fail` | 目标实体、入口 section、campaign、失败码 |
| `stale_target_fallback` | 原房源、楼盘、发生阶段、降级结果 |

事件不得包含手机号、姓名、备注原文或精确用户位置。

## 16. 性能要求

- 移动端 75 分位：LCP ≤ 2.5 秒、CLS ≤ 0.1、INP ≤ 200 毫秒。
- 首屏只加载封面和必要缩略图；视频、地图、POI、相关推荐延迟加载。
- 图片提供尺寸、响应式 `srcset`、压缩格式和失败占位。
- 地图、分析等第三方脚本失败不得影响主内容和咨询。
- 房源状态变更使用实体级缓存失效，不得回退旧 `status=available` 查询。

## 17. 分期

| 阶段 | 范围 |
|---|---|
| P0 | 完整结构化字段、媒体分类、房源概况、楼盘摘要、咨询、有效性、响应式、SEO |
| P1 | 视频、平面图增强、地图与实时 POI、收藏/分享增强、信息纠错 |
| P2 | 路线规划、预约时段、顾问在线状态、个性化推荐 |

P1/P2 字段可提前建模，但对应模块不得阻塞 P0 上线。

## 18. 测试矩阵

1. 三种租金单位、出售总价、工位价和价格面议。
2. 得房率/工位区间/物业费/租期/付款/注册字段有值与缺失。
3. 实景图、平面图、视频分类；单图失败、分类为空、全媒体失败。
4. 地图正常、无坐标、SDK 失败、POI 超时、拒绝定位。
5. 访问前失效、浏览中失效、提交咨询瞬间失效。
6. 楼盘或区域停用导致详情、推荐和 sitemap 撤销。
7. 咨询成功、字段错误、限流、重复提交和服务失败。
8. 320/375/768/1024/1440px、键盘、触控、读屏和减少动效。
9. canonical、OG、JSON-LD、BreadcrumbList、404 和 sitemap。
10. 手机号不进入 URL、埋点、日志、地图请求或分享链接。

## 19. EARS 验收标准

- 当有效房源被访问时，系统应以同一公开版本展示原始价格单位、面积、交付条件、媒体、楼盘关系和核验时间。
- 当页面展示换算价格、套内面积、工位数或距离时，系统应标注“约/参考”并保留计算口径。
- 当价格单位为元/工位/月时，系统不得将其解释为元/㎡/天。
- 当房源不再满足任一有效供给条件时，系统应在失效窗口内从详情、楼盘数量、价格区间、列表、推荐和 sitemap 同步撤销。
- 当用户提交针对刚失效房源的咨询时，系统应明确告知变化并降级为楼盘需求，不得创建错误房源意向。
- 当地图或 POI 服务不可用时，系统应展示地址、地铁和外部导航降级，且咨询保持可用。
- 当用户使用键盘或读屏浏览时，画廊、锚点、弹窗和固定 CTA 应可理解、可操作并正确归还焦点。
- 当视口为 375px 时，核心字段与 CTA 应持续可达、无横向溢出且不被固定栏遮挡。
- 当页面生成 SEO 数据时，系统不得输出失效供给、未经验证的价格/评分或内部经纪人信息。
- 当分析、地图或错误请求发出时，系统不得携带手机号、姓名或精确用户位置。
- 当页面关键字段低于公开完整性门槛时，系统应阻止发布，而不是以前台“暂无数据”替代治理。

## 20. 非目标

- 公开完整业主、商户或经纪人私人联系方式。
- 在线签约、支付和合同履约。
- 历史价格走势和成交价承诺。
- 未经用户主动触发的定位追踪。
- 将顾问自由文本作为结构化事实。
- 在 P0 阶段提供实时顾问在线状态或已确认看房时段。
