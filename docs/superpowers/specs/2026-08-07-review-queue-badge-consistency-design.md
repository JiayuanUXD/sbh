# 审核队列角标一致性设计

## 背景

审核队列页面以 `listings.reviewStatus = pending` 展示当前待审核房源；侧栏角标却统计只追加的 `listing-reviews` 历史事件中 `taskStatus = pending/processing` 的记录。审核决定会新增一条已完成事件，但不会改写最初的提交事件，因此历史提交记录长期残留为 pending，造成角标显示 `99+` 而队列为空。

## 决策

侧栏角标改为统计 `listings` Collection 中 `reviewStatus = pending` 的当前状态，并继续使用队列相同的 `building.city` 城市权限条件。队列和角标因此共享同一业务实体、状态字段与权限路径。

不修改或删除 `listing-reviews` 历史记录，不增加迁移，不改变审核状态机、审核队列页面或 `99+` 的展示上限。

## 验收

- 当前没有待审核房源时，审核队列为空且侧栏不显示角标。
- 有待审核房源时，角标数量与用户城市权限范围内的队列数量一致。
- 已完成房源对应的历史提交事件不再计入角标。
- 现有权限失败隔离和其他导航角标行为不变。
