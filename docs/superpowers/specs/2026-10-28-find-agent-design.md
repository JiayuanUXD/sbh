# 设计：网站内嵌对话找房 Agent（首期）

日期：2026-10-28  
仓库：`JiayuanUXD/sbh`（线上 [shangban.cc](https://shangban.cc)）  
状态：草案，待实现计划

## 背景与目标

为 C 端用户提供网站内嵌对话，通过自然语言澄清需求后推荐可点进详情的房源卡片。对标现有筛选找房体验，不替代列表/详情主流程。

### 已确认决策

| 项 | 决策 |
| --- | --- |
| 入口 | `shangban.cc` 全站悬浮对话窗 |
| 成功标准 | 推荐 3～6 张房源卡，可点进详情；可附「打开列表页」链接 |
| 找房方式 | 先聊清意图，再落到现有结构化筛选出卡（方案 A） |
| 轻量增强 | 商圈/地铁/楼盘俗称小词表映射（掺一点 B），不做全量向量库 |
| 明确不做（首期） | 代提交咨询、预约看房、全库 embedding、后台运营助手、跨设备账号 |

## 架构

```
[悬浮 Chat UI]
      │  POST /api/find-agent（会话 + 用户消息）
      ▼
[编排层]
  ├─ 会话态（已填槽位）
  ├─ LLM（理解 / 澄清 / 决定是否调用工具）
  ├─ 别名词表解析
  └─ searchListings(filters) ──► public-catalog / 有效供给（与 C 端同源）
      │
      ▼
[响应] 文本气泡 + ListingCard DTO[] + 可选 listUrl
```

- 前端：轻量 Chat UI；消息流嵌房源卡；视觉复用现有 Apple 中性 token（`(frontend)/styles.css`），不另起设计体系。
- 后端：服务端编排；LLM API 密钥仅服务端；工具调用强制结构化参数。
- 检索：禁止第二套 where / 简化 `status=available`；必须走与列表页相同的有效供给与计价单位语义。
- 列表 URL：用当前槽位生成与列表页一致的 query（URL 仍是筛选事实源），方便「打开完整列表」。

## 对话与槽位

### 槽位（首期）

| 槽位 | 必填 | 说明 |
| --- | --- | --- |
| 城市 | 是 | 缺则先问 |
| 区域 / 商圈 / 地铁 | 否 | 经别名词表解析到 geography |
| 面积区间 | 否 | 与现网面积筛选一致 |
| 租金 + 计价单位 | 条件必填 | 有租金意向时必须带 `priceUnit`（12 值体系，与列表页一致）；单位不明必须追问 |
| 工位数 / 人数 | 否 | |
| 物业类型 | 否 | |

规则：一次只追问 1～2 个缺失关键槽；不连环审讯。

### 检索工具 `searchListings`

- 入参：规范化 filters（城市、geography、面积、priceUnit + 区间、类型等）。
- 出参：最多 3～6 张卡；总数；可选 `listUrl`。
- 0 结果：主动放宽一项（优先放宽面积或租金边界），并在文案中说明放宽了什么。
- 结果过多：出卡 + 「打开完整列表」。

### 别名词表（轻量 B）

- 覆盖：商圈俗称、地铁站简称、楼盘常见叫法 → 正式 geography / building id。
- 存放：配置文件或 Payload 可编辑字段（实现阶段二选一，优先可运营维护）。
- 解析失败：反问「你是指某某吗」，不猜测写入错误筛选。

### 卡片 DTO（只读）

封面、楼盘名、关键价位（必须带单位）、面积、商圈、详情 URL。  
禁止在对话中编造库存或价格；字段一律来自 public-catalog DTO。

### 会话

短会话（cookie / session），刷新可续；不做跨设备登录态。会话长度与轮次设上限。

## 界面

- 全站悬浮球 → 展开面板；桌面右下，移动端不挡主导航。
- 气泡 + 房源卡 + 底部输入 + 「清空对话」。
- 列表页可有弱提示「也可以对话找房」，不打断筛选主流程。
- 卡片点击进入现有详情路由。

## 模型与降级

- 国内 LLM API 优先；温度偏低；工具参数 JSON schema 校验失败则重试或降级。
- 降级路径：无法可靠检索时，生成合法筛选列表 URL，引导用户去列表页；**不得**伪造房源卡。
- 提示词约束：不承诺「一定有房」「全网最低价」；不确定就澄清。

## 安全与边界

- 只读公开供给；不访问后台私有 collection / 权限数据。
- 不代提交 `/api/inquiries`（留作二期）。
- 接口限流；防提示词注入导致越权工具调用（工具白名单仅检索与别名解析）。
- 日志：匿名记录槽位、工具入参、结果数、点卡 / 点列表，便于调优；不落用户隐私文本到长期存储时需脱敏策略（实现计划细化）。

## 验收标准

1. 给定口语需求（含城市 + 面积或租金），在合理轮次内产出真实房源卡或合法澄清问题。
2. 用户只说租金数字不说单位时，必须追问计价单位，不得静默套默认单位出卡。
3. 有效供给为 0 时，必须说明并尝试放宽，不能空回复或编造。
4. 卡片详情链接可打开且价格/面积与详情页一致（同源 DTO）。
5. LLM / 上游失败时降级为列表链接，页面不崩溃。
