# 后台导航信息架构与功能分类优化设计

日期：2026-07-28

状态：已通过方案确认，待写实现计划

关联基线：[`../../prd/后台管理系统_MVP_页面PRD/README.md`](../../prd/后台管理系统_MVP_页面PRD/README.md)

## 1. 背景

当前后台导航主要由 Payload Collection 自动生成。除“账号与权限”“workflow”“system”外，大部分业务功能集中在“集合”分组中，造成以下问题：

- 房源、客户、组织、内容和配置等不同业务对象混排；
- 日常任务与系统记录处于相同导航层级；
- `workflow`、`system` 使用技术名称，与中文业务语境不一致；
- 桌面端和移动端均形成过长的平铺列表；
- “线索归属历史、搜索索引、领域事件、审计日志”等低频或技术功能占用日常导航空间；
- 用户需要先理解数据集合，才能判断应进入哪个功能。

本设计从产品信息架构和用户任务出发重构导航。目标不是减少功能，而是让用户按业务职责和工作任务找到功能。

## 2. 目标与非目标

### 2.1 目标

- 使用明确的中文业务名称替代技术集合名称；
- 将导航重组为职责单一、边界清晰的业务分组；
- 高频任务前置，低频配置收拢，技术功能降级；
- 不同角色只看到有权限且有实际用途的分组；
- 通过待办数量和快捷入口减少跨页面查找；
- 桌面端和移动端使用一致的信息架构；
- 导航可随业务增长扩展，不依赖继续堆叠一级入口。

### 2.2 非目标

- 不改变现有业务对象、状态机或数据权限定义；
- 不新增合同、结算、财务、开放平台等业务模块；
- 不在本期重构各 Collection 的详情页和表单；
- 不用前端隐藏替代后端权限校验；
- 不删除搜索索引、领域事件、审计日志或历史数据。

## 3. 设计原则

1. **按用户职责分类**：一级分组使用房源运营、客户运营等业务语言。
2. **按任务频率排序**：工作台和核心业务优先，系统管理置底。
3. **一个入口一个主目的**：避免“合作方与组织”“内容与获客”等语义过宽的组合。
4. **记录依附业务对象**：归属历史等记录从主导航降级到相关详情页。
5. **技术能力退出日常导航**：索引、事件、审计进入高级工具。
6. **权限决定可见性**：无可访问子项的分组整体隐藏。
7. **渐进披露**：默认只展开当前分组，基础配置和高级工具按需展开。
8. **不制造空分组**：单一功能也可拥有边界清晰的业务分组，后续按真实需求扩展。

## 4. 目标信息架构

一级分组顺序固定为：

1. 工作台
2. 房源运营
3. 审核与风控
4. 客户运营
5. 商户合作
6. 团队管理
7. 内容管理
8. 表单中心
9. 系统管理

完整层级如下：

```text
工作台
├─ 运营概览
├─ 我的待办
└─ 消息通知

房源运营
├─ 房源列表
├─ 楼盘库
└─ 基础配置
   ├─ 行政区域
   ├─ 商圈管理
   └─ 配套字典

审核与风控
├─ 审核队列
└─ 举报处理

客户运营
├─ 咨询线索
├─ 客户档案
└─ 跟进记录

商户合作
└─ 商户管理

团队管理
├─ 团队管理

├─ 用户管理

```

## 6. 分组功能设计

### 6.1 工作台

工作台承接跨业务任务，不复制完整业务列表。

- 运营概览展示角色相关指标；
- 我的待办只统计未完成且分配给当前用户的任务；
- 消息通知只统计当前用户未读通知；
- 提供“新增房源、查看线索、进入审核队列”等权限内快捷操作；
- 不同角色进入后台时获得不同的工作台内容，但使用同一路由和组件框架。

### 6.2 房源运营

- 房源列表是第一入口，楼盘库是第二入口；
- 行政区域、商圈管理、配套字典统一收进“基础配置”；
- 基础配置默认折叠；
- 房源和楼盘编辑页可直接选择素材，不要求先进入素材库。

### 6.3 审核与风控

- 审核队列默认按待处理优先、提交时间倒序；
- 举报处理默认按风险等级和提交时间排序；
- 已完成记录通过筛选查看，不增加额外导航；
- 菜单数量仅统计当前用户有权处理的记录。

### 6.4 客户运营

- 咨询线索、客户档案、跟进记录形成连续业务路径；
- 在线索详情中直接创建跟进、调整负责人或转为客户；
- 线索归属历史改为详情页“归属记录”，不保留独立主导航。

### 6.5 商户合作

- MVP 仅保留商户管理；
- 未来只有在合同、资质复核、供给关系等形成独立高频任务后才增加子项；
- 不提前创建空入口。

### 6.6 团队管理

- 团队详情直接展示和管理成员；
- 经纪人管理用于跨团队查询和独立人员维护；
- 不再新增与经纪人列表重复的“团队成员”主菜单。

### 6.7 内容管理

- 页面内容负责前台页面编辑；
- 素材库负责批量整理、查询和维护共享媒体；
- 房源、楼盘和页面编辑器可直接调用素材选择器；
- 素材库是共享能力，不归入单一房源对象。

### 6.8 表单中心

- 表单详情显示近期提交数量和数据入口；
- 提交数据提供跨表单筛选、查看和导出；
- “获客”不作为分组名称，避免与客户运营语义重叠。

### 6.9 系统管理

- 用户管理和角色管理是常规系统入口；
- 高级工具仅向具备对应权限的管理员显示；
- 搜索索引和领域事件主要用于诊断；
- 审计日志保持只读；
- 高级工具默认折叠并置于导航末端。

## 7. 导航交互

### 7.1 桌面端

- 工作台固定在导航顶部；
- 业务分组采用单组展开的手风琴模式；
- 打开一个分组时收起其他业务分组；
- 当前页面所属分组自动展开并高亮；
- 刷新后根据当前路由恢复展开状态，不记忆多个展开组；
- 系统管理默认折叠；
- 导航主体独立滚动，账号入口固定在底部；
- 无可访问子项的分组不渲染；
- 展开或收起不能改变当前路由。

### 7.2 移动端

- 使用全屏抽屉，不使用超长平铺列表；
- 工作台、我的待办、消息通知置顶；
- 业务分组使用折叠面板，一次只展开一组；
- 点击菜单后自动关闭抽屉；
- 系统管理和高级工具置底；
- 数量提醒保留，辅助说明省略；
- 返回按钮与关闭菜单按钮使用不同图标和语义。

### 7.3 状态

导航需覆盖：

- 默认、悬停、选中、禁用和加载状态；
- 分组展开与收起状态；
- 数量为 0、1–99、99+ 的提醒状态；
- 当前路由无权访问时的拒绝状态；
- 菜单数据加载失败时保留当前路由，并显示非阻断错误反馈。

## 8. 角色与默认入口

| 角色 | 默认首页内容 | 默认可见的主要分组 |
|---|---|---|
| ADM 平台管理员 | 平台运营概览 | 全部分组 |
| OPS 运营人员 | 待审核房源与举报处理 | 工作台、房源运营、审核与风控、商户合作、内容管理、表单中心 |
| MGR 销售主管 | 团队线索与跟进情况 | 工作台、房源运营、客户运营、团队管理 |
| BRK 经纪人 | 我的待办与我的客户 | 工作台、房源运营、客户运营 |
| CSR 客服 | 新咨询线索与未处理表单 | 工作台、客户运营、表单中心 |

该表是默认信息架构，不替代现有权限集合。最终可见性必须由用户角色的菜单权限、操作权限和 Collection `read` 权限共同决定。

## 9. 数量提醒

仅需要用户采取行动的入口显示数量：

| 菜单 | 统计口径 |
|---|---|
| 我的待办 | 未完成且分配给当前用户 |
| 消息通知 | 当前用户未读 |
| 审核队列 | 当前用户权限范围内待审核 |
| 举报处理 | 当前用户权限范围内待处理 |
| 咨询线索 | 新线索或超过跟进时限的线索 |
| 提交数据 | 尚未处理的新提交 |

统一规则：

- 数量为 0 时不显示；
- 1–99 显示实际数字；
- 超过 99 显示 `99+`；
- 普通待办使用品牌色，逾期或举报风险使用警示色；
- 数量统计必须应用与目标列表相同的权限和数据范围；
- 提醒失败不能阻止菜单渲染；
- 数量变化不自动改变菜单排序，避免导航跳动。

## 10. 权限与安全

- 前端菜单隐藏仅用于降低认知负担；
- 后端 Collection 和 endpoint 权限继续作为最终边界；
- 用户不能通过直接输入 URL 访问无权页面；
- 数量接口不能泄露无权限数据总量；
- 高级工具必须分别校验搜索、事件和审计权限；
- 审计日志不可通过导航改造获得创建、修改或删除能力；
- 角色切换或权限变更后，重新登录或刷新权限上下文才能生效。

## 11. 实施边界

实现阶段预计涉及：

- 自定义 Payload Admin 导航组件；
- Collection 分组名称和展示名称调整；
- 菜单配置模型与角色权限映射；
- 导航数量聚合接口；
- 工作台角色化入口；
- 线索详情中的归属记录入口；
- 表单详情中的提交数据入口；
- 桌面端与移动端响应式导航。

不应通过修改数据库表名或 Collection slug 完成菜单改名。稳定 slug、API 路径和既有数据关系保持不变，仅调整展示层配置和导航组件。

## 12. 验收标准

### 12.1 信息架构

- 一级分组名称、顺序和子项与第 4 节一致；
- 不再出现“集合”“workflow”“system”等技术分组名；
- 线索归属历史不再占用主导航；
- 搜索索引、领域事件、审计日志仅在高级工具中出现；
- 素材库、提交数据、审核队列、举报处理使用目标名称。

### 12.2 权限

- ADM 可见全部九个分组；
- OPS、MGR、BRK、CSR 仅看见权限内分组；
- 分组无可访问子项时整体隐藏；
- 直接访问无权 URL 仍被后端拒绝；
- 数量提醒不包含无权限数据。

### 12.3 交互

- 桌面端一次只展开一个业务分组；
- 当前路由所属分组始终展开并高亮；
- 移动端点击菜单后抽屉关闭；
- 系统管理默认折叠并置底；
- 刷新页面后导航定位正确；
- 0、1、99、100 条提醒分别符合隐藏、实际数字和 `99+` 规则。

### 12.4 回归

- 所有现有 Collection 仍可通过目标入口访问；
- Collection slug、REST API 和数据关系不变；
- 后台登录、退出和账号入口不受影响；
- 现有工作台、房源、审核、线索和权限测试通过；
- 桌面端和移动端均不存在无法滚动或菜单被遮挡问题。

## 13. 推进顺序

1. 建立菜单配置和旧名称到新名称的映射；
2. 完成桌面端导航分组和权限过滤；
3. 完成移动端折叠菜单；
4. 迁移低频入口和详情页关联入口；
5. 接入数量提醒；
6. 完成角色矩阵与直接 URL 权限回归；
7. 逐角色灰度验证后发布。

## 14. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 菜单分组改名导致老用户找不到入口 | 首次上线提供简短的新导航说明；保留稳定 URL |
| Payload 默认导航能力不足以支持三级结构 | 使用自定义 Admin Nav，菜单配置与 Collection 定义解耦 |
| 前端菜单权限与后端权限不一致 | 菜单配置只决定展示，最终可见性同时检查后端 `read` 权限 |
| 数量聚合增加请求和数据库压力 | 合并为单个轻量聚合接口，按用户和短时间窗口缓存 |
| 角色权限变化后旧会话仍显示旧菜单 | 权限变更后刷新权限上下文，必要时要求重新登录 |
| 九个一级分组仍显得较多 | 单组展开、无权限分组隐藏、系统管理置底，控制同时可见条目 |
