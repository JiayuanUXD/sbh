# MP-109 小程序真实闭环与交互抽屉修复设计

## 1. 背景与目标

MP-106/107 与后续 UI 细节提交已经形成首页、找房、楼盘、详情和“我的”页面，但审查确认存在三类根本问题：一是多个咨询入口只显示成功提示而未创建服务端 Lead；二是收藏与咨询记录只保存在本机，不能满足登录后跨会话一致；三是 UI 优化只覆盖静态页面，筛选/咨询抽屉仍沿用旧结构，且筛选抽屉的父子属性已被错误重命名。

MP-109 的目标是在不进入正式发布 MP-108 范围的前提下，把这些页面收束成可信、可测试的纵向闭环：所有成功状态来自服务端；用户资产绑定稳定 Mini session subject；楼盘与首页数据来自真实 DTO；筛选与咨询抽屉必须在真实打开态完成视觉、交互和可访问性验收。

## 2. 方案比较与选择

### 方案 A：仅修补文案和抽屉样式

改动最小，但咨询仍可能丢失、收藏仍不能跨设备、验收仍可能假绿。该方案只能改善截图，不能完成 MP-107，拒绝采用。

### 方案 B：复用现有 session/咨询链，新增最小用户资产门面

使用现有由 openid 派生的稳定、不可逆 `subject` 作为归属键；新增私有用户资产集合和 Mini 专用读写路由；扩展既有咨询合同以支持房源、楼盘和通用需求；统一抽屉结构并补真实父子合同与自动化几何断言。该方案改动可控、没有第二套身份系统，采用此方案。

### 方案 C：完整微信用户账户体系

新增用户资料、授权头像昵称、账户设置与运营后台。范围和隐私成本显著超出当前 MVP，留到正式账户体系，不纳入 MP-109。

## 3. 系统边界

- 继续使用原生微信小程序、Next.js Mini API、Payload 与 PostgreSQL。
- 不修改生产环境、不执行生产迁移、不发布正式版。
- Mini session 仍由 `wx.login` 换取，token 保持短期；同一 openid 每次登录生成相同稳定 subject。
- 小程序不展示或存储 openid；服务端集合只保存不可逆 subject。
- 新增数据库结构只通过 `payload migrate:create` 生成迁移，迁移正文不得手改。
- MP-108 保留为上线加固与正式发布；本次使用独立编号 MP-109。

## 4. 用户资产模型

新增内部集合 `mini-user-assets`，所有公共 access 均为拒绝，只允许 Mini API 使用 `overrideAccess` 访问。

每条资产包含：

- `assetKey`：服务端计算的 SHA-256 唯一键，输入为 subject、kind 与目标标识；客户端不能提供。
- `subject`：Mini session 的稳定不可逆归属键，建立索引。
- `kind`：`favorite-listing`、`favorite-building` 或 `inquiry`。
- `targetType`：`listing`、`building` 或 `general`。
- `targetSlug`：房源/楼盘 slug；通用需求为空。
- `lead`：仅 inquiry 记录引用对应 Lead；收藏为空。
- Payload 自带 `createdAt/updatedAt`。

收藏写入使用唯一 `assetKey` 实现幂等；取消收藏只删除当前 subject 对应的精确资产。咨询成功后写入 inquiry link；如果 Lead 已创建但 link 写入失败，请求返回可重试错误，同一 submission 重试时必须修复 link，不得创建第二条 Lead。

## 5. Mini API

### 5.1 身份规则

除受保护的 staging acceptance 路径外，咨询 POST、用户资产 GET、收藏 PUT/DELETE 均必须携带有效 Bearer session。缺失、过期或签名错误统一返回 `401 session_invalid`。

### 5.2 咨询目标合同

咨询输入使用显式联合类型：

- `targetType=listing`：必须有 `listingSlug`，可附所属 `buildingSlug`。
- `targetType=building`：必须有 `buildingSlug`，不得伪造 listingSlug。
- `targetType=general`：不得携带目标 slug。

三种目标都复用现有手机号授权、手填手机号、隐私同意、幂等键和失败码。服务端只在真实写入或幂等命中后返回成功。

### 5.3 “我的”读取门面

新增 `GET /api/mini/v1/me`，返回严格白名单：

- 收藏房源/楼盘的当前有效公开卡片；失效目标不继续展示为可用供给。
- 咨询目标标题、目标类型、目标 slug、提交时间、对用户安全的状态标签。
- 收藏/咨询数量。

禁止返回手机号、openid、内部备注、经纪人内部信息、idempotencyKey、Lead ID、审计字段或后台权限信息。状态只从 Lead 的真实阶段/状态派生；没有实际分配时不得显示“顾问已分配”。

### 5.4 收藏门面

新增 `PUT /api/mini/v1/favorites` 与 `DELETE /api/mini/v1/favorites`。请求只接受 `targetType` 与 `targetSlug`，服务端先通过有效公开供给验证目标，再创建或精确删除资产。

## 6. Mini API 楼盘与首页修复

- 楼盘 grade 使用真实公开枚举及明确中文展示映射，不用类型断言伪装为 A/B/C。
- 地铁信息没有线路或距离时返回 `null`，绝不把未知值写成 `0`。
- 楼盘详情从公共 fact groups 映射竣工时间、楼层、标准层、电梯、车位、物业公司和物业费。
- 未知面积不进入任一面积段。
- 分页元数据与公共查询实际 pageSize 保持一致；`keyword`、竣工年份和翻页要么完整实现，要么不进入公开合同。
- 首页 `featuredBuildings` 从真实首页 DTO 映射并由小程序消费；删除硬编码楼盘、套数、价格与不可验证的“实时/逐条实勘”文案。

## 7. 找房搜索与排序

- 搜索只写入领域字段 `q`，WXML、页面状态、URL 和服务端解析保持同名。
- 价格排序必须在已选择 `priceUnit` 时启用；无单位时 UI 显示“推荐排序”，不得静默显示升降序后又被领域层还原。
- 父页传给筛选抽屉的属性固定为 `section`、`query`、`result-count`；增加跨文件合同测试防止再次漂移。

## 8. 抽屉交互与视觉规范

筛选与咨询抽屉共享以下视觉和行为规则，但保留独立业务控制器：

- 遮罩覆盖整个可交互页面；筛选抽屉打开时隐藏原生 TabBar，关闭、页面卸载和失败时恢复。
- 页面背景锁滚动，面板内部使用独立纵向滚动；点击面板不穿透，点击遮罩关闭，提交/授权中禁止关闭。
- 面板顶部使用 64rpx 拖拽把手视觉、88rpx 以上标题栏、44pt 关闭命中区；关闭按钮使用中性图标/文字，不与主 CTA 竞争。
- 面板为白色，上圆角 24rpx；遮罩使用独立半透明黑色 Token；只保留蓝色主交互色，不使用红色收藏或彩色 emoji 作为产品图标。
- 筛选抽屉最大高度为可视区减去状态/导航安全距离，底部操作栏固定在面板内并包含安全区；清除为次操作，结果数 CTA 为唯一主操作。
- 咨询抽屉压缩供给摘要，手机号方式使用分段选择；主提交按钮固定在面板底部，表单滚动时始终可见。成功态只展示服务端结果和真实后续说明。
- 输入聚焦时依赖 `adjust-position`、面板内部滚动与底部安全区，不能让键盘遮挡当前输入或提交按钮。
- 进入动画仅使用 160ms–200ms 的 opacity/translateY；尊重小程序性能边界，不使用长动画或弹跳。

## 9. 页面行为修复

- 首页委托、楼盘详情、暂无在租楼盘均打开真实咨询抽屉，不再直接 toast 成功。
- “我的”点击收藏进入带服务端收藏集合的结果，不进入未筛选的全部列表。
- 咨询记录按 `targetType` 导航到房源详情、楼盘详情；通用需求不伪造详情页。
- 用户身份区只显示“微信用户/已连接当前微信”，不得声称完成头像昵称授权。
- 暂未实现的地图和对比入口从 MVP 主界面移除，不用“即将开放”占据主交互位置。

## 10. 验收与证据

### 自动化门禁

- runner 对关键 selector 缺失、任何 `passed=false`、请求未发生、响应失败或重载后状态不一致都必须退出 1。
- Mock UI 验收与 staging 验收分目录、分报告；Mock 报告不得使用“全链路真实通过”。
- MP-107 不再调用 `addSampleInquiryForDemo`；测试必须通过真实页面提交方法和受控 API mock 生成记录。
- mapper 测试必须调用真实 mapper，不允许用理想 DTO mock 掉被测服务层。

### 抽屉证据

至少归档以下稳定截图与断言：

1. 价格筛选抽屉：只显示价格相关分区，继承当前 query，结果数不为硬编码 0，TabBar 不可见。
2. 全部筛选抽屉：内部可滚动，footer 固定，遮罩关闭后 TabBar 恢复。
3. 咨询抽屉：微信手机号模式、手填模式、键盘打开态、隐私错误态、提交中、成功态。
4. 小屏与大屏：无横向裁切、无状态栏残影、关闭与主 CTA 命中区不小于 44pt。

### 完成定义

MP-109 只有在代码、迁移、相关测试、Node 22 全量回归、构建、DevTools 打开态截图、runner fail-closed 自测和独立代码审查全部通过后才可标记代码完成。真实 staging 数据写入、iOS/Android、隐私后台和正式体验版仍受 MP-105/108 环境门控制，未执行时必须明确记录为环境验收待完成。
