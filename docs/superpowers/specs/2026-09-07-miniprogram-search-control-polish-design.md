# 小程序首页搜索控件视觉修复设计

> 状态：已获用户确认（方案 A）
> 日期：2026-09-07
> 范围：仅首页搜索控件视觉与对应验收，不修改搜索数据、路由或 API

## 1. 问题与根因

首页蓝色搜索按钮内的放大镜由两个独立节点绘制。圆环固定在 `32rpx` 容器左上角，手柄固定在右下角，两者没有共享连接点；在微信渲染比例和抗锯齿取整后，手柄与圆环之间出现明显断口。搜索条外层当前使用 `12rpx` 控件圆角，视觉仍接近矩形，与用户要求的圆角搜索条不符。

## 2. 已确认方案

- 搜索条保持现有 `104rpx` 高度、内容顺序、阴影和页面位置，圆角改为 `999rpx` 胶囊形。
- 蓝色提交按钮保持 `80rpx × 80rpx` 和现有主交互蓝色，圆角改为 `999rpx`，形成圆形按钮。
- 放大镜继续使用 CSS 绘制，不依赖字体、emoji、远程图片或平台图标。
- 圆环与手柄在同一个 `32rpx × 32rpx` 坐标系中使用显式 `top/left` 定位；手柄起点与圆环右下边缘重叠，避免像素取整后断裂。
- 圆环固定 `left: 2rpx; top: 2rpx; width: 22rpx; height: 22rpx; border: 4rpx solid #ffffff`，手柄固定 `left: 20rpx; top: 18rpx; width: 12rpx; height: 4rpx; transform: rotate(45deg); transform-origin: left center`。手柄旋转原点 `(20, 20)` 与圆环外缘重叠。原实施坐标 `top: 22rpx` 虽通过初版静态合同，但 375/430 两档截图仍显示间隙，已按视觉验收修正。
- 保留 `aria-role="button"`、`aria-label="提交搜索"`，保持现有 `80rpx × 80rpx` 命中区和现有按压反馈。

## 3. 非目标

- 不改变“当前城市 · 上海”、搜索占位文案或关键词合同。
- 不修改 `handleSearchSubmit`、列表页搜索条、搜索 API 或结果排序。
- 不引入新的图片资源、图标库或第三方 UI 依赖。

## 4. 验收

- 合同测试先证明旧样式没有胶囊搜索条、圆形按钮和相连图标坐标，再由最小样式修改转绿。
- Node 22 下运行首页合同测试、小程序全量测试、双 TypeScript 和 `project:check`。
- 在微信开发者工具重新生成 375 与 430 两档 MP-109 证据；检查首页咨询截图中的搜索控件没有图标断裂、裁切或圆角异常。
- 由于桌面开发者工具仍无法证明软键盘避让，若环境事实未变化，报告继续保持 `incomplete`，不得伪造全绿。
