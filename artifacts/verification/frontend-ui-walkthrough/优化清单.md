## P0 — 阻断，用户直接撞墙

### P0-1 首页「资讯」区 6 个链接全部 404（生产同样存在）

- **现象**：首页资讯区块的「更多资讯 →」和 5 条文章标题指向 `/shanghai/news`、`/shanghai/news/<slug>`，这两类路由在 `src/app/(frontend)/[city]/` 下**不存在**，全部 404。
- **证据**：本地与生产 `curl` 均返回 404；生产首页 HTML 里确实渲染了 `href="/shanghai/news"`、`href="/shanghai/news/chooffice-1090"` 等。
- **根因**：[HomeNewsList.tsx:31](payload-office-platform/src/components/frontend/home/HomeNewsList.tsx:31) 与 [:38](payload-office-platform/src/components/frontend/home/HomeNewsList.tsx:38) 手拼 `${prefix}/news`，绕过了 `city-routes.ts`——后者对 `news` / `news-detail` 正确返回不带城市前缀的 `/news`。
- **建议**：改用 `city-routes` 的路径构造（唯一事实源），并补一条断言"首页所有链接可达"的 E2E。

### P0-2 房源详情「房源概况」8 行参数值被右侧决策卡遮住

- **现象**：桌面端滚到规格表时，**「面积与格局」整组的值不可见**——建筑面积、套内参考面积、得房率、净层高、工位估算、房源楼层、朝向、可分割。用户看到的是"只有标签、没有数字"的空表。22 行里 8 行受影响，随滚动位置移动。
- **影响范围（第二轮补测）**：`.dt-core` 在 ≤1023 塌成单列，所以**≥1024 的所有宽度都命中**——1024 / 1440 / 1920 逐个复现，不是 1440 独有。移动端与平板（≤1023）不受影响。
- **证据**：1440×900 下 `elementFromPoint(值的右端)` 命中 `DIV.dt-panel dt-panel--side` / `SECTION.advisor-card` 而非值本身；两次独立复现（含全新加载）。第二轮逐滚动步扫描在 d1024 上再次命中 12 处（`round2/audit2.json` → `coveredText`）。截图 `shots/listing-detail-desktop.png` 对应区域。
- **根因**：[detail.css:147](payload-office-platform/src/app/(frontend)/styles/detail.css:147) `.dt-overview-block { grid-column: 1 / -1 }` 让概况块横跨两列，行宽 1264px 一直铺到侧栏轨道下方；而 [detail.css:387](payload-office-platform/src/app/(frontend)/styles/detail.css:387) `.dt-decision` 是 `position: sticky`，在整个第 1 行 grid area 内都吸附。两者在竖直方向重叠时，右对齐的值就被压住。
- **建议**：概况块收进主栏（`grid-column: 1`）。**顺带把它切成两列一起改**——见 P2-14，同一处代码可以同时解决遮挡、空间浪费、与楼盘详情不一致三件事。移动端单列不受影响。
- **待确认**：生产域名有腾讯云「页面访问提示」拦截页，未点确认（需要用户授权），生产端未目视复核。

### P0-3 移动端菜单打开后「关闭菜单」按钮点不到

- **现象**：点汉堡打开抽屉后，右上角按钮切换成 `aria-label="关闭菜单"`，但它被抽屉面板盖住——抽屉从 x=56 铺到 x=375，按钮在 x=315~359。抽屉内部**没有任何关闭按钮**。唯一出路是点左侧 56px 宽的遮罩。
- **证据**：`elementFromPoint(按钮中心)` 返回 `DIV.mobile-drawer`；`drawer.querySelectorAll('button').length === 0`；遮罩点击可关闭。
- **建议**：抽屉内加显式关闭按钮，或把关闭按钮的 z-index 提到抽屉之上。

## P1 — 严重体验缺陷

### P1-1 前台没有 `not-found.tsx`，无效 URL 掉出站外（生产同样存在）

任何拼错的城市 / 失效的收藏链接都落到 Next.js 默认 404：英文「This page could not be found」、无页头页脚、无搜索或回首页的出口，而且它自带 `prefers-color-scheme: dark`——深色系统用户会看到一个黑底英文页，与站内白底中文完全割裂。生产 `curl` 已确认。
**建议**：新增 `src/app/(frontend)/not-found.tsx`，套站内壳 + 搜索框 + 热门商圈/房源入口。

### P1-2 委托找房 / 投放房源不跟随城市，页面自相矛盾

`/entrust?city=hangzhou` 上：头部城市切换器显示「杭州」、页脚 tagline 显示「聚合**杭州**甲级写字楼…」、表单城市选「杭州」，但 hero 品牌胶囊仍写死「**上海**中高端办公租赁平台」。`/publish` 同样。
**根因**：[landing-config.ts:9](payload-office-platform/src/lib/frontend/landing-config.ts:9) `BRAND_BADGE = '上海中高端办公租赁平台'` 是常量。7 个城市（上海/杭州/宁波/苏州/南京/嘉兴/无锡）都会命中。
**建议**：改为按 citySlug 取城市名的函数，和页脚 tagline 走同一套。

### P1-3 全站次要文字色对比度不达 WCAG AA

`#86868b` 在白底 **3.62:1**、在 `#f5f5f7` 灰底 **3.33:1**，都低于正文要求的 4.5:1。命中范围极广（按出现页数排序）：面包屑链接、页脚 tagline、卡片位置/面积、文章摘要与日期、详情页分组标题 `dt-group-title` 与规格标签、筛选提示、顾问卡状态。另有 `#0071e3` 在 `#eaf2fb` 浅蓝底上 4.16~4.31（标签类，勉强）、`#0077ed` 在同底 3.82（不达标）。
**建议**：这是**一个 token 改到底**的事——把次要文字色压到 ≥ 4.5:1（约 `#6e6e73` 级别），浅蓝底上的蓝色标签换深一档。

### P1-4 楼盘详情「在租房源」表：整张表没有列间距，表头与数值也不在同一垂直线

- **现象**：
  - 面积 / 单价 / 月租三列的**表头贴在列左端、数值贴在列右端**，用户很难把数字对回表头。错位量随视口放大：**768 → 35–62px，1024 → 46–96px，1440 → 97–148px，1920 → 110–161px**，四个桌面视口全部命中。
  - **整张表所有相邻列之间的间距都是 0**：房源｜面积、面积｜单价、单价｜月租、月租｜可入驻 全部 gap = 0px，可入驻｜详情 甚至是 **-1px（重叠）**。所以长数字（如 `161,700`）会和黑色「可即刻」徽标贴死，看起来像压上去了。
- **证据**：`shots/supply-table-header-misalign.png`；计算样式 `th{text-align:left; padding-right:0}` / `td{text-align:right; padding-right:0}`；`statusBadge.left - totalCell.right === 0`；第二轮 `tableAlign` + `tightChip` 探测在 4 个视口 × 2 个楼盘上共 26 条命中，全部指向这一张表。
- **根因**：**CSS 具体度打架**。[styles.css:1968](payload-office-platform/src/app/(frontend)/styles.css:1968) 的 `.building-supply-browser__table thead th { text-align:left; padding:12px 0 }`（具体度 0-1-2）压过了 [:1978](payload-office-platform/src/app/(frontend)/styles.css:1978) 的 `.building-supply-browser__table-num-head { text-align:right; padding-right:24px }`（0-1-0）；同理 `tbody td { padding:12px 0 }` 压掉了 `.building-supply-browser__table-num` 的 `padding-right:24px`。两条**本来写对了的规则整条失效**。
- **建议**：把 `-num-head` / `-num` 提到同等或更高具体度（如 `.building-supply-browser__table thead th.building-supply-browser__table-num-head`），或把基础规则改成只写 `padding-block`，别用 `padding` 简写覆盖 `padding-right`。修完顺手扫一遍同文件里其它"类选择器被后代选择器压死"的组合。

### P1-5 移动端底部固定「筛选」浮层遮住页脚

列表页滚到底时，`ls-mtrigger__dock`（全宽、84px 高、fixed）盖住页脚最后 84px。列表容器 `padding-bottom: 0`，没有为浮层预留空间。
**建议**：给页面底部加 `padding-bottom: calc(dock 高度 + safe-area-inset-bottom)`。

### P1-6 咨询弹窗的表单细节

核心转化路径（`询价 / 预约看房`）上三处问题：
- **必填星号 `*` 被挤到 label 下一行**，看起来像个孤立红点（`label` 是 `display:flex`，`.modal__required` 是 `display:block`）。
- **错误只有底部汇总列表**（「请填写姓名 / 请填写有效的中国大陆手机号 / …」），字段本身虽然设了 `aria-invalid="true"` 却**没有任何视觉错误态**——视觉用户看不出是哪个框错了。
- 弹窗容器**缺 `role="dialog"` / `aria-modal="true"`**（焦点管理已做：打开时焦点到标题，提交失败后回到第一个错误字段）。

### P1-7 委托找房首屏表单：提交按钮与输入框错位 22px

- **现象**：hero 里的「服务城市 / 手机号 / 免费委托」是一行，但**按钮顶端对齐到了 label 那一行**，比两个输入框整体高出一截，看起来像悬在半空。这是首屏唯一的转化控件。
- **证据**：`round2-shots/entrust-form-baseline.png`；实测 label `T=402–422`、控件 `T=426–466`、按钮 `T=402–446` —— 按钮垂直中心 424 对输入框中心 446，**差 22px**。
- **根因**：`.entrust-form` 是 `display:flex; align-items:flex-start`，两个字段各自带 label 所以高 64px，而按钮没有 label、只有 44px，顶对齐后自然错开。
- **建议**：给按钮 `align-self: flex-end`，或把它包进一个带占位 label 的 `.field`（后者能同时解决 768 以下换行时的对齐）。

### P2-2 隐私政策标题层级倒挂

h1「隐私政策」比 h2「一、我们收集的信息」（36px、更粗）看起来还轻。同页 h2 与上下段落的间距几乎相同，标题"浮"在段落之间（违反邻近性）。另外一二三节用项目符号列表、四五六七节用纯段落，同级内容两种格式；正文栏左边界（360px）与页头 logo（48px）、页脚（48px）完全不对齐。

### P2-3 区块「更多」链接 5 种写法

首页：`查看全部房源 →` / `全部 5 个商圈` / `全部 7 个楼盘` / `查看 11 套在租` / `更多资讯 →`。2 个带箭头、3 个不带；「查看 X」与「全部 X」两种句式并存。

### P2-4 首页区块纵向节奏 3 套

`hm-section` 上下 72px、`hm-stats` 56px、`hm-values` / `hm-news` 88px。同一页三种呼吸感。

### P2-5 阴影与圆角未 token 化

- **阴影 6 种、两套色系**：`rgba(0,0,0,.06) 0 4px 20px`（首页卡）、`rgba(23,26,29,.06) 0 1px 2px`（列表工具条）、`rgba(23,26,29,.08) 0 2px 8px`（详情）、`rgba(23,26,29,.12) 0 8px 24px`（投放房源）、`rgba(0,0,0,.12) 0 2px 12px`、`rgba(0,0,0,.18) 0 4px 24px`。纯黑与 `#171a1d` 两种阴影色混用。
- **圆角**：4 / 7 / 8 / 9 / 10 / 12 / 18 / 50% / 980px / 999px 并存。`980px` 与 `999px` 是同一个"全圆角"意图的两种写法；`7px`、`9px` 是列表页的离群值。

### P2-6 画廊缩略图的上一张/下一张一浅一深

`.detail-gallery__arrow--prev` 是浅灰底灰字（`#f5f5f7` / `#6e6e73`），`--next` 是深蓝黑底白字（`#1e293b`）。同一对导航按钮配色相反，且第一张时 prev 未 disabled。
**根因**：[styles.css:1552](payload-office-platform/src/app/(frontend)/styles.css:1552) 硬编码 `#1e293b`——这是全站 CSS 里**唯一一处**硬编码的 Tailwind 灰，不属于站点色板。

### P2-7 两类详情页的转化机制完全不同

房源详情：右侧 sticky 决策卡 + 决策卡离屏后由 JS 接管的吸附询价条。楼盘详情：顶部 sticky 锚点条（楼盘名 + 在租房源/周边与交通/楼盘参数 + 预约看房）。用户在两类详情页之间来回时，"下一步在哪"每次都要重找。

### P2-8 委托找房 vs 投放房源：同类页面两种范式

- hero 排版：entrust 左对齐、publish 居中。
- 城市 select 宽度：entrust 74px、publish 276px（两套表单实现，input 宽度也差 4px）。
- publish 把「提交房源 → 实勘采集 → 资源曝光 → 签约成交」流程图**插在表单字段中间**（服务城市之后、楼盘信息之前），打断填写节奏。
- entrust 的 hero h1 是品牌 slogan「商办租赁｜找办公室、写字楼租赁」，与页面用途（委托找房）不符；「全城海量真房源，价格透明，服务专业。」在 hero 副标题和「核心服务能力」区块**重复出现两次**。

### P2-9 资讯的两副面孔

首页资讯 = 无图纯文字列表（标题 + 右侧日期）；资讯中心 = 大图卡片网格。同一批内容两种呈现。命名也有两种：导航「资讯」、页面标题「资讯中心」、页脚「资讯中心」、首页区块「资讯」。

### P2-10 卡片高度不齐

- 首页「按类型浏览」第 5 张「创意园区」**缺「N 套在租」那一行**（其余 4 张都有）。桌面端卡片等高但底部空一块；移动端卡片整体矮一截（89px vs 117px），且编号「05」因为 `align-items:center` 随行数漂移，与 CSS 注释里"编号与名称同一行"的意图不符。
- 资讯中心网格同一行卡片不等高（摘要 2 行 vs 3 行），底边参差。

### P2-11 其它一致性小项

- 首页 hero 快捷标签：`长宁` / `徐汇` / `黄浦` / `静安区`——只有一个带「区」。
- 详情页「分享 / 收藏 / 信息纠错」三个同组操作三种视觉权重（前两个轻、「信息纠错」带边框加粗）。
- 楼盘详情同页两套参数范式：左侧「关键规格」宫格（大数字 + 小单位）、右栏 label-value 两端对齐列表；且「支持注册」这种非数值按数值排版（28px 大字），视觉权重错配。

### P2-12 四类可点控件在桌面端没有任何 hover 反馈

全站 54 类可交互元素里，50 类有 `:hover` 规则，下面 4 类没有——鼠标划过去毫无变化，只有 `cursor: pointer` 一个信号：

| 元素 | 位置 |
|---|---|
| `hm-search__filter-btn`「筛选」 | 首页 hero 搜索栏 |
| `detail-gallery__thumb` 缩略图 | 房源详情画廊 |
| `location-panel__poi-tab`（交通/餐饮/银行/酒店） | 房源 + 楼盘详情「周边与交通」 |
| `location-panel__poi-subtab`（地铁/公交） | 同上 |

顺带一个正面结论：**`:focus-visible` 规则 54 类全覆盖，0 缺失**，键盘可达性这一块是好的。

### P2-14 房源概况通栏单列，一行 1264px 只有两端有字；楼盘参数却是两列

同一个 `.dt-spec__row` 组件，在两个详情页有两种用法：

| | 房源详情「房源概况」 | 楼盘详情「楼盘参数」 |
|---|---|---|
| 容器 | `.dt-overview-block` 通栏，行内 flex 两端对齐 | `.dt-building-spec`，`grid-template-columns: 596px 596px` |
| 行宽（@1440） | **1264px** | 596px |
| 行数 | 22 | 23 |
| label 与 value 之间的空白 | **1056–1188px** | 458–506px |
| 区块高度 | **1367px** | 973px |

- **现象**：22 行里内容实际只占行宽的 8–13%，其余全是空白；用户为了看完 4 组参数要滚过 1367px。而同站的楼盘详情用的是两列。
- **可优化的量**：最长的一行内容宽度实测只要 **208px**（「套内参考面积 530.4 ㎡（估算）」）。主栏宽度 @1024 = 556px、@1440 = 940px、@1920 = 1036px（侧栏固定 372 + gap 32）。所以**收进主栏后再切两列，每列 454px（@1440）/ 262px（@1024）都远够用**，区块高度从 1367px 降到约 750px，**省掉约 600px 垂直空间**，首屏能多看到约 10 个字段。
- **和 P0-2 是同一处代码**：把 `.dt-overview-block` 从 `grid-column: 1 / -1` 改成 `grid-column: 1`（收进主栏）再切两列，一次同时解决三件事——值不再被决策卡遮住（P0-2）、不再浪费横向空间（本条）、与楼盘详情范式统一。**建议合并成一个改动做掉。**
- **不建议三列**：@1024 主栏 556px 三列只有 174px/列，装不下 208px 的最长行；且会与楼盘详情的两列再次不一致。

### P2-13 供给表的单价单位，一会儿在表头一会儿在数值里

同一张 `building-supply-browser__table`：陆家嘴楼盘是表头「单价 元/㎡/天」+ 值「9.80」，虹桥楼盘是表头「单价」+ 值「3200 元/工位/月」。表头随计价单位变化，值也随之变化，两种范式在同一个组件里并存——用户在两个楼盘之间切换时，同一列的读法要重新建立。

### P3-2 标题层级与图片属性

- **列表页 h1 → h3 跳级**：`/listings`、`/buildings`、`/sale`、`/news` 全部缺 h2（筛选区、结果区都没有标题），页面上第一个 h3 是页脚的「浏览」。

- 移动端画廊仍显示左右箭头（38×38），移动端应以滑动为主，箭头占用图片可视面积。

### P3-3 桌面 1440 下整页横向溢出 8px

`documentElement.scrollWidth = 1433`、`clientWidth = 1425`。首页所有 `.hm-section` / `.hm-band` 宽 1440px（`100vw`，没有扣掉 15px 滚动条），而 header / footer 是 1425px。结果是页面可以左右晃、区块比页头页脚宽、左侧被切掉 8px。移动端不受影响。

## P4 — 内容与信息架构

### P4-1 列表页同一个数字说了三遍

`上海在租房源` / `共 11 套在租房源` / `11 套符合条件` / `显示第 1–11 套，共 11 套`。移动端这两句还隔了 300px。

### P4-2 说明书式文案占据首屏

- 「三种报价单位之间缺少面积或工位数，无法换算，因此不合并排序。切换单位会更换整个结果集。」
- 「每行单选，选中即写入地址栏；未选的行保持「全部」」
- 「点任一行只改那一个参数，其余条件与排序保留在地址栏里」

文案本身写得准确、诚实，问题是**用文案解释交互 = 交互没自解释**，而且都是 12px `#86868b`（对比度不达标）。移动端这两行说明正好占住首屏黄金位，真正的房源要滚过 650px 才出现。
**建议**：单位切换改成三个 tab 的分段控件（语义上就是"三个独立结果集"），说明降级为图标 tooltip。

### P4-3 同一网格混排 4 种计价口径

一屏里并排出现 `1,800 元/工位/月`、`9.80 元/㎡/天`、`70,000 元/月`、`11.00 元/㎡/天` 和「价格面议」。用户无法横向比较。「价格面议」还用了明显更小更轻的字重，在网格里像是加载失败。
**建议**：至少给「面议」一个与价格同字号的处理；考虑在卡片上补一个统一折算的次要口径（标注为估算）。

### P4-4 空态处理三套标准

- **列表页有筛选时**（做得最好）：「当前筛选组合下没有符合条件的在租房源」+「清除全部条件 · 11 套」+ 可点的「取消『关键词：xxx』这一个条件 → 11」，每个建议都带真实命中数。
- **但 0 结果时「位置 / 类型」两行筛选整行消失**，只剩「面积下限」——用户想改位置却找不到入口，只能靠底部建议。**筛选控件不该随结果集消失。**
- **出售频道 0 套时**：仍然渲染「面积下限」筛选行 + 「每行单选…」说明（筛选毫无意义），顶部「共 0 套出售房源」与「0 套符合条件」重复，空态里唯一的行动点「提交需求」却用了次要按钮样式（全站主 CTA 是蓝色实心）。

### P4-5 资讯中心 5 篇文章同一张蓝色斜纹占位图

一屏 5 个一模一样的占位块占了卡片一半高度。无图时应该退成纯文字卡（首页资讯列表就是这么做的），而不是铺满装饰性占位。

### P4-6 城市切换器把"未开通"当成可选项

下拉里 6 个城市标着「正在开通」且可直接点，点进去落到城市合伙人招募页——与用户点「找办公室」的预期严重不符。状态标签用的是和普通文字同色的小灰字，没有禁用态或视觉区隔。未开通城市的顶部导航也仍然是完整的「找办公室 / 找楼盘 / 共享办公」。

### P4-7 移动端面包屑占两行不折叠

`首页 / 办公选址 / 浦东新区 / 陆家嘴江景甲级写字楼 / 陆家嘴核心区·江景甲级办公` 在 390 宽下换行成两行，吃掉约 100px 首屏。建议折叠中间层级或改横向滚动。

### P4-8 隐私政策缺生效日期

只有「版本 MVP-R1」，没有生效/更新日期。

### P4-9 房源列表的「横向列表」视图比网格视图还稀疏

`?view=row` 这个视图第一轮完全没渲染过（我只测了默认网格）。实测：单张卡 **1344 × 182px**，只承载 4 个字段（标题 / 位置 / 面积 / 价格）；标题行到面积行之间有 **86px 纯空白**，右侧约 **600px 横向空白**。同样宽度下网格视图能放 4 张卡、每张 6 个字段。列表视图本该是"更密、更好比价"的那一个，现在反而更费空间。
**建议**：要么补足字段（层高、可入驻、核验日期、标签），要么压缩行高做成真正的密度视图；否则这个切换按钮不值得存在。

## 第二轮扫了什么（方法 + 负面结论）

第一轮漏掉 P1-4 之后重写的探测，覆盖 **20 条路由 × 5 个视口（390 / 768 / 1024 / 1440 / 1920）= 100 次页面加载**，每页按 0.75 屏步进滚动最多 14 步，逐步跑遮挡类探测；另外两套静态扫描各覆盖 9–10 页。

| 探测项 | 做法 | 结果 |
|---|---|---|
| 文字被遮盖 | 每个文本叶子取 3 个采样点做 `elementFromPoint` | **命中 P0-2**（并确认 ≥1024 全中）；其余全是吸附页头/锚点条/底部条的正常遮挡 |
| 交互元素被挡 | 每个可点元素中心点 `elementFromPoint` | 105 类命中，逐条核对后**全部是吸附栏正常遮挡，0 个真实不可点**（移动端抽屉关闭按钮那条只有点开抽屉才触发，见 P0-3） |
| 表头↔列值对齐 | 逐列比 `text-align` / `padding` / 文本边缘 | **命中 P1-4**；全站只有 1 个 `<table>`，无第二处同类问题 |
| 徽标与相邻文字间距 | 有底色/描边的小块与左右文本的间距 <8px | 10 条，**全部属于 P1-4 同一根因** |
| 文本硬裁切 | `scrollWidth > clientWidth` 且无省略号 | 10 条命中**全是 `.visually-hidden`（屏读专用 1px 裁切），0 个真实裁切** |
| 子元素溢出父容器 | 与父 padding box 比对 | **0** |
| 同行卡片不等高 | 按 top 分组比高度 | 10 类，逐条核对后只有 P1-7 是真问题，其余是有意的 `align-items:start` |
| 重复 id | — | **0** |
| CSS 声明失效 | 遍历所有匹配规则，归一化后与 `getComputedStyle` 比对 | 725 条原始命中，逐条排掉归一化误报与刻意覆盖后，**整站只剩 P1-4 一处是非预期失效** |
| hover / focus 态 | 解析样式表看 `:hover` / `:focus-visible` 是否命中 | **命中 P2-12**（4 类无 hover）；focus 环 54 类全覆盖，0 缺失 |
| 锚点跳转是否被吸附栏盖住 | 逐个 `#anchor` 跳转后比标题顶端与吸附栏底端 | **0**（`scroll-margin-top: 112px` 已正确设置） |

也就是说：这一轮把「元素级布局缺陷」能自动测的都测了，新增 4 条（P1-7、P2-12、P2-13、P4-9），并把 P0-2 / P1-4 的影响范围测准。**但仍不能声称"零遗漏"**——自动探测测不到的是审美判断（层级、留白、信息密度、文案语气）和需要特定状态才出现的问题（表单中途态、上传失败、超长内容、并发数据），这些只能靠继续人工走查补。
