## 2. 阶段 A：已确认缺陷修复（F-001 ~ F-004）

### A1. 房源详情底栏布局（F-001）
- **根因确认**：微信小程序原生 `<button>` 带有微信 UA 默认样式 `width: 184px; margin-left: auto; margin-right: auto;`。在 CSS Grid 布局中，原生按钮若未声明 `width: 100%`，其 184px 固有宽度会撑破并溢出所在的 grid 列，导致右侧主操作区域被原生按钮的隐形框体遮挡甚至事件重叠。
- **修复方案**：
  在 `miniprogram/pages/listing-detail/index.wxss` 中为 `.listing-detail__bar-action` 增加明确的尺寸与布局约束：
  ```css
  width: 100%;
  max-width: 100%;
  box-sizing: border-box;
  min-width: 0;
  min-height: var(--sbh-size-touch-target);
  ```
- **验收结果**：
  - 在 375×667、390×844、430×932 视口下，分享次按钮（width: 100% 填满其所属的 1fr 列）与咨询主按钮横向独立，几何交集为 0，间距保持 16rpx（≥ 8px），命中热区高度 ≥ 44px（88rpx）。

### A2. 楼盘详情重试（F-002）
- **根因确认**：`building-detail/index.ts` 中的 `loadBuildingDetail(targetSlug?: unknown)` 之前将 `bindretry` 事件派发出的 `CustomEvent` 对象直接作为 `targetSlug` 参与逻辑判断，误将 `object` 当作 slug，导致其无法匹配合法 slug 从而跳转到 `not-found`，且重试没有发起正确的网络请求。
- **修复方案**：
  - 严谨处理参数：仅当 `typeof targetSlug === 'string' && targetSlug.trim()` 时采纳传参；否则回退至 `this.data.slug`。
  - 请求前增加 slug 格式校验 `isValidBuildingSlug(resolvedSlug)`。
  - 增加请求竞态防护版本号 `this.loadVersion`，避免快速重试或切页导致陈旧请求覆盖最新状态。
- **验收结果**：
  - 模拟网络失败后点击“重新加载”，网络层使用正确原 slug 发起有限重试，成功后恢复为 `ready` 状态；若 slug 本身无效则准确进入 `not-found` 态。

### A3. 楼盘详情错误分类（F-003）
- **根因确认**：旧代码存在依赖面向用户的 message 文本判断（如正则或字符串匹配 "404" / "not_found"），容易将服务异常或含特定文本的错误误判。
- **修复方案**：
  - 采用结构化错误判别 `isBuildingNotFound(error)`：
    ```ts
    const isBuildingNotFound = (error instanceof MiniApiError && error.code === 'building_not_found') ||
      (error instanceof MiniApiError && error.statusCode === 404);
    ```
  - 任何普通的 `network`、`timeout`、5xx 或未知异常严格归类为 `error` 态，保留重新加载能力；仅确定资源不存在时才进入 `not-found` 态。
- **验收结果**：
  - 8 组错误测试矩阵（`tests/building-detail-behavior.test.ts` 及探针）显示：改变错误 message 不影响分类；标准业务 404 与 HTTP 404 准确进入 `not-found`；网络错误与 500 进入 `error`。

### A4. 公共状态组件空状态恢复动作（F-004）
- **根因确认**：`sbh-state` 组件在 `index.wxml` 中原先只在 `kind === 'error'` 且具备 `actionLabel` 时才渲染操作按钮并绑定 `handleRetry`，`kind === 'empty'` 时的按钮被硬编码隐藏，导致业务页无法提供重置筛选或返回等引导。
- **修复方案**：
  - 修改 `sbh-state/index.js` 与 `index.wxml`，支持 `(resolvedKind === 'error' || resolvedKind === 'empty') && actionLabel` 时显示操作按钮。
  - `loading` 状态无论有无 `actionLabel` 绝对不渲染按钮，不派发事件。
  - 楼盘列表页空状态配置 `action-label="重置筛选"`，绑定 `handleResetFilters`，清空筛选条件并回到第一页。
  - 楼盘详情页 404 空状态配置 `action-label="返回楼盘列表"`，绑定 `handleBackToList`，通过 `wx.switchTab({ url: '/pages/buildings/index' })` 跳转。
- **验收结果**：
  - 5 行条件真值表单元测试全部通过。
  - 筛选零结果点击“重置筛选”清空筛选项并重新加载第 1 页。

## 4. 阶段 C：条件性优化与复核（C1 ~ C4）

### C1. 首页背景媒体（R-003）
- **核查结论**：原代码 `heroVideoUrl` 指向 Web 相对路径 `/video/hero.mp4`，在微信小程序原生运行时无法寻址且产生加载警告；当前项目暂无合规的绝对 HTTPS CDN 视频资源。
- **处理方案**：依照规格既定策略明确收口：移除不可达的视频组件，使用高质量静态海报背景；若图片加载失败，通过 `binderror="handleHeroImageError"` 优雅降级为品牌深色渐变背景，彻底杜绝白屏与网络异常警告。

### C2. 详情返回后的收藏同步（R-004）
- **核查结论**：在多层跳转（楼盘 A → 房源 → 楼盘 A 实例 2 → 变更收藏）后返回上一实例时，由于缺少生命周期刷新，页面会显示过期的收藏状态。
- **处理方案**：在 `pages/building-detail/index.ts` 与 `pages/listing-detail/index.ts` 中补齐 `onShow()` 生命周期钩子，调用 `this.loadFavoriteState(slug)` 静默重新拉取状态。若同步失败，保留原状态或明确报错，不伪造未收藏状态。

### C3. 咨询失败信息连续性
- **核查结论**：用户在咨询弹窗中遇到通用错误（如会话失效或服务异常）后，切换“微信一键”与“手填验证码”模式时，原有的通用错误被一刀切清空。
- **处理方案**：在 `components/inquiry-sheet/controller.ts` 中精细化模式切换逻辑：仅清空特定验证方式专有的错误（如 `phone-code-consumed`），保留通用的 `session-invalid`、`service`、`network` 等阻断性错误，避免用户在未解决的会话/网络问题下盲目重试。

### C4. 组件 WXSS 兼容性
- **核查结论**：`listing-card`、`building-card` 与 `inquiry-sheet` 中存在 `image` 标签选择器以及 `button[disabled]` 复合选择器，微信开发者工具控制台会报出 WXSS 限制告警。
- **处理方案**：规范重构为类选择器：
  - `image` → `.listing-card__image` / `.building-card__image`
  - `button[disabled]` → `.inquiry-sheet__submit[disabled]` 及等价 class。控制台对应告警彻底消除。
