# OPT-062 视觉验证：待补清单

**这份文件列的是目前完全没有像素级证据支撑的结论。** 本轮验收拿到的是真实的

出图（而不是裂图占位符）；两个弹层叠在一起时有没有视觉错位、闪烁、z-index 穿插。
**这不是「差最后一层薄薄的确认」，这是视觉验收本来要验的东西**，本次都没验到。

本文件由独立审计在复核 `network-evidence.json` 后指出「brief 要求写清哪些结论
没有像素证据，但报告没有列出具体清单」而补建，清单条目为审计给出、经确认后落地。

## 待补的五项视觉确认

### 1. `cover-thumbnail-render.png` —— 封面缩略图上传后的实际渲染

- **访问**：登录后台（`e2e-adm@example.com` / 密码见 `scripts/seed.ts`），进入
  「区域管理 → 商圈管理」，随便打开一个当前**没有封面**的商圈的编辑抽屉
  （列表「封面」列显示 ⚠ 的都是），点开「从素材库选择 / 上传新图」→上传一张
  真实的、有实际像素内容的图片（不要用本轮验证时那种 1×1 占位 PNG——那张图
  本身就不构成任何视觉证据，只是用来触发接口）。
- **看什么**：上传成功后，抽屉里「更换 / 移除」按钮旁边的缩略图是否**正常显示
  出图**——有没有裂图图标、加载失败的占位符、长宽比拉伸变形、或者图片主体
  被组件容器裁切到看不出内容。
- **看到什么算通过**：缩略图清晰显示上传的图片内容，比例正常，没有裂图/
  加载失败标志。看到裂图或空白占位，记下具体表现，判不通过。

### 2. `cover-buttons-visibility.png` —— 「更换 / 移除」按钮的真实可见可点性

- **准备**：接第 1 项，抽屉里已经有一张真实封面图。
- **看什么**：「更换」「移除」两个按钮是否**完整可见、不被缩略图或其它元素
  遮挡**；按钮的可点击区域是否与视觉呈现的按钮边界一致（本轮验证全程靠
  `element.click()` 直接调用 DOM 方法触发，没有一次是靠「鼠标移动到按钮视觉
  位置再点」，所以「按钮长在正确的地方、没有被 z-index 更高的元素盖住」这件事
  完全没有被验证过）。
- **看到什么算通过**：两个按钮清晰可见、位置符合预期（缩略图下方或旁边，
  不与其它控件重叠）。看到按钮被遮挡、错位或视觉上判断不出可点，判不通过。

### 3. `picker-modal-over-drawer-layout.png` —— 选图弹层叠在抽屉之上的实际布局

- **准备**：进入任意商圈抽屉，点开「从素材库选择 / 上传新图」打开
  `CoverPickerModal`。
- **看什么**：弹层是否在抽屉之上正确居中/定位，有没有与抽屉边缘的视觉冲突
  （比如弹层被抽屉的滚动条裁切、弹层的遮罩层没有完全覆盖抽屉导致背景穿帮、
  弹层出现/消失时有没有明显的抖动或跳变）；`z-index` 层级本轮只用
  `getBoundingClientRect`/`getComputedStyle` 验证过「关闭后弹层不可见、抽屉仍
  可见」这一个**二元状态**，没有验证过弹层打开状态下的**实际叠放效果**是否
  美观、无穿插。
- **看到什么算通过**：弹层完整、居中展示在抽屉之上，遮罩正确覆盖，没有裁切
  或穿帮，开关动画顺滑无跳变。看到布局错位、裁切或明显闪烁，判不通过。

### 4. `list-cover-icon-legibility.png` —— 列表「封面」列 ⚠/✓ 图标的实际可辨识度

- **访问**：「商圈管理」列表页，默认视口下查看「封面」这一列。
- **看什么**：⚠（缺封面）与 ✓（已配封面）两种状态图标在正常字号/行高下是否
  **一眼可辨**（颜色对比度、图标大小），会不会和相邻列（例如「边界」列同样用
  ⚠ 符号）混淆导致运营人员看错列。
- **看到什么算通过**：两种图标清晰可辨、色彩语义明确（缺失用警示色、完整用
  确认色），不会与「边界」列的同类图标产生列间混淆。看到图标模糊、颜色区分度
  不够，或容易看错列，判不通过。

### 5. 响应式 / 加载态等只有画面能捕捉的现象

- **访问**：把浏览器窗口缩到移动端宽度（375px 左右）或用设备模拟，重复第 1-3
  项的操作；另外在上传过程中观察（网络慢速模拟或直接看）有没有**加载中状态**
  的视觉反馈（spinner、按钮禁用态的视觉呈现）。
- **看什么**：抽屉在窄屏下封面区块的布局是否合理（按钮会不会被挤到换行、
  缩略图会不会溢出）；上传中是否有清晰的加载反馈，而不是让用户误以为卡住了。
- **看到什么算通过**：窄屏下布局不错乱、不溢出；上传过程中有明确的
  loading/disabled 视觉状态。看到布局挤压错乱或上传过程没有任何反馈（容易
  被误判为卡死/重复点击），判不通过。

本轮所有交互改用 `javascript_tool` 里 `element.click()` 直接调用 DOM 方法、
