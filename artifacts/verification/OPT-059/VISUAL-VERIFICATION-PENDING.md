# OPT-059 视觉验证：待补清单

**这份文件列的是目前完全没有证据支撑的结论。** 本次验收拿到的是 DOM 结构、`getComputedStyle` 读值、真实网络请求——这些证明的是「数据被正确传到了决定渲染结果的属性/接口上」，**不证明肉眼看到的画面是对的**。比如 `object-position` 从 `50% 50%` 变成 `20% 80%` 只说明这个 CSS 属性值变了，不说明：这张图片的内容配上容器的宽高比，偏移后视觉上是否真的能看出来、构图是否合理、有没有把主体裁没了。断点那边同理，`display:none`、`height:232px` 这些数字对了，不代表没有溢出、没有残留色块、字体没有挤压变形。**这不是「差最后一层薄薄的确认」，这是这三项验收项本来要验的东西**，本次都没验到。

## 待补的三张截图

### 1. `desktop.png` —— 首页桌面视口

- **访问**：桌面浏览器窗口（不缩放，标准桌面宽度，比如 1440px 或更宽），打开首页 `/shanghai`（多城市路由已开启，根路径会重定向到这个地址；如果重定向没生效，直接访问 `/shanghai`）。
- **看什么**：
  - 「按类型浏览」区块（`.hm-types`）里几张类型卡的图片——**图片本身有没有被拉伸变形**（长宽比不对、人脸/建筑物看起来被压扁或拉长）。
  - 「热门商圈」bento 区块（`.hm-bento`）——大卡（480px 高）、两张小卡（232px 高）、宽卡（280px 高）各自的图片，**裁切构图是否合理**：主体（比如楼盘外立面、天际线）有没有被裁掉关键部分，图片是否清晰、没有明显的马赛克或拉伸痕迹。
- **看到什么算通过**：所有卡片图片都是「铺满容器、按比例裁切、无变形拉伸、主体清晰完整」的正常状态；看到任何一张图被明显压扁/拉长/裁得很怪，都算不通过，需要记下是哪张卡、什么问题。

### 2. `mobile.png` —— 375px 窄屏

- **访问**：浏览器开发者工具切到设备模拟，或者直接把窗口缩到 375px 宽（对应 iPhone SE/8 这一档），刷新首页 `/shanghai`。
- **看什么**：
  - 「按类型浏览」区块——每一行应该变成横向紧凑行（无图，左侧是编号），**编号列（左侧 28px 宽的区域）里不应该有任何残留的色块或方形占位**（这是 `home.css:210` 那条规则要盖住的——图片元素被 `display:none`，但如果还有别的元素露出底色，就是没盖干净）。
  - 「热门商圈」bento 区块——应该纵向堆叠成一列，**大卡/小卡/宽卡三种卡看起来高度一致**（都是 232px），观感上不应该有一张明显比另外两张矮或高。
- **看到什么算通过**：类型卡那一列干净，只有编号+文字，没有色块；bento 三张卡纵向排列、高度肉眼看起来整齐一致。看到编号列里有灰色/彩色方块，或者三张 bento 卡高度明显不一样，算不通过。

### 3. `focal-effect.png` —— 焦点确实影响裁切

- **准备**：登录后台（用 `scripts/seed.ts` 里的 E2E 夹具账号，比如 `e2e-adm@example.com`，密码写在该文件里），进入「素材库」，找一张已经有三档派生（即最近上传过、不是老图）的图片，点「编辑图像」，把「焦点」的 X% 改成 20、Y% 改成 80（明显偏左上/偏下，取决于图片方向——总之要是一个肉眼能分辨出「偏离正中心」的位置），保存。
  - 如果手头没有现成的「有派生」图片，就新传一张（任意一张有明显主体、比如一张人物照或建筑照，不要用纯色图/无特征图，否则偏移了也看不出来），再按上面步骤设焦点。
  - 把这张图配到某个「商圈管理」条目的「封面图」字段上（后台 → 区域管理 → 商圈管理，编辑任意一个商圈，「封面图」选刚才那张图）。
- **访问**：首页 `/shanghai`，找到「热门商圈」区块里对应那张商圈卡（**注意：首页有数据缓存，最长 5 分钟内可能还看到旧封面/旧焦点，如果刷新后没变化，等几分钟再刷新一次**）。
- **看什么**：这张卡片里的图片，构图有没有明显偏移——比如你设的焦点是「偏左上」，卡片露出来的部分应该也偏向图片左上角的内容，而不是像其它卡片一样居中取景。
- **看到什么算通过**：跟同一批其它没设特殊焦点的卡片对比，这张卡的取景明显偏向你设定的焦点方向。如果肉眼完全看不出差异（哪怕焦点数值确实是 20/80），算不通过，需要记下来——这种情况可能意味着图片内容本身在偏移前后差异不大，或者裁切逻辑没有真正按焦点生效。

## 为什么本次没做到

本会话的 Browser pane 全程处于「未显示，不合成帧」状态，`computer.screenshot` / `computer.zoom` 每次调用都报：

```
Screenshot timed out after 5s: the Browser pane is not displayed, so the page is not compositing frames. Display the pane and retry.
```

这个报错本身说明浏览器压根没有产出任何一帧画面——不是截图工具本身的 bug，是这个非交互式/后台子代理会话没有一个真正显示出来的浏览器界面。已经过多次重试、切换 tab、新建前台 tab 排查，均复现同样的错误，是**会话级限制**，与被测功能无关。协调者也独立复现了同样的报错，确认了这一点。

1. 确认在分支 `feat/opt-059-image-pipeline-4b3c` 上（或它已合并到的分支）。

5. 按上面「3. `focal-effect.png`」的步骤，找一张图设置明显偏离中心的焦点，配到某个商圈封面上。
6. 访问 `http://localhost:3717/shanghai`（首页），按标准桌面宽度截一张图存为 `desktop.png`。
