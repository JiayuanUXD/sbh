# 商办平台前台开发 Agent 指南

> 适用对象：Codex、Claude Code、自动化 Agent 与人工开发者  
> 适用范围：C 端公开站、公开查询、SEO、咨询表单及其测试  
> 更新日期：2026-07-25

## 1. 使命

前台 Agent 负责把已确认的产品需求和视觉设计实现成可信、快速、易用的商办选址网站。工作重点不是堆叠页面，而是保证：

- 用户看到的房源真实、当前有效且口径一致；
- 搜索、比较、详情和咨询形成完整闭环；
- 页面具有专业服务品牌质感，而非通用后台组件风格；
- SEO、性能、可访问性、隐私和可观测性能够被实际验收；
- 每项完成声明均有静态检查、测试和真实浏览器证据。

## 2. 触发范围

当任务涉及以下任一路径或能力时，必须读取本文件：

- `src/app/(frontend)/`
- `src/components/frontend/`
- `src/lib/frontend/`
- `src/domain/public-catalog/`
- `src/app/api/inquiries/`
- 前台使用的 Pages、Media、Listings、Buildings、Locations、Leads 字段
- metadata、canonical、JSON-LD、robots、sitemap
- 前台缓存、分析事件、隐私同意、响应式布局和浏览器验收

如果任务同时修改后台领域服务或数据模型，还必须遵守根级 `AGENTS.md` 和对应后台 PRD；本文件不能放宽后台业务不变量。

## 3. 权威文档与优先级

开始前按顺序阅读：

1. `../docs/prd/前台网站_MVP_页面PRD/README.md`
2. `../docs/prd/前台网站_MVP_页面PRD/` 下对应页面 PRD
3. `../specs/frontend-mvp/requirements.md`
4. `../specs/frontend-mvp/design.md`
5. `../specs/frontend-mvp/tasks.md`
6. 后台统一规则：`../docs/prd/后台管理系统_MVP_页面PRD/README.md`
7. 根级 `AGENTS.md`
8. 本文件
9. 代码注释与历史计划

解释规则：

- 页面 PRD 是用户可见结果与页面验收基线。
- Requirements 定义跨页面需求和业务边界。
- Design 定义架构、数据、安全、缓存和测试方案。
- Tasks 只定义实施顺序与状态，不得反向改写需求。
- 后台 PRD 中的状态、权限、有效供给、金额和历史规则不可由前台放宽。
- 文档冲突时暂停受影响实现，列明冲突内容、影响页面和建议选项。

## 4. 当前实施流程

每次任务遵循：

1. 确认 `tasks.md` 编号、对应 Requirement、页面 PRD 和依赖。
2. 读取直接拥有该流程的路由、组件、查询、领域服务和测试。
3. 记录修改前的目标页面、相邻页面和控制台状态。
4. 对跨模块、数据模型、API、安全或视觉方向变化取得用户确认。
5. 先补测试或可复现失败，再实现最小完整闭环。
6. 执行类型、测试、构建和浏览器验证。
7. 只在证据通过后更新任务复选框。
8. 交付时列出结果、文件、验证、剩余风险和未执行项。

禁止未经确认跨越 `tasks.md` 当前里程碑。允许先做无阻塞的 F0/F2 工作，但不得用假数据宣称依赖后台 M4.7/M5 的业务闭环已经完成。

## 5. 技术栈与工程边界

- Next.js 16 App Router、React 19、TypeScript。
- Server Components 和 Payload Local API 为公开读页面默认方案。
- 客户端组件只用于筛选抽屉、画廊、咨询弹层和必要交互。
- 包管理器固定为 pnpm，不得使用 npm/yarn 改写锁文件。
- 前台样式使用项目原生 CSS 和设计 token。
- 禁止引入 shadcn-ui、Tailwind reset 或全局第三方 CSS reset。
- 不为一个局部任务重写框架、路由系统或状态管理方案。
- 不手工修改生成的 Payload `importMap.js` 和 `payload-types.ts`。

### 5.1 目录职责

```text
src/
├── app/(frontend)/              # 路由、Metadata、页面编排、错误边界
├── app/api/inquiries/           # 公开询盘写入口
├── components/frontend/         # 公开站 UI 与交互组件
├── domain/public-catalog/       # 公开查询门面、DTO、mapper
├── domain/supply/               # 统一有效供给服务（后台 M4.7）
└── lib/frontend/                # 纯解析、格式化和前台工具
```

路由层不得拼 Payload `where`，组件不得调用 Payload，Collection hook 不得包含页面编排。

## 6. 不可违反的产品与数据规则

### 6.1 统一有效供给是唯一入口

首页、列表、总数、facet、详情、楼盘聚合、相关推荐、内容引用、询盘候选和 sitemap 必须调用同一 `domain/supply` 服务。

不得使用以下方式降级：

- 只判断 `status=available`；
- 只判断发布状态；
- 在组件、路由或 sitemap 中复制一份简化谓词；
- 数据服务失败时回退到未经有效供给校验的旧查询；
- 用 UI 隐藏代替服务端排除。

完整谓词至少包含：Listing 未逻辑删除、已上架、审核通过、冻结正常、未被有效举报暂停、媒体完整；Building、城市和区域启用；当前商户关系有效且唯一；商户启用、资质有效未过期、服务城市启用并覆盖楼盘；租赁可用性和陈旧规则符合后台定义。

后台 M4.7 未完成时，只允许实现契约、fixture 和明确的未就绪状态，不得接入生产公开页面。

### 6.2 公开 DTO 隔离

- 页面和组件只消费 `Public Catalog DTO`，不接收原始 Payload 文档。
- mapper 使用明确字段白名单。
- 不向浏览器暴露审核、举报、商户资质、内部电话、权限、审计、精确内部坐标或工作版本。
- 媒体、价格、面积、时间和 SEO 使用统一值对象。
- 详情、卡片、聚合和结构化数据不得分别解释同一字段。

### 6.3 价格和排序

- 金额始终保留并展示数值、币种、计价周期和单位。
- 租赁与出售、不同币种、不同单位不得直接聚合或排序。
- 推荐、最新和价格排序最后使用不可变 `listing_id` 稳定收束。
- 页面刷新、分享、前进和后退必须复现相同筛选状态。
- 时间以数据库 UTC 存储，产品展示与自然日规则使用 `Asia/Shanghai`。

## 7. TypeScript 与 React 规则

- 禁止 `any`、`as any`、`@ts-ignore`、`@ts-nocheck`。
- 外部 JSON、查询参数和请求体使用 `unknown`，通过 schema 或类型守卫收窄。
- 第三方类型错误用精确 adapter 或 module augmentation 修复。
- DTO 默认使用 `Readonly`，避免客户端误写服务端数据。
- Server Component 优先；不得为使用 hooks 把整页变为 Client Component。
- 客户端状态局限于当前交互，不引入全局状态库保存可由 URL 表达的筛选。
- effect 必须有明确外部同步目的，不用 effect 派生普通渲染数据。
- 列表 key 使用不可变业务 ID，不使用数组索引。
- 不用捕获并吞掉错误来制造“正常”状态。

## 8. 视觉实现规则

视觉方向固定为：克制、专业、温暖、数据可信、具有编辑感。

### 8.1 设计 token

- 墨色 `#171A1D`
- 品牌纸色 `#F5F1E8`
- 页面底色 `#FCFBF8`
- 分隔色 `#D5D0C7`
- 铜色强调 `#A46F3F`
- 森林绿 `#1F5A50`
- 错误色 `#B0443C`

中文展示使用思源宋体 SC，界面正文使用思源黑体 SC，数字/英文使用 IBM Plex Sans，并提供系统字体回退。

### 8.2 布局和组件

- 桌面最大内容宽 1440px，使用 12 列栅格。
- 重点验证 `<640`、`640–1023`、`1024–1439`、`>=1440`。
- 卡片以留白、排版和边界建立层次，避免大面积阴影和胶囊化。
- 房源卡图片 4:3，详情主图桌面 16:10。
- 首屏不使用自动轮播，不使用阻碍找房的全屏视频。
- 图标使用统一专业图标库，不用 emoji 充当操作图标。
- 动效 160–240ms，并尊重 `prefers-reduced-motion`。

任何新增视觉方向、配色、字体或大规模布局变化必须先更新 Design Specification 并取得确认；不要在实现中临时发明第二套设计系统。

## 9. 状态与内容质量

每个页面必须实现并验证：

- 正常；
- 加载；
- 空；
- 错误与重试；
- 数据失效/404；
- 长标题、长地址和极值价格；
- 图片失败；
- 移动端软键盘或小视口；
- 减少动效。

规则：

- 请求失败不得展示为 0 套。
- 无结果不得混入不匹配房源。
- 失效房源不得继续显示历史详情或接受定向询盘。
- 未支持 CMS 模块可安全跳过并告警，不得让整页崩溃。
- 用户可见中文不得出现乱码、占位问号、错误编码或内部枚举。

## 10. 咨询表单安全

- 服务端把请求体视为 `unknown` 并做白名单 schema 校验。
- 校验 Content-Type、body 大小、同源/CSRF、字段长度和枚举。
- 未主动同意隐私政策不得提交，必须保存政策版本。
- 使用数据库唯一约束实现持久化幂等。
- 生产限流使用多实例共享机制，不得只使用进程内 `Map`。
- 带房源提交前再次调用 `assertEffectiveListing`。
- 目标失效时不得创建有效房源兴趣关系，可转通用选址需求。
- 日志、埋点和错误监控不得包含完整姓名、手机号、留言正文或原始 IP。
- 返回值不暴露 Lead ID、负责人、内部校验原因或数据库错误。

## 11. SEO、缓存与分析

### 11.1 SEO

- 每页生成唯一 title、description、canonical 和 OG。
- 页面只存在一个 H1，标题层级按语义顺序。
- JSON-LD 与页面使用同一 DTO，不声称无法保证的价格或库存。
- 高维筛选组合按设计使用 `noindex,follow`。
- sitemap 只包含已发布内容和当前有效供给。
- 域名来自类型化环境配置，不硬编码生产地址。

### 11.2 缓存

- 公共供给最长缓存 5 分钟。
- 使用 design 中定义的实体/查询 tag。
- 发布、审核、冻结、举报、媒体、位置、商户关系/资格/服务城市和可用性事件触发失效。
- 无法安全计算局部影响时执行更大范围安全失效，不延长陈旧窗口。
- 询盘与用户提交结果不缓存。

### 11.3 分析

- 事件名和字段遵循前台 Design。
- 只记录匿名对象 ID、枚举、页面上下文和结果。
- 不发送搜索或表单中的个人信息。
- 曝光事件使用可见性阈值和去重，禁止 render 即曝光。

## 12. 可访问性与性能

### 12.1 可访问性

- 目标为 WCAG 2.2 AA。
- 全键盘完成搜索、筛选、分页、画廊、弹层和咨询。
- Modal/Drawer 必须焦点锁定、Esc 关闭、焦点归还和背景不可操作。
- 输入有可读 label，错误与控件关联，结果变化使用适度 live region。
- 触控目标至少 44×44px，颜色不是唯一状态表达。
- 图片 alt、landmark、skip link、标题层级和语义链接完整。

### 12.2 性能

- 移动 p75 目标：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。
- 首屏仅关键图片优先，其余懒加载并声明尺寸。
- 字体子集化，首屏最多预加载两个必要字体文件。
- 初始客户端 JavaScript 目标 ≤ 170KB gzip。
- Payload 查询只选 DTO 所需字段，控制 depth 并避免 N+1。

## 13. 测试策略

### 13.1 最低测试范围

- 单元：URL、schema、format、mapper、排序、幂等键。
- 契约：统一有效供给对所有公开消费者一致。
- 集成：公开查询门面、询盘入口、缓存失效。
- E2E：首页搜索 → 列表 → 详情 → 咨询；楼盘 → 房源；内容 → CTA。
- 视觉：四档视口及所有重要状态。

### 13.2 失效供给 fixture

必须覆盖：草稿、未审核、冻结、举报暂停、媒体不足、Building/区域停用、商户停用、资质过期、服务城市不覆盖、关系重叠、陈旧、已出租和逻辑删除。

每种 fixture 都要断言首页、列表、total、facet、详情、楼盘聚合、相关推荐、内容引用、询盘候选和 sitemap 结果一致。

## 14. 完成前必须验证

按改动范围执行：

```bash
pnpm exec payload generate:types
pnpm exec payload generate:importmap
pnpm exec tsc --noEmit --pretty false
pnpm test
pnpm build
```

- 未改 Collection/Global 可省略 `generate:types`。
- 未改后台组件注册可省略 `generate:importmap`。
- 用户可见页面、路由、表单或异步交互必须在真实浏览器验证。
- 至少检查目标路由、一个相邻路由和控制台。
- 视觉走查必须包含 375×812、768×1024、1440×900、1920×1080。
- 验证记录包含路由、操作、预期、实际、截图/日志和未验证项。

任何命令未运行或环境阻塞时必须明确报告，不得笼统声称“全部正常”。

## 15. Git 与数据安全

- 保留用户和其他任务的未提交修改，不覆盖无关文件。
- 禁止 `git reset --hard`、`git checkout --` 和破坏性清理。
- 未经用户要求不自动提交、推送或创建 PR。
- 不提交 `.env`、密钥、数据库、上传媒体、临时截图和个人信息。
- 数据模型变更必须有显式迁移、dry-run、影响数量、校验和回滚说明。
- 不修改历史审核、举报、归属、跟进或审计记录来修复展示问题。

## 16. 完成定义

一项前台任务只有同时满足以下条件才可完成：

- 用户可见结果符合对应页面 PRD。
- 服务端数据口径和公开字段正确。
- 无新增乱码、类型逃逸、敏感信息泄露或控制台错误。
- 关键正常、空、错和失效路径有测试。
- TypeScript、相关测试和构建通过。
- 真实浏览器目标流程和相邻流程通过。
- 性能与可访问性没有新增阻断问题。
- `specs/frontend-mvp/tasks.md` 已更新。
- 交付说明准确列出验证证据和剩余风险。
