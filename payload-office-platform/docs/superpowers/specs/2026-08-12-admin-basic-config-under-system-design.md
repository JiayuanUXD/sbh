# 后台基础配置移入系统管理设计

## 目标

将后台导航中的“基础配置”整体从“房源运营”移动到“系统管理”，让低频主数据配置与用户、角色和高级工具集中管理，同时保持业务页面、路由和权限行为不变。

## 菜单结构

- “房源运营”保留：房源列表、楼盘库、房源投放申请。
- “系统管理”依次包含：用户管理、角色管理、基础配置、高级工具。
- “基础配置”保留既有五项及顺序：城市管理、行政区域、商圈管理、地铁管理、配套字典。
- “基础配置”继续作为二级可折叠分组，不平铺为一级菜单。

## 行为边界

- 不修改任何页面 URL、Collection、Custom View 或数据结构。
- 不修改菜单码、Collection 读权限、操作权限或角色矩阵。
- 导航仍按现有权限过滤；无任一基础配置权限的角色不会看到空分组。
- 当前路由位于五个基础配置页面时，“系统管理”应作为所属一级组展开。

## 实现方式

仅调整 `ADMIN_NAV_GROUPS` 的树结构：把现有 `supply-settings` 子树从 `supply` 移到 `system`，放在角色管理和高级工具之间。沿用既有导航渲染、权限过滤和展开状态逻辑，不新增组件或状态。

## 验证

- 导航配置合同测试锁定新的树结构与顺序。
- 导航状态/角色矩阵相关测试确保权限和展开行为无回归。
- 地理后台 E2E 改为从“系统管理 → 基础配置”进入，并继续验证五项及无独立商圈扩展入口。
- TypeScript、相关测试及生产构建通过。
- 真实浏览器验证目标结构、基础配置入口、房源运营相邻菜单和控制台。

## 非目标

- 不拆分“基础配置”中的地理与配套项目。
- 不调整“高级工具”、用户管理或角色管理内容。
- 不重命名菜单，不新增后台字典管理能力。
