# 后台区域管理导航设计

## 目标

将地理主数据从“房源运营 → 基础配置”中独立出来，新增一级导航“区域管理”，使城市、行政区域、商圈和地铁入口更容易发现；配套字典仍作为系统级基础配置管理。

同时修复地理自定义 Admin View 缺失后台框架的问题，使列表、详情和新建页面恢复与其他 Payload 后台页面一致的左侧导航和顶部栏。

## 菜单结构

- 新增一级导航“区域管理”，位于“房源运营”之后、“审核与风控”之前。
- “区域管理”直接包含四个叶子入口，顺序为：城市管理、行政区域、商圈管理、地铁管理。
- “房源运营”保留：房源列表、楼盘库、房源投放申请。
- “系统管理”依次包含：用户管理、角色管理、基础配置、高级工具。
- “系统管理 → 基础配置”继续作为二级可折叠分组，仅保留“配套字典”。

## 行为边界

- 不修改任何页面 URL、Collection、Custom View 或数据结构。
- 不修改各入口已有的菜单码、Collection 读权限、操作权限或角色权限数据。
- “区域管理”作为配置树的新一级分组，按四个地理入口的既有权限过滤；没有任何可见地理入口的角色不显示空分组。
- 当前路由位于四个地理页面时，“区域管理”作为所属一级组展开。
- 当前路由位于配套字典时，“系统管理”作为所属一级组展开。
- 四个地理列表页、城市详情页和行政区新建页都必须显示后台左侧导航与顶部栏。
- 自定义地理页面继续执行已有的服务端准入检查；模板修复不得扩大任何角色的页面访问权限。

## 缺失左侧导航的根因

Payload 3.86 的自定义 Admin View 在 `getRouteData` 找到自定义路由后不会自动选择 `default` 模板，而是直接渲染页面组件。当前六条地理路由只注册了页面组件，因此 DOM 中没有 `.template-default`、`.nav` 或 `.admin-navigation`；CSS 和导航权限并非根因。

## 实现方式

继续以 `ADMIN_NAV_GROUPS` 为唯一导航配置源：

1. 从 `supply` 删除既有 `supply-settings` 子树。
2. 新增 `region-management` 一级组，使用与区域含义匹配的现有图标键，直接承载四个地理叶子节点。
3. 在 `system` 的角色管理和高级工具之间新增/保留 `supply-settings` 二级分组，仅承载配套字典。

沿用现有导航渲染、权限过滤、路由归属和展开状态逻辑，不新增运行时状态。

新增一个服务端共享包装组件 `GeographyAdminTemplate`：

- 接收现有 `AdminViewServerProps` 和页面内容。
- 使用 `@payloadcms/next/templates` 导出的官方 `DefaultTemplate`，将 `initPageResult` 中的请求、用户、权限、可见实体、语言和路由信息原样传入。
- 地理列表、城市详情和行政区新建三个服务端入口均通过该组件包裹其现有内容，包括禁止访问和未知模块状态。
- 页面业务组件与数据加载逻辑保持不变，不复制一套导航，也不修改生成的 `src/app/(payload)/admin/[[...segments]]/page.tsx`。

## 验证

- 导航配置合同测试锁定十个一级分组的新顺序、区域管理四项及系统基础配置一项。
- 导航状态与角色矩阵测试验证新一级组的过滤和展开语义无回归。
- 地理后台 E2E 从“区域管理”进入并验证四项；同时验证“系统管理 → 基础配置”只含配套字典。
- 模板合同测试锁定三个地理服务端入口均使用共享包装组件，且包装组件使用 Payload 官方 `DefaultTemplate`。
- 浏览器验证四个列表路由、城市详情和行政区新建至少各类代表路径存在 `.admin-navigation`；目标路由所在“区域管理”自动展开。
- 复核未授权用户仍得到登录重定向或 403，不因模板包装绕过服务端准入。
- TypeScript、相关测试、全量测试及生产构建通过。
- 真实浏览器验证区域管理、系统基础配置、相邻房源运营菜单和控制台。

## 非目标

- 不更改四个地理页面的布局或能力。
- 不重写 Payload 根布局，不复制自定义侧边栏或顶部栏。
- 不移动配套字典到“区域管理”。
- 不调整高级工具、用户管理或角色管理内容。
- 不新增后台动态菜单管理能力。
