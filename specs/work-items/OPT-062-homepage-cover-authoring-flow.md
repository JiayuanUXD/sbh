# Task Packet：OPT-062 首页配图动线收口——导航归位 + 商圈抽屉内配封面

> 状态：**设计已定，未实施**
> 创建日期：2026-08-28
> 来源：用户在 OPT-060 上线后连续提出两个问题——「后台菜单里没有找到『地理数据』」「『城市管理』和『城市站点配置』是不是冲突了」，以及「商圈封面能不能放在商圈管理的编辑抽屉里」
> 编号说明：OPT-061 是 `next/image` 开放代理收敛（另一分支），故取 062
> **前置依赖**：`OPT-060` 已于 2026-08-28 落地并上线。本工作项收口它带来的配图动线。

## 1. 一句话

`OPT-060` 让运营**能**配首页的图了，但配一次要在**三个地方来回跳**，其中两个还跨了一级分组；
而商圈管理的列表**能诊断出「这个商圈缺封面」，抽屉里却治不了**。

## 2. 证据：两个断口

### 2.1 导航错位：运营配置被埋在地理层级里

`navigation-config.ts:85-107` 的「区域管理」组有六项：

```
区域管理
├─ 城市管理      /admin/geography/cities            ← 地理
├─ 城市站点配置   /admin/collections/city-site-profiles ← 运营配置（夹在中间）
├─ 行政区域      /admin/geography/districts          ← 地理
├─ 商圈管理      /admin/geography/business-areas     ← 地理
├─ 地铁管理      /admin/geography/metro-lines        ← 地理
└─ 地理别名      /admin/collections/location-aliases ← 地理
```

**六项里五项是地理层级（城市 → 行政区 → 商圈 → 地铁 → 别名），唯独第二项是运营配置。**
两者名字又都以「城市」开头、挨在一起，于是看起来像同一件事的两个入口。

用户的原话是「是不是冲突了」——**数据模型上不冲突**（见 §4），冲突感完全来自这个排布。

而 `SiteSettings`（站点设置）在「内容管理」组（`navigation-config.ts:162-174`）。于是
`OPT-060` 建立的「全局默认 → 单城覆盖」两层，被拆在两个一级分组下：

| 配什么 | 在哪 | 一级分组 |
|---|---|---|
| 类型卡**全局默认**封面 | 站点设置 → 首页区块 | 内容管理 |
| 类型卡**单城覆盖** | 城市站点配置 → 首页内容 | **区域管理** |
| 商圈卡封面 | 商圈管理 → 抽屉 | **区域管理**（且抽屉里配不了，见 §2.2） |

> 附带说明「地理数据」为什么找不到：`Locations.admin.group: false`（`Locations.ts:202`），
> **刻意不出现在导航**——注释写着「Task 16：地理管理重构后 locations 不再出现在导航，
> `plural` 仅用于面包屑」。「地理数据」只是面包屑上的名字，不是菜单项。商圈的正确入口
> 是「区域管理 → 商圈管理」这个自定义视图。

### 2.2 抽屉断口：诊断得出来，就地治不了

`/admin/geography/business-areas` 这个自定义视图**已经具备完整的「找出缺封面」能力**：

- `geography-modules.ts:109`：列表有「封面」列（`hasCover` 标记）；
- `geography-modules.ts:157-160`：有 **「仅看缺封面」** 筛选 chip，专门用来找漏配的；
- `GeographyListViewClient.tsx:346`：点行开抽屉，可改名称 / 状态 / 前台可见 / 排序 / 中心经纬度。

**但抽屉里没有封面字段**（`GeographyListViewClient.tsx:383-430` 共六个字段，全是
`Input` / `Select` / `Switch` / `InputNumber` 这类纯值控件）。要配封面只能点
「完整编辑」（`:371`）跳到 `/admin/collections/locations/<id>`——**而那个页面不在导航里**。

运营的实际动线：筛出缺封面 → 点开抽屉 → 发现配不了 → 点「完整编辑」跳走 → 传图 →
返回列表 → 下一个。

**`OPT-060` 刚把「商圈封面」从「配了也可能不生效」变成运营会频繁使用的字段，
配图动线在这时候断着最不划算。**

## 3. 目标与非目标

**目标**：把首页配图的动线收口——两层配置在导航上相邻，商圈封面能就地配完。

**非目标**（明确不做）：

- **不合并 `SiteSettings` 与 `CitySiteProfiles` 的数据模型**（理由见 §4）；
- **不改任何权限码**（已裁定，见 §5）；
- 不动 C 端渲染，不动 `OPT-059` 的图片管线；
- 不给「城市管理」「地铁管理」的抽屉加封面字段（那两类节点没有这个字段，见 §6.4）。

## 4. 关键裁定一：不合并数据模型

用户问「城市站点设置是否可以和内容管理下的站点配置结合」。**结论：导航上合并，数据模型不合并。**

| | 站点设置（Global，1 行） | 城市站点配置（Collection，7 行） |
|---|---|---|
| 品牌 / logo / 首屏文案 | ✅ 全局 | — |
| 合规声明、页脚、导航 | ✅ 全局 | — |
| 类型卡五张 | ✅ 全局默认 | ✅ **本城覆盖**（OPT-060） |
| SEO 标题 / 描述 | — | ✅ 分城独有 |
| 开城状态 / 切换器 / 排序 | — | ✅ 分城独有 |
| 未开城页 Hero、精选区域 | — | ✅ 分城独有 |

它们是**「全局默认 + 分城覆盖/分城独有」两层**——正是 `OPT-060` 为类型卡封面建立的那个模式。
七城共用一套品牌与合规声明，但 SEO 和开城状态**必须各城独立**。这个分层是对的，不该合并掉。

真要在数据层合并（把 `CitySiteProfiles` 塞成 `SiteSettings` 的 array 字段），代价是：
七城的权限、缓存失效标签、`profile-protect` 校验、`featuredRegions` 关系字段全要重做，
而且 Global 单行存所有城市配置会让并发编辑互相覆盖。**不做。**

## 5. 关键裁定二：不动权限码

`CitySiteProfiles` 的写权限是 `location:manage`（`CitySiteProfiles.ts:138-139`），
而 `SiteSettings` 是 `site_settings:manage`（`SiteSettings.ts:28`）。导航里两个 leaf 的
`requiredOperationCode` 各自跟着自己的集合走——这是对的，`navigation-config.ts:167` 的注释
专门强调过「菜单看得见的人和 API 改得动的人得是同一批」。

挪位置后，「内容管理」组里会出现一项要 `location:manage` 的入口。**本次只挪位置、
权限码一个不动**，理由是把「结构错了」和「权限该给谁」两个问题解耦：

- 导航错位是**当下就在咬人**的（用户连续两个问题都指向它）；
- 「谁该有权把一个城市下线」（`serviceStatus`）是业务判断，**不该在一次导航调整里顺手决定**。

### 5.1 上线前必查（数据问题，不是代码问题）

角色的权限分配**不在代码里**——`Roles` 集合把它存成 `operationPermissions` 字段
（`Roles.ts:157`），是**数据**。所以「内容运营手里有没有 `location:manage`」这个问题，
**仓库回答不了**，必须看生产库里的实际角色配置。

**上线前用一句查询确认生产库里这两个码的分布。** 如果确实存在只拿 `site_settings:manage`
的角色，那本方案就给他们留了一个看不见的入口——**届时再单独评估是否新增专用码
（如 `city_site_settings:manage`），不要在本工作项里顺手改权限。**

> 不要拿本地夹具角色去推断生产分布——夹具 ≠ 生产。

## 6. 方案

### 6.1 导航挪位（纯配置）

`src/domain/admin-navigation/navigation-config.ts`：把 `city-site-profiles` 这个 leaf 从
`region-management` 组挪到 `content` 组，紧跟在 `site-settings` 之后。

```
内容管理                     区域管理
├─ 站点设置      ← 全局默认    ├─ 城市管理
├─ 城市站点配置   ← 分城        ├─ 行政区域
├─ 页面内容                   ├─ 商圈管理
├─ 资讯中心                   ├─ 地铁管理
└─ 素材库                     └─ 地理别名
```

`requiredOperationCode: 'location:manage'` **原样保留**（§5）。区域管理回归纯地理五项。

### 6.2 抽屉数据形状

`GeographyRow`（`GeographyListViewClient.tsx:29-46`）现在只有 `hasCover: boolean`
——`GeographyListView.tsx:131` 把 `d.coverImage != null` 压成了布尔，**拿不到是哪张图**。

要把封面的 **id 与预览 url** 带下来。`hasCover` **保留**（列表的「封面」列与
「仅看缺封面」筛选还在用它），但必须**从同一处服务端映射派生**，不能两处各算一次
——否则两者会漂移。

### 6.3 抽屉表单与上传流程

抽屉加一个「封面图」区块：

- **有图**：缩略图预览 + 「更换」「移除」；
- **无图**：「从素材库选择」「上传新图」两个入口。

保存时 `save()`（`GeographyListViewClient.tsx:200-218`）的 `PATCH /api/locations/:id`
body 白名单加 `coverImage`。**已有的 `version` 乐观锁天然覆盖它，不要因为加字段把它丢了。**

**上传流程**：

```
选文件 → 预填 alt「{商圈名}商圈封面」（输入框可当场改）
       → POST /api/media 创建媒体
       → 拿到 id 写进抽屉本地 state（显示预览）
       → 点「保存」时随 PATCH 一起落到商圈上
```

**alt 为什么必须处理**：`Media.alt` 是 `required: true`（`Media.ts:24`），不给就创建失败。
自动预填而非强制手写，理由：`{商圈名}商圈封面` 对读屏用户是准确描述，比批量补图时
被敷衍成「图片1」强；输入框摆在那儿，想写得更好随时可以。

> 注意首页那两个区块渲染封面时是**装饰性**的（`OPT-059` 给 `<Media>` 加了 `decorative`，
> alt 会被强制置空、读屏不念）。所以这里的 alt **主要服务于素材库自身的可管理性**，
> 以及这张图被别处复用时的无障碍。

**上传不引入新权限面**：`Media` 只声明了 `read`（`Media.ts:16-18`），写权限走 Payload
默认（已登录即可）。有 `location:manage` 的人点「上传新图」不会 403。
（记一笔：这是「默认」而非「有意配置」，与 `Listings`/`Buildings` 缺 `delete` access 同形状。）

### 6.4 抽屉是四模块共用的，封面必须按模块条件渲染

`GeographyListViewClient` 被城市 / 行政区 / 商圈 / 地铁四个模块共用，而
`Locations.coverImage` 的 `admin.condition`（`Locations.ts:351-352`）限定只对
`business_area` / `district` 显示。

**做法：给 `geography-modules.ts` 的模块定义加一个能力标记**，照该文件已有的
`columns` / `filters` / `chips` 那套模式来。**不要在组件里写 `if (type === 'business_area')`
这种硬编码**——那会让「哪些模块有封面」这件事散落在两处。

### 6.5 顺带接上的一件事

`OPT-060` 的 Task 1 已把 `coverImage` 补进了 `PUBLIC_LOCATION_FIELDS`（缓存失效字段表），
而抽屉走的是 `PATCH /api/locations/:id`（REST 会触发 `afterChange` 钩子）。

所以**从抽屉存封面会正确打失效标签、前台立刻生效**，不需要额外做什么。

## 7. 风险与对策

| 风险 | 为什么危险 | 对策 |
|---|---|---|
| **上传组件是仓库测试铁律盯得最紧的那类** | 根 `CLAUDE.md` 有「表单保存与持久化：三步铁证」——抓包核验实际请求体、响应核验、**强刷重载核验 DOM 回显** | 三步一步不能省，写进验收（§8） |
| **Arco Modal 嵌在 Drawer 里** | 选图弹层套在抽屉内，z-index / 焦点 / ESC 冒泡是这类组合的常见坑；抽屉外层还有 `onRow onClick`（`:346`） | 专门实测弹层开关、ESC 只关弹层 |
| **上传后未保存就关抽屉 → 孤儿媒体** | 已裁定可接受（与「素材库传了没用」同性质），但**不能半截数据** | 验收专门走这条路径（§8 第 5 条） |
| **`hasCover` 与 `coverImage` 漂移** | 一个布尔一个对象，两处各算就会不一致 | §6.2：同一处服务端映射派生 |
| **模块隔离失守** | 给城市/地铁塞一个存不进去的封面框——**不报错，只是存了没反应**，正是本仓库反复吃亏的静默失效 | 加断言锁死（§9） |

## 8. 验收（必须在浏览器里实际做）

导航：

1. 「城市站点配置」出现在**内容管理**下、紧挨「站点设置」；「区域管理」只剩五个地理项；
   点进去能正常打开、能存。

抽屉——**「表单保存三步铁证」一步不能省**：

2. **抓包核验**：上传时拦下实际发出的 `POST /api/media`，确认 `alt` 真的带上了；
   保存时拦下 `PATCH /api/locations/:id`，确认 body 里有 `coverImage`
   **且 `version` 仍在**（乐观锁不能因为加字段被丢掉）。
3. **响应核验**：两个请求都 `200/201`，响应文档结构正确。
4. **强刷重载核验**：`page.reload` 重新进入，确认封面**还在**、列表「封面」列翻成有图、
   「仅看缺封面」筛不到它了。这一步专治「界面看着存上了、其实没落库」。

本方案特有的三条：

5. **孤儿路径**：上传完**不点保存**直接关抽屉 → 不报错、不留半截数据；素材库里那张图
   存在且可用。
6. **弹层嵌套**：选图弹层能正常开关；按 ESC **只关弹层、不连抽屉一起关**；关掉弹层后
   抽屉里其它字段的未保存改动**还在**。
7. **模块隔离**：「城市管理」「地铁管理」的抽屉里**不该有封面字段**。

**本地验之前先 `pnpm exec payload migrate`**——本地库落后会看到「缺列 500 → 页面降级」
的假象。

证据存 `artifacts/verification/OPT-062/`。

> 若执行环境的 Browser pane 不合成帧（`OPT-059`/`OPT-060` 两轮都遇到过），
> **如实报告截不到，并写清哪些结论因此没有证据**——不要用 DOM 证据冒充视觉确认。

### 11.1 上线前必查：**已执行，结论为零代价**（2026-08-28）

**已在生产库（`sbh-d9gnr8h5ef7e22e30`）执行只读查询，结果：**

| 角色 | `*` 通配 | `site_settings:manage` | `location:manage` |
|---|---|---|---|
| **ADM** 平台管理员 | ✅ | 经通配持有 | 经通配持有 |
| MGR 销售主管 | — | ❌ | ❌ |
| OPS 运营人员 | — | ❌ | ❌ |
| CSR 客服 | — | ❌ | ❌ |
| BRK 经纪人 | — | ❌ | ❌ |

查询：`SELECT ... FROM roles r, LATERAL jsonb_array_elements_text(r.operation_permissions)`。
通配语义已从代码核实：`permission-context.ts:135` —— 持有 `*` 直接返回 true。

**结论：两个码的持有者完全重合**（都只有 ADM 经 `*` 通配），生产库里**没有任何角色
只持有其中一个**。所以「只挪位置、不改权限码」这个裁定的**代价是零**——不存在
「看得见『站点设置』却看不见旁边『城市站点配置』」的角色。

> 顺带一个事实：`site_settings:manage` 与 `location:manage` 目前**没有任何角色显式持有**，
> 能进这两个入口的只有平台管理员。若将来要把配图工作交给运营，需要先给 OPS 之类的角色
> 显式加码——**那是独立的权限设计决策，不属于本工作项**。

### 11.3 已知可接受的行为

- **上传后不保存就关抽屉 → 素材库留下一张没被引用的图。** 与「在素材库传了图但没用」
  同性质，实测确认不报错、不留半截数据。
- **列表「封面」列说有、抽屉却显示无。** `hasCover` 与「仅看缺封面」chip 对齐成了
  「`coverImage` 字段非空」（chip 是 SQL `exists` 查询，无法检查嵌套的 `media.url`），
  而喂抽屉 `<img src>` 的 `coverImage` 仍要求 url 非空。所以理论上存在「字段非空但
  拿不到 url」的记录会出现这个组合。取舍与理由写在 `GeographyListView.tsx` 的注释里
  ——比修复前「列说缺、chip 筛不出」的旧不一致范围更小。

### 11.4 可选的小改进

- `CoverPickerModal` 的素材库搜索**无防抖**，每敲一个键发一次请求；
- `requestKey` 用的是未 trim 的 `keyword`，而查询是 trim 过的，敲一个尾随空格会白跑
  一次并闪一下 loading；
- 用同一个 key 重开弹层会先瞬间显示上次的列表再后台刷新，刚上传的图可能有一瞬不在网格里。
