# Task Packet：OPT-082 卡片媒体比例统一为 16:10

> 状态：**实施中**
> 创建日期：2026-09-10
> 来源：用户走查第 2 条「楼盘卡片的图片比例不统一」→ 追问定位为「同页楼盘卡 vs 房源卡」

---

## 1. 一句话

把房源卡的 4:3 改成 16:10，全站卡片媒体统一到一档；并修掉移动端房源卡「同一页三种
比例」的既有缺陷（根因是拉伸，不是比例值）。

## 2. 定位过程（先证伪再动手）

用户说「楼盘卡片的图片比例不统一」，但**容器比例这一层是齐的**——扫了所有出现楼盘卡的
页面，全部 `sf-media--16x10`、实测 1.6：

| 位置 | 实测 |
| --- | --- |
| 首页「热门楼盘」轨道 | 400×250 |
| 楼盘列表 · 网格 | 324×203 |
| 楼盘列表 · 横排（OPT-081） | 240×150 |
| 楼盘详情 · 相关楼盘 mini 卡 | 324×203 |
| 楼盘详情 · 周边楼盘条带 | 200×125 |

追问后确认指的是**同页楼盘卡（16:10）与房源卡（4:3）并排看着不齐**。

顺带排除一个误报：在浏览器面板里打开线上站量到「盒子 4032×48、比例 84:1」，一度像线上
炸了——实际是面板拦了跨域样式表（`document.styleSheets === 0`），线上 CSS `curl` 是
200 / 79KB。**面板量线上站的布局数据不可信**，要量得用真实浏览器。

## 3. 为什么统一到 16:10 而不是 4:3

改动面 7:3 倒向 16:10：

- **16:10（7 处）**：楼盘结果卡 / 楼盘横排行 / 楼盘 mini 卡 / 周边楼盘条带 / 首页楼盘
  轨道 / 资讯卡 / **房源横排行**
- **4:3（3 处）**：房源结果卡 / 通用房源卡 / 首页房源轨道

即**房源自己内部本就不统一**：`/listings` 切到横排是 16:10、切回网格变 4:3，移动端
`.ls-rowcard__media` 又被显式改回 4:3。统一到 16:10 顺带收掉这处。

反向（统一到 4:3）要改 7 处，并推翻「楼盘卡 16:10（封面多为横向街景）」这条成文全站
规则——而那条规则当初正是为修「同一栋楼被裁三种样子」才立的。

代价：房源内景照多为 4:3，会多裁掉上下。已向用户说明并由用户拍板。

## 4. 真正的缺陷不在比例值，在拉伸（本项最重要的一条）

移动端房源网格卡实测**同一页并存三种比例**：

```
116x103 (1.128)   116x81 (1.427)   116x79 (1.461)
```

根因：OPT-078 把 `.ls-card` 改成 `flex-direction: row` 横排，图是定宽 flex 子项，而
`.ls-card` 是 `align-items: stretch`——图被**拉伸到卡片高度**，`aspect-ratio` 从不生效。
于是每张卡的图比例由「这张卡文案多高」决定。

**这与 4:3→16:10 无关**：只换比例值是把「统一的错」换成「另一个统一的错」。
修法是 `.ls-card > .sf-media { align-self: flex-start }`，让 `aspect-ratio` 重新说了算。

修后 375 实测：24 张卡全部 `116×73 (1.600)`，唯一比例。

  仍引用它，删了等于把一个通用比例基元砍成只有一档。已加注释说明当前无产品消费方。
- **不动 `.hm-type-card__media`（1.543）**：那是首页「按类型浏览」的入口卡，不是供给卡，
  与本次「楼盘卡 vs 房源卡」不是一类东西。
- **不动「暂无在租」的 48×48 方形缩略图**：那是降权紧凑行的缩略图，不是卡片封面。
