# Task Packet：OPT-049 后台左侧导航——隐藏选择器早已失效，原生导航一直显示着

> 状态：**已实施**（2026-08-24，含两条双向验证的守卫）
> 创建日期：2026-08-24
> 来源：OPT-045 D4 上线后用户反馈「左侧导航样式问题还存在」
> 编号说明：OPT-048 是迁移快照链，故取 049

---

## 1. 一句话

后台左下角那个「挤成一团、与上面九个分组风格明显不一致」的区块，**不是兜底渲染，
是 Payload 原生导航整个都在**——`custom.scss` 里用来隐藏它的选择器写的是
Payload 2 的 BEM 类名，在 Payload 3.86 下**一个都匹配不到**。

## 2. 证据

`src/app/(payload)/custom.scss` 第 694 行起：

```scss
// 始终隐藏 Payload 默认的导航分组（我们的自定义 admin-navigation 已完全替代）
.nav__groups { display: none !important; }
// 始终隐藏 Payload 默认的左下角退出按钮（已合并到右上角 AccountMenu 下拉菜单）
.nav__controls { display: none !important; }
```

对着 `@payloadcms/ui@3.86.0` 的产物核对：

| `custom.scss` 里写的 | 在 payload/ui 中出现的文件数 | 判定 |
|---|---|---|
| `.nav__groups` | **0** | ❌ 匹配不到任何元素 |
| `.nav__controls` | **0** | ❌ 匹配不到任何元素 |
| `.app-header__account` | 1 | ✅ 有效 |
| （实际类名）`nav-group` | 6 | —— |

`NavGroup/index.js` 里 `baseClass = 'nav-group'`——**连字符，不是双下划线**。

**注释的意图是对的，选择器是错的。** 这类失效完全静默：CSS 选择器匹配不到元素不会
报错、不会警告，页面只是「看起来多了点东西」。

## 3. 为什么 OPT-045 D4 没能解决它

D4 把三个游离集合收编进自定义导航，我当时判断「兜底区块会自然消失」——**这个判断是错的**。

收编只影响**自定义导航**里显示什么，与**原生导航显不显示**毫无关系。两者是并列渲染的：
`payload.config.ts` 把自定义导航挂在 `admin.components.beforeNavLinks`，
顾名思义是**加在原生导航之前**，原生的照常渲染在下面。

教训与 OPT-045 §10.5.3 同类：**按清单执行了，却没验证清单声称的结果**。

## 4. 顺带发现：还有 5 个集合没收编

即使选择器修好（原生导航消失），自定义导航里仍然缺这 5 个：

| 集合 | 性质 | 建议 |
|---|---|---|
| `information-corrections` | 业务数据（信息纠错） | 收编进「审核与风控」 |
| `display-tags` | 业务配置（展示标签） | 收编进「系统基础配置」 |
| `lead-ownership-history` | 审计流水（`delete: () => false`） | 收编进「客户运营」，或设 `admin.hidden` |
| `exports` / `imports` | **Payload 插件自带**，运营用不到 | `admin.hidden` |

统计口径：集合总数 41，已收编 30，`admin.hidden` 6，剩余 5。

## 5. 需要改什么

- [ ] `custom.scss`：`.nav__groups` → `.nav-group`；`.nav__controls` 查清 3.86 的真实类名后改
- [ ] 5 个集合：三个业务类收编进分组，`exports` / `imports` 设 `admin.hidden`
- [ ] **测试守卫（关键，见 §6）**

## 6. 测试守卫——这条比修复本身更重要

两个缺陷都属于「静默失效」：CSS 选择器匹配不到不会报错，集合漏收编只是少个入口。
必须让它们在 CI 阶段就红。

### 6.1 选择器守卫

断言 `custom.scss` 里每个 `display: none` 的类名**确实出现在 `@payloadcms/ui` 的产物里**。
Payload 升级改了类名 → 立刻红，而不是等用户反馈「样式又乱了」。

> 这条守的是**跨依赖的隐式契约**。这类契约没有类型系统保护，升级时最容易断，
> 而断了之后症状轻微到没人会立刻报障。

### 6.2 收编完整性守卫

断言「所有非 `admin.hidden` 的集合都在 `ADMIN_NAV_GROUPS` 里」。
新增集合忘了收编 → 立刻红。

⚠️ **不要写成「断言当前有 5 个未收编」**——那是把现状固化成期望，
下次再漏一个照样绿。要断言的是**集合为空**。
（这正是 OPT-045 §10.5.3 那条教训：验 X 的症状，不是验导致 X 的数据结构长什么样。）

## 7. 验收

- 后台左侧只剩自定义导航的九个分组，**没有任何原生导航残留**；
- 左下角没有重复的退出按钮；
- 两条守卫：现状下绿；人为改坏（选择器写错 / 新增集合不收编）时**红**——
  **必须双向验证**，只验绿等于没验。

## 8. 坑

- **`beforeNavLinks` 是「加在原生导航之前」，不是「替换原生导航」。** Payload 没有
  「关掉默认导航」的配置项，只能靠 CSS 藏。所以那几条 `display: none` 是功能而非样式，
  删掉或写错等于原生导航复活。
- **CSS 选择器失效是静默的**，没有任何运行时信号。这就是 §6.1 存在的理由。
