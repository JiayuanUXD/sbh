## 1. 一句话

用楼盘经纬度和地铁站坐标，给没填「最近地铁」的楼盘算出直线距离最近的同城站点，经人工确认阈值后回填。

## 2. 现状（2026-10-22，公开接口统计）

| 项 | 数量 |
|---|---|
| 楼盘 | 4,313 |
| 已填 `nearestMetro` | 14（都是手工维护的楼，且都没有坐标） |
| 有经纬度 | 4,308（汇租同步，入库时已转高德 GCJ-02） |
| 地铁站 / 线路 | 1,236 / 66（七城，全部有坐标，高德 POI 采集，GCJ-02） |

这个字段前台多处在用，几乎全空：楼盘卡片「近 X 站」、楼盘详情「地铁」、房源和楼盘列表的地铁筛选（`listing-query-sql.ts`、`building-search.ts`）、站内搜索按站名匹配（`listing-query-sql.ts` 的排序分）。

公开接口对匿名请求会清空楼盘坐标（`Buildings.afterRead` 字段脱敏），所以计划必须读库。

## 3. 设计

- 算法（`scripts/lib/nearest-metro.ts`）：同城站点里取 haversine 直线距离最近的；距离相同取 id 小的。坐标缺失、越界、`(0,0)`、疑似经纬度写反的进人工清单，不猜。已填的不动，只列出与计算结果不一致的。
- 三步命令（`scripts/backfill-nearest-metro.ts`）：
  - `pnpm buildings:nearest-metro:plan --out=… [--max-distance=2000]`：强制只读连接（`default_transaction_read_only=on`）、不启动任务队列；输出 `plan.json` 与人看的 `plan-summary.md`（数量、距离分布、各阈值能回填多少、按线路 / 站汇总、抽样、异常清单）。
  - `pnpm buildings:nearest-metro:execute --plan=… --max-distance=<米> --out=…`：阈值必须显式给出，且不能比计划更宽；计划里的数据库与当前连接不一致就拒绝；逐栋复核（仍未填、坐标没变）后带 `version` 经 Local API 更新（并发改动触发乐观锁冲突就跳过）；每写一栋追加一行回滚清单。
  - `pnpm buildings:nearest-metro:rollback --applied=… --out=…`：只把仍等于当时写入值的改回空。
- 距离口径：直线距离，不是步行距离；步行一般比直线长 20%–40%。

## 4. 范围与非目标

| 项 | 说明 |
|---|---|
| 存距离 / 线路字段 | 不做：要加列走迁移；前台目前只展示站名 |
| 换乘站多线归属 | 不做：库里换乘站只挂首开线路（`docs/geography-code-convention.md`），按线路统计会低估换乘多的线路 |
| 改已有的 14 个手工值 | 不做，只在报告里列出差异 |
| 步行距离（高德路径规划） | 不做：4,000+ 次调用、配额与时长都不划算，直线距离加保守阈值足够 |
