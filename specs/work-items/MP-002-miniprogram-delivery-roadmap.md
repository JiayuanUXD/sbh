## 1. 为什么拆成多个工作项

小程序工程、服务端 API、咨询身份、页面视觉和发布资质是不同的评审边界。将它们放进一个实现任务会导致任何一部分失败都无法独立验收，也会让一次代码审查横跨前后端、隐私、数据库和发布配置。以下每个工作项都产生独立可测试的交付物；前五项串成上海纵向闭环，后续能力另行进入排期。

## 2. 路线总览

```text
MP-101 Mini API 只读门面
       ↓
MP-102 原生小程序工程基础
       ↓
MP-103 首页 + 搜索 + 列表
       ↓
MP-104 房源详情 + 咨询身份与提交
       ↓
MP-105 联调、真机与灰度门
       ↓
MP-106 楼盘闭环 → MP-107 个人能力 → MP-108 正式发布
```

## 4. 各工作项边界

### MP-101 Mini API v1 只读门面

**包含**：

- `/api/mini/v1/home`
- `/api/mini/v1/listings`
- `/api/mini/v1/listings/:slug`
- 小程序专用 DTO mapper、稳定错误协议、`requestId` 与 `asOf`
- 复用现有 Public Catalog、Effective Supply、300 秒缓存和标签失效
- Web/小程序 Listing ID 集合一致性测试

**不包含**：会话、手机号、咨询写入、小程序页面、数据库迁移。

详细执行计划：`specs/work-items/MP-101-mini-api-read-facade-plan.md`。

### MP-102 原生小程序工程基础

**包含**：

- `sbh-miniprogram/` 独立 TypeScript 工程、锁文件和微信项目配置
- 开发/预发布/生产 API 基址与合法域名检查
- `request<T>()`、超时、重试边界、业务错误映射、请求 ID 回显
- token、字体、间距、圆角、颜色和 44px 触达基础组件
- `miniprogram-simulate`、Vitest、`miniprogram-automator`、`miniprogram-ci` 基础脚本

**不包含**：业务页面、登录、发布上传私钥入库。

### MP-103 首页、搜索与房源列表

**包含**：

- 160–180px 短品牌头图、搜索与快捷筛选、首组真实房源
- URL 等价的本地筛选状态序列化；改变结果集后页码归一
- 计价单位作为结果集维度；月租估算主展示、单位报价次展示
- 骨架、空、错、图片失败、失效刷新和逐项放宽筛选
- 首页和列表组件测试、自动化与真机截图

**不包含**：地图、对比、收藏、求租广场。

### MP-104 房源详情与咨询闭环

**包含**：

- 详情决策信息、费用拆项、核验时间、失效与相似房源出口
- `/api/mini/v1/session` 与 `/api/mini/v1/inquiries`
- `wx.login` 按需触发；手机号授权拒绝时手工输入
- 复用咨询领域 schema、幂等、限流、审计和有效供给校验
- “咨询顾问/获取完整报价”主 CTA，不提供未接通排期能力的预约承诺

**数据库门**：如果收藏或独立小程序用户集合不进入本工作项，则本工作项不修改 Collection，也不生成迁移。

### MP-105 集成验收与预发布

**包含**：

- 微信开发者工具模拟器、网络面板、包体、分包和性能检查
- iOS/Android 真机；小屏与常见大屏
- 弱网、超时、离线恢复、会话过期、重复提交、图片失败和服务端错误
- 预发布合法域名、隐私政策版本、CI secret、预览码和回滚步骤
- 证据存放在 `artifacts/verification/MP-105/`
- 当前进入安全闸门实现：trial 不得复用生产 API；任何自动或真机写验收必须先通过受控 staging deployment、数据库指纹、操作者认证写许可和精确 fixture ownership。外部环境未交付前保持“未通过”，MP-106/107 不进入实现、集成或合并。

**不包含**：未经确认的生产部署与正式上传。

### MP-106–108 后续能力

这三个工作项在 MP-105 通过后分别编写独立实现计划。它们不得反向阻塞上海首个闭环，也不得为了未来收藏、地图或多端复用提前改变 MP-101–104 的接口边界。

## 5. 依赖与并行策略

- MP-101 的 DTO 契约冻结后，MP-102 可以用固定响应夹具并行搭建工程基础。
- MP-103 必须等待 MP-101 的首页/列表契约和 MP-102 的 request 层稳定。
- MP-104 的详情展示部分可与咨询服务端适配并行，但合并验收必须使用同一预发布 API。
- MP-105 不在最后才第一次看真机：MP-102 起每个工作项都要留一轮开发者工具和真机证据，MP-105 负责全链路复核。
- MP-106 与 MP-107 只有在 MP-105 通过后开始，避免 MVP 范围扩张。

## 6. 项目管理门禁

每个工作项都要同时具备以下内容才能标记完成：

1. 明确的输入/输出接口与非目标。
2. 失败测试 → 最小实现 → 通过测试的 TDD 证据。
3. 类型检查、单元测试和相关 lint 通过。
4. 涉及页面或路由时，有微信开发者工具或真实浏览器证据。
5. 涉及写入时，有请求体、成功响应、重复提交和服务端持久化证据。
6. 涉及隐私时，有拒绝授权、手工输入和脱敏证据。
7. 状态、风险和未验证项回写对应任务包。

## 7. Git 与发布约束

- 所有工作继续留在 `feat/miniprogram-mvp-59f9` 或从它拆出的合规短分支/worktree。
- 只能显式 `git add <具体路径>`，不得使用 `git add .`、`git add -A` 或 `git commit -am`。
- 计划中的提交命令只有在用户明确授权提交后才能执行。
- 未经用户确认，不推送、不创建 PR、不合并 `master`、不部署、不正式上传小程序。
- 如后续修改 Collection/Global，必须先读迁移规则，生成迁移且不得手改迁移正文。

## 8. 当前决策

先执行 MP-101，再执行 MP-102。MP-101 不依赖 AppID、微信开发者工具账号或数据库迁移，因此是风险最低且能最快验证“专用 API 门面”路线的第一项。
