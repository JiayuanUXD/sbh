# Task Packet：OPT-072 热门区域封面图——尺寸调整与自定义截取区域

> 状态：**设计已定，未实施**
> 创建日期：2026-09-06
> 来源：用户「热门区域上传的封面图增加调整尺寸和自定义截取区域的功能」
> **前置依赖**：`OPT-062`（首页配图动线收口）**设计已定但未实施**。见 §2——没有它，本工作项没有落脚点。

---

## 1. 一句话

首页「热门区域」的商圈卡封面（`Locations.coverImage`）现在只能整张图硬塞进卡片，
运营要能自己框出用哪一块、按什么比例。

## 2. 先看清依赖：抽屉里现在连封面都设不了

「热门区域」= `Locations`（type=district）的商圈卡，前台走
`HomeDistrictBento` → `Media` 组件（`Media.tsx:160` 已在应用 focalPoint 转 object-position）。

后台侧 `OPT-062` §2.2 已经查明：`/admin/geography/business-areas` 的列表**能诊断**缺封面
（有「封面」列、有「仅看缺封面」筛选），**抽屉里却治不了**——六个字段全是纯值控件，没有封面字段。

**所以顺序是 OPT-062 先、本工作项后。** 在一个还不能设封面的抽屉里做裁剪 UI 没有意义。
若要合并推进，就把本工作项并进 OPT-062 的 §抽屉改造一起做。

## 3. 已定的决策：按用途存裁剪框，不动母版

用户在 2026-09-06 的需求梳理里选定：**在引用关系上存裁剪框，母版一个字节不动。**

明确**不启用** Payload 原生的 `Media.upload.crop`（3.86 支持，一行配置就有），原因有三：

1. **它裁的是母版文件。** 同一张图的所有引用处一起变——运营为商圈卡裁一刀，
   详情页那张也跟着被裁。
2. **与 OPT-069 水印撞车。** 水印烘进母版像素，`media-source/` 存干净原件。
   裁剪重写母版会让备份对不上：已烘过的图再裁，下一轮重刷会把**带水印的字节当干净原件**
   备份，干净副本永久丢失（这正是 `backfill-watermark.ts` 头注释里那条铁律要防的事）。
3. **一张图只能有一种裁法。** 商圈卡要 16:9、别处要方图，做不到。

代价是裁剪 UI 要自己写（拖框选区），比开一行配置多不少活。这是用户在知情下选的。

## 4. 数据形态

裁剪框存在**引用侧**，不在 Media 上。`Locations` 的封面相关字段成组：

| 字段 | 类型 | 说明 |
|---|---|---|
| `coverImage` | upload → media | 现有字段，不变 |
| `coverCrop` | group，可空 | `{ x, y, width, height }`，**归一化到 0–1**，不是像素 |
| `coverAspect` | select，可空 | 目标比例，回落到卡片自己的比例 |

**归一化存储是硬要求**：存像素的话，同一张图换成更高分辨率重新上传，裁剪框就错位了；
存比例则与源图尺寸无关。

`coverCrop` 为空 = 沿用现状（整图 + focalPoint），**不是错误状态**。存量数据零迁移风险。

## 5. 渲染：扩展 Media 组件，不新开一条路

`Media.tsx` 已经在做「ratio + focalPoint → aspectRatio + object-position」这件事（第 113 / 160 行）。
裁剪框接在同一处：把归一化的 `{x,y,w,h}` 换算成 `object-position` + 放大倍数
（或外层 `overflow:hidden` + 内层 `transform`）。

两条约束：

- **不要为裁剪去生成新的派生文件。** 派生尺寸（thumb/card/hero）是 OPT-059/068 的资产，
  再按裁剪框生成一套会让 `backfill-media-sizes` 的口径变复杂，且与水印重刷抢同一批文件。
  纯 CSS 应用裁剪，源文件不动。
- **裁剪与 focalPoint 是二选一，不是叠加。** 有裁剪框时忽略 focalPoint，
  否则两个定位机制打架，运营调半天不知道哪个在起作用。UI 上要明示。

## 6. 后台 UI

裁剪器放在 `OPT-062` 要改造的那个抽屉里（`GeographyListViewClient.tsx`），
与封面字段挨着。最小可用形态：

- 显示原图 + 一个可拖拽 / 可缩放的选框
- 比例锁（跟随 `coverAspect`）
- 实时预览「卡片里长什么样」——与前台同一套换算，避免所见非所得
- 「清除裁剪」回到整图 + focalPoint

**不引新 UI 库**（宪章硬约束）。后台已有 Arco，选框用它的基础组件 + 原生指针事件自己拼。

## 7. 验收判据

1. 设了裁剪框的商圈卡，首页显示的确实是框出来的那一块，比例正确。
2. 同一张图被别处引用时**不受影响**（这是选这条路线的全部理由，必须验）。
3. 清除裁剪后回到整图 + focalPoint，不残留。
4. 换一张更高分辨率的同内容图，裁剪框仍然框在同一处（归一化生效）。
5. **浏览器实测**：后台拖框 → 保存 → 强刷首页核对，三步铁证（见 `.agent/testing.md`）。
6. 与水印无交互——`Locations.coverImage` 的 `usage` 是 `brand`，本来就不打水印；
   但要确认裁剪不触发任何写回 media 的路径。
