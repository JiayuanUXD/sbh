# Task Packet：OPT-078 移动端结果卡改横排紧凑式

> 状态：**实施中**
> 创建日期：2026-09-09
> 来源：eBay 前端对标分析（本轮清单项 S4）+ 用户拍板「比价（优先于看图）」

---

## 1. 一句话

≤767 的结果卡从「一列 4:3 大图」改成「图左信息右」的横排紧凑卡，一屏从 1.5 条变成 4 条，
价格跨卡纵向对齐。

## 2. 本项**不含**筛选计数（S3）——它早就做完了

清单项 S3 写的是「筛选项显示命中计数」，依据是调研报告里的「筛选行选项是纯文本链接，
没有计数」。**核对源码后确认这条是错的**：

- `FilterRow.options` 早有 `count?: number`，`FilterFormC` 也早就渲染
  （`<span className="ls-filterc__opt-count">{option.count}</span>`）。
- `CityListingsView` 通过 `toCountMap(districtFacets.districts)` / `typeFacets.listingTypes`
  把 facet 计数传进 `buildListingFilterRows`。
- 线上实测：位置行「长宁 4 · 徐汇 4 · 黄浦 5 · 静安区 8」，类型行「传统办公 11 · 共享办公 3 …」。

S3 里我另外提的「0 命中的项置灰而不隐藏」**也不采纳**：`listing-filter-rows.ts:299-302`
有明确的反向决定——「计数为 0 的候选不渲染：点进去必然空手而归，比不出现更糟」，
且当前已选项永远保留。这是既有产品判断，不该拿 eBay 的做法去推翻。

## 3. 做法：纯 CSS，不按视口换组件

`view` 由服务端从 URL 解析，**服务端拿不到视口**；要按视口换组件只能上客户端探测，
会带来水合不一致与首帧闪烁。CSS 改版式没有这些问题，DOM 一份，`?view=` 语义不受影响。

| 改动 | 值 |
|---|---|
| `.ls-grid` ≤767 | 单列，gap 12（断点从 599 提到 767：600–767 原本两列，横排卡并排会挤成两团） |
| `.ls-card` ≤767 | `flex-direction: row`，图定宽 116（4:3 → 87 高），卡高 107–123 |
| `.ls-card__body` | 加 `min-width: 0`（见 §4）与 `.ls-card__meta { flex-wrap: wrap }` |
| `.ls-rowcard` ≤767 | 从「转竖排 + 整宽大图」改为同款横排；价格列落到信息下方整宽一行 |
| `.ls-toolbar__viewseg` ≤767 | 隐藏 |

### 3.1 为什么两种视图在移动端收敛，且隐藏切换

改之前 `?view=row` 在 ≤767 是**转竖排 + 整宽大图**，与本次改横排的默认卡正好相反：
同一页里默认视图密集横排、点「横向列表」反而变成一屏一张大图，**切换等于变差**。
让两者在 ≤767 收敛为同一套横排后，切换控件点了什么都不变——那正是 `.agent/frontend.md`
明令禁止的死控件，所以一并隐藏。**只隐藏控件、不动 `?view=` 解析**：带 view 的分享链接
在移动端仍正常渲染。桌面照常提供切换。

## 4. 走查抓到的两个问题

1. **整节 CSS 写错了位置，一条都没生效且不报错。** 第一版把 `@media (max-width: 767px)`
   写在文件上方的网格区，而 `.ls-card { flex-direction: column }` 在下方 160 行、
   `.ls-toolbar__viewseg { display: flex }` 在 505 行——同为 (0,1,0)，同特异度靠源码顺序
   定胜负，后面的基础声明把媒体查询整段覆盖掉了。**本仓库 CSS 的头号静默失败形态**，
   已把整节移到被覆写声明之后，并在注释里写明这条约束。
2. **`.ls-card__body` 少了 `min-width: 0`，标题穿出卡片。** flex 子项默认 `min-width: auto`，
   正文列被最长标题撑到未截断宽度，`text-overflow: ellipsis` 于是永不触发。375 实测：
   标题跑出卡片右缘、被 `.sf-card` 的 overflow 裁成断字。与本文件 `.ls-grid` 用
   `minmax(0,1fr)` 而非裸 `1fr` 是同一个坑。

## 5. 验收（375 / 720 / 1440 实测）

| 视口 | 网格 | 卡片 | 视图切换 | 横向溢出 |
|---|---|---|---|---|
| 375 | 单列 | row，高 107–123，图 116；**4 张卡价格左缘同为 154px** | none | 无 |
| 720 | 单列 | row，高 107 | none | 无 |
| 1440 | 4 列 324px | column，图 324（**桌面完全不变**） | flex | 见下 |

`?view=row` 在 375 下同为横排、图 116、价格列整宽落在信息下方，与默认视图一致。
标题正常省略号截断、不越界。

`pnpm typecheck` 干净；`pnpm test` 343 文件 / 4705 用例通过。

### 5.1 一个既有缺陷（非本次引入，已另开）

1440 下 `documentElement` 可横向拖动 8px：`.ls-page` 是 `width: 100vw`（1440）而
`clientWidth` 是 1425（15px 滚动条），`body { overflow-x: clip }` 只裁视觉、不消除可滚动性。
**未改动过的首页 `.hm-home` 完全同样**，是 `100vw` 出血模式的全站问题；本次改动全部落在
`max-width: 767px` 内、1440 下一条都不生效，与它无关。已单独挂出。
